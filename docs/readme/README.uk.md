Редактор Markdown для локальної папки нотаток — у дусі Obsidian, але повністю вміщений в
одному автономному HTML-файлі. Мережа не використовується: файли читаються з диска й
зберігаються прямо на нього.

**[Онлайн-демо](https://markdown.marketkernel.com/)** — той самий редактор
у вигляді PWA (Progressive Web App, прогресивного веб-застосунку): його можна встановити в систему, і тоді
він працює як окремий застосунок, зі своїм вікном і значком, та працює офлайн. На комп'ютері, в Chrome,
Edge і Arc, скористайтеся кнопкою встановлення в адресному рядку; на Android — меню ⋮ в Chrome →
Встановити застосунок; на iOS — Поділитися → На початковий екран, у Safari або в Chrome. Ваші нотатки
залишаються на вашому диску і там теж, а встановлений застосунок оновлюється, коли ви скажете — див.
«[GitHub Pages](#github-pages)».

Той самий редактор — це ще й **Send to Markdown**, [розширення для Chrome](#send-to-markdown-розширення-для-chrome):
клік по його кнопці або правий клік на сторінці надсилає сторінку — або виділення, посилання,
зображення — в нотатку у вашій папці, і редактор відкривається поруч зі сторінкою в боковій
панелі Chrome.

![Редактор з відкритою папкою нотаток: дерево файлів і теги ліворуч, нотатка в режимі редагування праворуч](../macaed.jpg)


## Як користуватися

1. Зберіть `build/macaed.html` (див. «[Збірка](#збірка)») і відкрийте його в браузері.
2. «Відкрити папку» → виберіть папку з файлами `.md`. Можна також просто перетягнути папку у
   вікно.
3. Перемикач **Читання / Редагування** вгорі або `⌘E`.

У Chrome, Edge і Arc папка відкривається через File System Access API: нотатки
читаються й записуються на місці, а створення, перейменування та видалення файлів і папок працюють.
У Safari та Firefox папка відкривається лише для читання, і `⌘S` пропонує завантажити змінений
файл — так само й на телефонах: у Chrome на Android немає File System Access, а будь-який
браузер на iOS, включно з Chrome, працює на рушії Safari.

Редактор пам'ятає останні шість відкритих у ньому папок (сторінка ніколи не дізнається шлях папки,
тому він зберігає хендл папки в IndexedDB браузера) і останню відкриту в кожній з них нотатку.
Під час наступного запуску остання папка відкривається сама, якщо браузер усе ще це дозволяє — у
встановленому застосунку або якщо ви вибрали «Дозволяти під час кожного відвідування». Інакше початковий
екран показує список нещодавніх папок: один клік — і браузер знову запитає доступ. Щоб повернутися до
цього списку — змінити папку або відкрити нову, — клацніть по імені папки вгорі панелі файлів,
або «Закрити папку» в налаштуваннях; × прибирає папку зі списку.

Якщо покласти `macaed.html` поруч зі своїми нотатками й роздавати його по HTTP, сторінка сама підхопить
папку — якщо поруч із ним лежить `index.json` вигляду
`{ "name": "Notes", "files": ["Note.md", "Folder/Other.md"] }`.

## Send to Markdown: розширення для Chrome

`npm run build` також створює `build/extension/`: редактор у вигляді розширення для Chrome, і
`build/macaed-extension-<version>.zip` для Chrome Web Store; у релізі цей zip теж є. Щоб встановити:
`chrome://extensions` → режим розробника → Завантажити розпаковане розширення →
`build/extension` (або розпакований zip).

Сам редактор живе в боковій панелі Chrome, поруч зі сторінкою, у телефонній розкладці, оскільки
панель вузька; він залишається там під час перемикання вкладок. Папка відкривається в ній так само, як у
файлі, і нещодавні папки запам'ятовуються — свої в розширення, окремо від папок файлу чи
PWA. Що додає розширення — це надсилання речей з вебу у ваші нотатки:

- **Кнопка на панелі інструментів** (або `Alt+Shift+M`) надсилає сторінку: її основний текст — статтю,
  без меню сайту, бокових панелей, підвалу, кнопок «поділитися», форм і прихованих частин — або,
  якщо на ній щось виділено, лише виділення.
- **У контекстному меню** сторінки є **Надіслати сторінку в Markdown**; на виділеному тексті —
  **Надіслати виділення в Markdown**; на посиланні — **Надіслати посилання в Markdown**; на зображенні —
  **Надіслати зображення в Markdown**.

Будь-який з варіантів відкриває бокову панель, і в діалозі, що там з'явився, показано, що прийшло — сторінка,
виділення, посилання чи зображення, і з якого сайту — у вигляді Markdown, який ще можна змінити, і
питається, куди це відправити:

- **Нова нотатка**, варіант за замовчуванням для сторінки: у папку для вирізок (`Clippings` у корені,
  якщо не змінити; папка запам'ятовується, порожньо означає корінь), названа за заголовком
  сторінки, з тим, що не може бути в імені файлу, — опущеним. Якщо ім'я вже зайняте, додається
  номер: `Title 2.md`. Нотатка починається з front matter — заголовка сторінки, її адреси
  та дати — а потім іде текст; вона відкривається після збереження.

  ```markdown
  ---
  title: "The page's title"
  source: "https://example.com/post"
  clipped: 2026-10-07
  ---

  # The page's title

  The text…
  ```

- **Кінець відкритої нотатки**, варіант за замовчуванням для виділення, посилання чи зображення: після
  порожнього рядка, за яким іде рядок `— [The page's title](https://…)`, що посилається на джерело. Посиланню
  це не потрібно: воно саме собі джерело.

Якщо надіслати до того, як папка відкрита, запит чекає: панель просить відкрити папку, і діалог з'являється,
щойно папку відкрито. Сторінка, яку розширення не може прочитати, — власні сторінки Chrome,
Chrome Web Store, PDF — приходить як посилання на неї.

**Що таке цей Markdown.** Заголовки, абзаци, **жирний**, *курсив*, ~~закреслений~~,
==маркер==, `код`, посилання та зображення з повними адресами, списки — вкладені, нумеровані,
завдання — цитати, блоки коду з позначенням мови (з `language-…`, гітгабівського
`highlight-source-…` і подібного), таблиці (перенесення рядка в комірці як `<br>`, як це
записує редактор), роздільники. Текст читається як є: `*`, `#` на початку рядка чи `<b>`,
набрані на сторінці, екранується, тож вони ніколи не перетворюються на форматування, і жоден HTML
сторінки не потрапляє в нотатку. Зображення залишаються у вебі, на них посилаються за адресою; у «лінивого»
зображення береться справжня адреса, а не заглушка, пікселі відстеження опускаються.

**Дозволи.** `activeTab`: клік по кнопці, в меню чи за сполученням клавіш дає
розширенню саме цю вкладку, і лише тоді воно її читає — за допомогою `scripting`, функція, яка виконується
в сторінці, копіює її текст і повертає його. Жоден content script ніколи не виконується, і доступу до
будь-якого сайту інакше немає: жодних `host_permissions`, збірка їх відхиляє. `contextMenus`,
`sidePanel` і `storage` — воркер передає взяте панелі свого вікна через
`chrome.storage.session`, що зникає під час закриття браузера, а мова панелі йде
воркеру, для меню, в `chrome.storage.local`. У сторінок розширення `connect-src 'none'`:
редактор нічого не досягає по мережі; збірка це перевіряє, а також
що жодна сторінка не має вбудованого скрипту чи зовнішньої адреси.

**Як це зроблено.** Панель — це сама сторінка: `panel.html` зі своїм скриптом у `panel.js`,
як цього вимагає Manifest V3, — той самий `src/main.ts`, з `src/extension/extension.ts` замість
`src/platform.ts`, чиї хуки нічого не роблять у файлі та в PWA. У воркера,
`background.js`, — кнопка, сполучення клавіш і меню. Chrome відкриває бокову панель лише
всередині власного обробника кліку, до того, як щось очікується (await), тому воркер спершу
відкриває панель і лише потім читає вкладку (`src/extension/grab.ts`); панель перетворює цей HTML на
Markdown (`src/extension/to-markdown.ts`), а редактор питає, куди це відправити (`src/clip-ui.ts`,
`src/clip.ts`).

## Живий перегляд

У режимі редагування документ залишається відформатованим, і лише блок, у якому стоїть курсор, перетворюється
на сирий Markdown. Блок — це абзац, заголовок, цілий список, блок коду чи цитата: список не
розсипається порядково. Таблиці редагуються інакше — див.
«[Таблиці](#таблиці)».

Вихідний рядок зберігає розмір шрифту, накреслення й висоту рядка відформатованого, тож текст не
стрибає: `# Heading` показується з розміром заголовка. Це перевіряється автоматично — під час
перемикання блоку його верхній край зміщується менш ніж на піксель за будь-якого масштабу від 50 до 200 %.

Є одне місце, де висота все ж змінюється, і це неминуче для такого режиму: блок коду
отримує два рядки-огорожі з `` ``` ``. Сусідні блоки при цьому не смикаються — зсувається
лише те, що нижче.

Enter поза списком починає новий блок. Натиснутий у кінці блоку або на порожньому рядку, він
відкриває порожній рядок під ним і ставить на нього курсор; натиснутий знову, додає ще один. У
Markdown один порожній рядок лише розділяє два блоки, тому порожній рядок, у який можна друкувати, —
це той, у якого порожні рядки з обох боків, — редактор сам додає розділовий рядок, і
набраний текст ніколи не приклеюється до сусіднього блоку. Такі рядки й визначення
посилань-виносок (`[id]: https://…`) показуються лише в режимі редагування; режим читання відображає
Markdown таким, яким він є.

## Таблиці

Таблиця ніколи не перетворюється на `| пайпи |`. Клік відкриває лише комірку під курсором, і
комірка показує свій власний текст — `**bold**`, а не жирним, — тож вбудоване форматування та
позначки панелі інструментів — посилання й кольори — і далі працюють усередині неї. Друк переписує у файлі
лише цю комірку; решта таблиці зберігає свої відступи та вирівнювання.

- **Переміщення**: Tab і Shift+Tab переходять до наступної й попередньої комірки, Enter — до комірки нижче,
  стрілки — до сусідньої комірки на краю тексту, а за краєм таблиці — до блоку поруч з нею. Enter на
  останньому рядку починає новий блок під таблицею.
- **Перенесення рядків**: Ctrl+Enter (а також ⌘Enter чи Shift+Enter) починає новий рядок усередині
  комірки. Рядок таблиці — це один рядок Markdown, тому перенесення записується як `<br>`; комірка, яку
  редагують, показує його як справжній перенос рядка, і вставлений текст зберігає свої рядки так само.
  Усередині комірки з кількома рядками стрілки вгору й вниз спершу переміщуються між її рядками. Текст
  комірки вирівнюється по верхньому краю.
- **Додавання**: у режимі редагування наведення на таблицю показує смугу з **+** під нею, яка додає
  рядок, і ще одну праворуч від неї, яка додає стовпець. Tab в останній комірці теж додає рядок.
- **Видалення**: видаляються лише порожні рядки та стовпці, тож жоден текст не втрачається через помилку.
  Наведення на порожній рядок показує **×** ліворуч від нього, на порожній стовпець — **×** над
  ним. Backspace у порожній комірці робить те саме з клавіатури: він видаляє рядок, якщо весь
  рядок порожній, інакше стовпець, якщо порожній весь стовпець (включно із заголовком); таблиця, в якій не
  залишилося тексту, видаляється цілком. Рядок заголовка залишається — таблиці він потрібен.

Додавання чи видалення переписує таблицю у звичайному вигляді `| a | b |`.

## Теги

Теги групують нотатки з різних папок. Вони не записуються в нотатки: Markdown залишається
таким самим, яким був, а всі теги папки зберігаються в одному файлі поруч із нотатками.

- **На нотатці**: теги розташовані під заголовком у вигляді чипів `#тег`, за якими йде **+**.
  **+** перетворюється на поле; Enter додає тег, і **+** знову з'являється після нього. Вже
  використані в папці теги підказуються під час набору. Esc скасовує; вихід з поля
  з текстом у ньому теж додає тег. **×** на чипі прибирає тег, а клік по чипу
  відкриває сторінку тега. Теги можна змінювати і в режимі читання, і в режимі редагування.
- **Написання**: провідний `#` відкидається, а пробіли всередині тега стають дефісами, тож
  `#to do` зберігається як `to-do`. Тег, що відрізняється від уже наявного лише регістром, набуває
  написання наявного — `Idea` та `idea` ніколи не стають двома різними тегами. Нотатка не може нести
  однаковий тег двічі.
- **Вкладеність**: `/` вкладає теги один в одного. `work/alpha` і `work/beta` розташовані під
  `work` у дереві тегів, і нотатка з тегом `work/alpha` рахується і під `work` теж.
- **Дерево тегів**: розділ унизу панелі файлів, окремо від дерева файлів. Кожен тег
  показує, скільки нотаток несе його чи вкладений у нього тег; стрілка батьківського тега
  згортає його нащадків, а заголовок згортає весь розділ. Фільтр за іменем
  над деревом файлів фільтрує й теги. Розділ займає до 42 % панелі й
  прокручується всередині себе; перетягування лінії над ним робить його нижчим (але ніколи вищим), подвійний
  клік по лінії повертає місце назад, а при фокусі на лінії ↑ і ↓ роблять те саме. Висота
  запам'ятовується.
- **Сторінка тега**: клік по тегу в дереві чи по чипу показує нотатки, що несуть його — батьківський
  тег показує й нотатки всіх вкладених у нього тегів теж. Кожен рядок дає ім'я нотатки, її
  папку та всі її теги; клік по імені відкриває нотатку, клік по тегу відкриває цей
  тег. Сторінка доступна лише для читання: на ній нічого редагувати, і панель форматування
  вимкнена. Для вкладеного тега батьки в його заголовку посилаються на свої власні сторінки.
- **Перейменування та видалення**: теги йдуть за нотаткою — або за всіма нотатками папки, —
  коли її перейменовують чи видаляють з панелі файлів. Нотатка, переміщена чи видалена поза редактором,
  зберігає свій запис у файлі, але цей запис не показується й не враховується, поки нотатка відсутня.
- **Папки лише для читання** (Safari, Firefox): теги показуються, але **+** і **×** —
  ні.

### `.meta.json`

Файл перебуває в корені відкритої папки й створюється при першому тегу. Він
ніколи не показується в дереві файлів.

```json
{
  "notes": {
    "Ideas.md": { "tags": ["idea", "work/alpha"] },
    "Projects/Roadmap.md": { "tags": ["work/alpha", "planning"] }
  }
}
```

Ключі — це шляхи нотаток відносно кореня, як їх показує дерево; теги зберігають
порядок, у якому їх додали. Файл записується з нотатками, відсортованими за шляхом, і з відступом у
два пробіли, тож він добре читається в diff, а нотатки, в яких не лишилося тегів, з нього прибираються.
Поля, яких редактор не знає — вгорі чи всередині запису нотатки, — зберігаються, коли він
записує файл назад, тож інші інструменти можуть зберігати в ньому свої дані. Якщо файл не є
валідним JSON-об'єктом, редактор повідомляє про це, не показує теги й ніколи не перезаписує його; теги
не можна змінювати, поки файл не виправлять і папку не відкриють знову.

Коли папку роздають по HTTP з `index.json` (див. «[Як користуватися](#як-користуватися)»),
перелічіть `.meta.json` серед його файлів, щоб теги показувалися.

## Експорт у HTML

Кнопка експорту на панелі інструментів (поруч зі «Зберегти») перетворює всю папку на статичний сайт;
«Експорт у HTML…» у контекстному меню папки робить те саме для однієї цієї папки, а на
порожньому місці під деревом — для всієї папки. Сайт записується в
`output/<folder>/` у корені папки нотаток; папка названа за моментом
експорту, `2025-12-31_23-33-33`, і може бути перейменована в діалозі. `output` ніколи
не показується в дереві. Експортувати можна лише папку, відкриту для запису.

Поки експорт виконується, діалог показує, на якому він кроці — читання нотаток, запис
сторінок, копіювання зображень — з індикатором прогресу, і його не можна закрити; «Зупинити» завершує його
після вже розпочатих файлів, залишаючи те, що встигло записатися. Кнопка експорту й
пункт меню недоступні, поки він не завершиться. Файли читаються й записуються по кілька за раз, кожна
папка на шляху створюється один раз. Наприкінці експорт зчитує папку назад з диска: якщо
якогось файлу бракує, діалог каже, скільки їх, і називає один, а не повідомляє про
успіх над порожньою папкою.

«Створити статичний сайт» — увімкнено за замовчуванням — робить сторінку на кожну нотатку, як описано нижче.
Вимкнено — експорт є однією сторінкою, `index.html`, з усіма нотатками в ній: ліва панель — це зміст,
кожна нотатка — розділ з її іменем над ним, її заголовки на рівень нижче, а їхні id з префіксом з
імені нотатки, тож посилання між нотатками й на їхні заголовки стають якорями на
сторінці. Сторінка показує по одній нотатці за раз — ту, на яку вказує чи в яку потрапляє
`#якір` адреси, а спочатку — кореневу `index` чи `README`, інакше першу нотатку в корені. Зміст,
посилання, результати пошуку та посилання **попередня** / **наступна** наприкінці кожної нотатки перемикають
між ними. Це зроблено на CSS (`:target`), тож працює і без скрипту теж; скрипт лише позначає
показувану нотатку в змісті. Друк показує всі нотатки. Вбудований пошук браузера (`⌘F`)
бачить лише показувану нотатку — поле пошуку переглядає їх усі. З тегами
дерево тегів на панелі й чипи на нотатках ведуть до розділу тегів наприкінці, із заголовком на
кожен тег і його нотатками. Сторінка — це один файл: таблиця стилів і скрипт
записані прямо в неї. Поруч з нею лежать лише зображення, зібрані в папку `assets`, яка зберігає
папки, звідки вони прийшли, але не власний крок `assets` кожної нотатки: `docs/assets/Guide/a.png`
стає `assets/docs/Guide/a.png`. В одностороінкового варіанта ті самі пошук, кнопка теми,
кнопки **розгорнути все** / **згорнути все** та змінна за шириною панель, що й у сайту; пошук читає
нотатки прямо зі сторінки, а результат переходить до своєї нотатки.

Ширина тексту та ім'я нотатки над нею дотримуються налаштувань редактора на момент
експорту: «Ширина тексту», виставлена на всю панель, дає сторінки на всю ширину, а при вимкненому
«Показувати назву нотатки як заголовок» над нотатками ім'я не додається.

Сторінки несуть увесь свій текст і звичайні відносні посилання, нічого не підвантажуючи пізніше: сайт
відкривається і з адреси `file://`, і з будь-якого веб-сервера, і для пошукової системи — у кожної сторінки
є `<title>`, `<meta name="description">`, взятий з її першого абзацу, `lang`
і один `<h1>`. Папки в навігації згортаються через `<details>`; тема слідує за
системною.

Один невеликий скрипт, `site.js`, додає те, чого не може сам HTML:

- **Пошук**: поле вгорі лівої панелі. Він шукає кожне набране слово в іменах нотаток, папках
  і тексті; результати займають місце дерева — спершу співпадні імена, кожне зі сніпетом
  навколо знайдених слів, виділеним, — а дерево повертається, коли поле очищено (Esc). Enter відкриває
  перший результат, ↓ і ↑ ходять списком. Текст приходить з `search.js`, який скрипт
  завантажує під час першого використання поля, тож самі сторінки лишаються такими ж легкими, якими були.
- **Розгорнути все** і **згорнути все** поруч з «Нотатки» над навігацією.
- Кнопка **теми** поруч з іменем сайту: місяць перемикає на темну тему, сонце — назад на
  світлу, яку б не воліла система. Поки її не натиснули, тема слідує за
  системою.
- Ручка на правому краю панелі, яка робить її ширшою чи вужчою (160–560 px; подвійний
  клік повертає значення за замовчуванням, ← → рухають її при фокусі на ручці).

Тема, ширина колонки й стан папок запам'ятовуються від сторінки до сторінки, в межах
сайту; папки показуваної сторінки завжди відкриті. Без скрипту — заблокованого чи прибраного
з шаблону — поля пошуку, кнопок і ручки просто немає, тема слідує за
системою, а сайт читається й посилається так само.

- **Сторінки**: `dir/Note.md` стає `dir/Note.html`. Нотатка, яка починається з заголовка,
  рівного її імені, отримує цей заголовок як заголовок сторінки, з її тегами під ним. Коренева нотатка
  `index` чи `README` стає титульною сторінкою, `index.html`; без неї титульна сторінка
  перелічує нотатки й теги. `[текст](other.md)` і `[[вікі-посилання]]` вказують на сторінки,
  `[[Нотатка#Заголовок]]` — на заголовок — у кожного заголовка є id, — а посилання на нотатку, якої немає
  в експорті, лишається звичайним текстом. Чекбокси завдань показуються, але не клікабельні. Front matter
  опускається.
- **Зображення**: кожна картинка й PDF у папці копіюються за тим самим шляхом, тож і
  `![[image.png]]`, і `![alt](path.png)` і далі працюють; вкладення знаходиться там само, де його
  знаходить редактор.
- **Теги**: при увімкненому прапорці «Експортувати теги» кожна сторінка показує свої теги, дерево
  тегів розташовується під навігацією, а сторінка на кожен тег перелічує його нотатки — для
  батьківського тега — нотатки всіх вкладених у нього тегів теж, — плюс покажчик тегів на
  `tags/index.html`. Враховуються лише нотатки, що потрапили в експорт.
- **Шаблон**: діалог показує шаблон сторінки; редагуйте його там само або натисніть «Повернути
  стандартний», і він запам'ятовується. Шаблон — це HTML з `{{підстановками}}`:

  | Підстановка | Означає |
  | --- | --- |
  | `{{navigation}}` | дерево папок у вигляді `<nav>`, з позначеною поточною сторінкою — обов'язкова |
  | `{{heading}}` | `<h1>` сторінки, порожній, якщо нотатка починається зі свого власного, — обов'язкова |
  | `{{content}}` | нотатка у вигляді HTML — обов'язкова |
  | `{{tags}}` | дерево тегів у вигляді `<nav>`; обов'язкова, коли теги експортуються, інакше порожня |
  | `{{pagetags}}` | теги нотатки у вигляді чипів `#тег`, що посилаються на свої сторінки |
  | `{{title}}` | ім'я сторінки як звичайний текст, для `<title>` |
  | `{{site}}` | ім'я експортованої папки |
  | `{{description}}` | перший абзац, звичайним текстом, для `<meta name="description">` |
  | `{{width}}` | `full` чи `column`, з налаштування ширини тексту |
  | `{{root}}` | `../` на кожну папку, в якій лежить сторінка, тож `{{root}}style.css` веде в корінь |
  | `{{styles}}` | таблиця стилів: `<link>` на `style.css`, або весь `<style>` цілком на односторінковому варіанті |
  | `{{script}}` | скрипт: `<script src>` на `site.js`, або весь `<script>` цілком на односторінковому варіанті |
  | `{{theme}}` | кнопка світлої/темної теми |
  | `{{path}}` | шлях нотатки, `docs/Note.md` |
  | `{{lang}}` | мова інтерфейсу, для `<html lang>` |

  Сайт отримує `style.css`, `site.js` і `search.js` у своєму корені незалежно від того, чи використовує їх
  шаблон; односторінковий варіант несе свої таблицю стилів і скрипт усередині себе й отримує
  `style.css` поруч із собою, лише якщо його шаблон, що залишився з часів до `{{styles}}`, усе ще посилається
  на нього. Стандартна таблиця стилів оформлює нотатку так само, як режим читання редактора, і читає
  ширину з `<html data-width="{{width}}">`. Підстановка, якої експорт не знає,
  залишається як є. Шаблон, збережений до появи нової підстановки, її не використовує:
  «Повернути стандартний» додає її.

## Приватність і безпека

- **Сторінка нікуди не звертається.** Content-Security-Policy у файлі дозволяє його коду запитувати
  лише файли поруч з ним на тому самому сервері (`connect-src 'self'`, для папки, що роздається
  з `index.json`), і не надсилати жодну форму нікуди. Збірка завершується помилкою, якщо політика
  зникає чи в неї проникає зовнішнє посилання. Копія PWA впускає свій маніфест і свій service worker,
  обидва зі свого власного джерела.
- **Скрипти в нотатках ніколи не виконуються.** Нотатки можуть містити HTML — саме так працює колір
  тексту, — тому політика дозволяє рівно один скрипт, власний скрипт редактора, за його хешем:
  `onerror` у `<img>` чи `<script>` у нотатці нічого не робить.
- **Те, на що нотатка посилається у вебі, завантажується звідти**: зображення, відео чи вбудований
  фрейм з адресою `https://`, як у будь-якому переглядачі Markdown, — це вибір нотатки, а не
  редактора. Такі запити не несуть `Referer`.
- **Файли залишаються на вашому диску.** Нотатки читаються й записуються на місці через File System
  Access API; запам'ятовані папки — це хендли в IndexedDB браузера, ніколи не шляхи й не
  вміст.
- Дозволи розширення: див. «[Send to Markdown](#send-to-markdown-розширення-для-chrome)».

## Можливості

- **Дерево файлів**: згортувані папки, фільтрація за іменем, створення, перейменування й видалення
  через контекстне меню, змінна за шириною панель, прихована панель (`⌘\`).
- **Форматування виділення**: заголовки H1–H3, жирний, курсив, закреслений, моноширинний,
  маркер `==…==`, колір тексту й фону, посилання, `[[вікі-посилання]]`, списки, завдання, цитата,
  блок коду, таблиця, роздільник.
- **Розмітка**: CommonMark плюс таблиці, завдання з клікабельними чекбоксами, `==маркер==`,
  `[[вікі-посилання]]`, front matter, підсвічування синтаксису для 19 мов, зображення з
  папки.
- **Зображення**: `![alt](assets/Note/image-1.png)` показує зображення за його шляхом з папки нотатки.
  Обсидіанівське `![[assets/Note/image-1.png]]` теж працює, шлях — з папки нотатки
  або інакше з кореня (`![[…|300]]` задає ширину). Старе
  вкладення з голим іменем, `![[image-1.png]]`, шукається в папці зображень з налаштувань,
  з підпапкою нотатки й без неї, в `assets/<ім'я нотатки>/`, поруч з
  нотаткою, а потім будь-де в папці за іменем, як це робить Obsidian. Папки із зображеннями
  згортаються в дереві за замовчуванням. Перейменування нотатки перейменовує і її папку із зображеннями й
  змінює посилання нотатки на свої зображення, в будь-якій формі, на новий шлях. Картинка, по якій клікнули
  в дереві, відкривається як картинка, а не як текст.
- **Додавання зображень**: кнопка картинки на панелі інструментів вибирає файли зображень;
  зображення, вставлене через `⌘V`, — скриншот, картинка, скопійована в браузері, файл,
  скопійований у файловому менеджері, — потрапляє тим самим способом. Будь-яке з них зберігається в
  папку зображень поруч з нотаткою, за замовчуванням `assets/<ім'я нотатки>/`, і вставляється як звичайний
  Markdown з його шляхом, `![image-1](assets/<ім'я нотатки>/image-1.png)`, який покаже будь-який редактор
  (пробіл у шляху записується як `%20`): у місці курсора, або в кінці нотатки, якщо не відкрито жодного
  блоку. Зображення, перетягнуті на нотатку, потрапляють туди, куди їх кинули: в це місце в блоці чи
  комірці таблиці, і поруч із текстом чи між двома блоками, в кінець блоку над ними; кидок у режимі
  читання перемикає на редагування, а кидок поза нотаткою додає зображення в кінець. Кидок з папкою
  всередині все одно відкриває папку. Вставлений скриншот називається `image-1.png`, `image-2.png` і далі;
  вибраний файл зберігає своє ім'я, з доданим номером, якщо воно вже зайняте. Комірки, скопійовані з
  електронної таблиці, вставляються як текст, а не як картинка, що йде разом з ними. Нові зображення
  приймає лише папка, відкрита для запису.
- **Теги**: вкладені теги на нотатках, дерево тегів і сторінка на кожен тег, що зберігаються окремо
  від нотаток у `.meta.json` — див. «[Теги](#теги)».
- **Експорт у HTML**: папка чи одна з її підпапок — у вигляді статичного сайту з пошуком,
  або у вигляді однієї сторінки — див. «[Експорт у HTML](#експорт-у-html)».
- **Send to Markdown**: сторінка, виділення, посилання чи зображення з Chrome в нотатку, у вигляді
  Markdown — див. «[Send to Markdown](#send-to-markdown-розширення-для-chrome)».
- **Налаштування** (шестірня вгорі праворуч, поруч з пошуком): мова інтерфейсу, тема
  (системна, світла, темна), масштаб 50–200 %, ширина тексту (колонка по центру чи вся панель),
  чи показувати ім'я нотатки як заголовок, і куди відправляються додані зображення: папка зображень
  поруч з нотаткою (`assets` за замовчуванням) і чи отримує кожна нотатка власну підпапку
  в ній; без неї всі зображення йдуть прямо в папку. Внизу — версія,
  а у встановленому застосунку — ще й перевірка оновлень, і чи встановлювати їх самостійно.
- **Мови**: англійська і ще 16 — 中文, हिन्दी, Español, Français, العربية, বাংলা,
  Português, Русский, اردو, Bahasa Indonesia, Deutsch, 日本語, Türkçe, 한국어, Italiano,
  Українська. За замовчуванням інтерфейс слідує за мовою браузера. В арабській та урду
  інтерфейс дзеркалиться справа наліво; сама нотатка зберігає свій власний напрям.
- **Телефони**: на екрані вужчому за 720 px панель файлів насувається поверх нотатки — ☰
  відкриває її, вибір нотатки чи дотик поруч закриває її, — а панель інструментів вміщається в один
  рядок; форматування отримує другий рядок лише в режимі редагування. Експорту там немає. На
  сенсорному екрані поля не менші за 16 px, тож iOS не збільшує їх, а рядки дерева
  вищі. Десктопна розкладка й запам'ятована ширина панелі не зачеплені.
- Автозбереження через секунду після редагування, скасування й повтор, пошук усередині нотатки.
- Мова, тема, масштаб, ширина тексту, ширина панелі, висота панелі тегів і остання відкрита нотатка
  запам'ятовуються.

## Переклади

Англійський текст залишається в коді: `t('tree', 'Delete')`, `tn('status', '{count} word',
'{count} words', n)`, і `data-i18n="context"` / `data-i18n-attr="context"` у
шаблоні. Перший аргумент — це контекст, частина інтерфейсу, до якої належить рядок, тож
те саме англійське слово можна перекладати по-різному в двох місцях. Словник,
`src/locales/<code>.json`, зіставляє контекст → англійський текст → переклад:

```json
{
  "tree": { "Delete": "Удалить" },
  "status": { "{count} words": { "one": "{count} слово", "few": "{count} слова", "many": "{count} слов", "other": "{count} слова" } }
}
```

Рядок, якого немає в словнику, показується англійською. Текст із числом має одну форму на кожну
категорію множини мови (`Intl.PluralRules`), з ключем за англійською формою множини.
`npm run i18n` виводить, по кожній мові, ще не перекладені рядки й ті, що більше не
використовуються; `npm test` перевіряє, що кожен переклад зберігає англійські плейсхолдери й має всі
форми множини.

Те, що Chrome показує про саме розширення — його ім'я й опис, підказку кнопки панелі
інструментів, — слідує за мовою браузера, а не панелі, через `chrome.i18n`. Ці
тексти — англійські, у `src/extension/manifest.json`, перекладені в тих самих
словниках, у контексті `manifest`; збірка записує їх у
`_locales/<code>/messages.json` і вставляє `__MSG_appName__` і подібне в маніфест.
У Chrome свої власні коди, а решту він ігнорує: `pt` стає `pt_BR` і `pt_PT`, `zh`
стає `zh_CN`, а в урду коду немає взагалі, тож там Chrome описує розширення англійською. Збірка
зупиняється, якщо ім'я довше за 75 символів чи опис довший за 132. Контекстне меню говорить
мовою панелі, якщо панель уже відкривали, інакше — мовою браузера.

Цей README теж перекладено: `docs/readme/README.<code>.md`, по одному на мову, зі
списком мов вгорі кожного. Зміна тут має потрапити й у переклади.

## Збірка

```sh
./build.sh         # installs the dependencies if needed, then builds
npm install
npm run build      # -> build/macaed.html, build/pages/, build/extension/ and its zip
npm run watch      # rebuild on changes in src/ and assets/
npm run typecheck  # tsc --noEmit
npm test           # the block model, formatting, Markdown syntax, tags, the export, clippings and the dictionaries
npm run test:browser  # in headless Chrome: the editor, HTML → Markdown, the PWA, the extension
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row: green means done
```

`build.mjs` об'єднує `src/main.ts` за допомогою esbuild в IIFE і підставляє його, разом
зі стилями та іконкою (data URI), в `src/template.html`; шаблон і таблиця стилів експорту
збираються як рядки. Content-Security-Policy шаблону отримує хеш саме цього скрипту. Результат —
`build/macaed.html`, близько 620 КБ. Збірка завершується помилкою, якщо в ньому залишається хоча б одне
зовнішнє посилання.

Той самий запуск записує `build/pages/`: ця сама сторінка у вигляді встановлюваного PWA — `index.html` з
посиланням на маніфест і `<meta name="service-worker">`, який каже сторінці зареєструвати свій
воркер, `manifest.webmanifest`, іконки й `sw.js`, який кешує сторінку, щоб вона відкривалася офлайн.
Сам `build/macaed.html` залишається єдиним файлом без зовнішніх посилань.

І `build/extension/`: `panel.html` — шаблон, його скрипт у `panel.js` — `background.js`,
іконки, `_locales/` і `manifest.json`, чия версія береться з `package.json`.
`build/macaed-extension-<version>.zip` містить ті самі файли з фіксованими датами: ті самі
вихідники дають ті самі байти.

Браузерні тести запускають локальний Chrome (`CHROME=/path/to/chrome`, щоб вибрати конкретний) і говорять з
ним за протоколом DevTools, без будь-яких залежностей; без Chrome вони пропускаються.
`tools/test-extension.mjs` завантажує розширення через цей протокол (`Extensions.loadUnpacked`
через pipe; `--load-extension` прибрали з Chrome починаючи з версії 137), відкриває папку в
боковій панелі й надсилає їй сторінки, виділення, посилання й зображення з тестових сайтів на локальному
сервері. Ні по кнопці панелі інструментів, ні по пункту контекстного меню не можна клацнути з DevTools,
тому тест викликає `onClicked` воркера сам; без справжнього кліку Chrome не дає `activeTab`, тож
тестована копія може звертатися до тестових сайтів, `*.test`, як до host permissions.

## Версії та релізи

Версія записана в одному місці, `package.json`. Збірка вставляє її на сторінку (рядок
під початковим екраном, низ налаштувань), у `manifest.json` розширення й у назву кешу PWA. Збірка коміту,
позначеного тегом `v<version>`, показує її як є; будь-яка інша додає свій коміт, `0.11.0+1a2b3c4`,
тож сторінку з `main` на GitHub Pages не приймають за реліз. `version` у Chrome містить лише
цифри, тому там коміт іде в `version_name`.

```sh
npm version minor           # 0.11.0 -> 0.12.0: package.json, package-lock.json, a commit and the tag v0.12.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

Релізний workflow зупиняється, якщо тег і `package.json` розходяться, запускає тести, потім
прикріплює `macaed-<tag>.html`, `macaed-extension-<tag>.zip` і `SHA256SUMS.txt`.

## GitHub Pages

`.github/workflows/pages.yml` збирає й тестує кожен пуш у `main` і розгортає
`build/pages/` на GitHub Pages (Settings → Pages → Source: GitHub Actions), за адресою
<https://marketkernel.github.io/markdown-catalog-editor/>. У Chrome, Edge і Arc кнопка
встановлення в адресному рядку перетворює його на окреме вікно застосунку; на iOS це Поділитися →
На початковий екран. Папки відкриваються так само, як в одиночному файлі.

**Офлайн.** Після відкриття редактор працює без з'єднання: service worker зберігає
сторінку, її маніфест та іконки в кеші, названому за версією, і віддає сторінку
звідти. Нотатки ніколи через нього не проходять — вони у вас на диску.

**Оновлення.** Кожен деплой змінює `sw.js`, тож браузер сам знаходить нового воркера — під час
запуску зі з'єднанням, кожні кілька годин, поки застосунок відкритий, коли з'єднання
повертається, або коли про це попросить Налаштування → Перевірити оновлення. Новий воркер завантажує свою
версію в окремий кеш і чекає; той, що працює, продовжує віддавати стару сторінку, теж офлайн, тож
нічого не змінюється у вас з-під рук. Налаштування, з крапкою на своїй кнопці, і початковий
екран тоді кажуть: «Версія … готова. Оновити»: Оновити зберігає відкриту нотатку (або питає,
якщо її не можна зберегти), впускає новий воркер і перезавантажує сторінку, яка один раз повідомляє, що
оновилася; старий кеш видаляється. Без натискання кнопки нова версія запускається сама, щойно
закриється кожне вікно застосунку — або, якщо в налаштуваннях позначено «Встановлювати оновлення
самостійно, коли все збережено, а застосунок працює у фоновому режимі», щойно нічого не
залишається незбереженим і вікно сховане з очей.

У цьому й полягає компроміс: встановлене PWA запускає те, що поклав останній деплой, тоді як
завантажений файл залишається тією версією, якою він є. Для версії, зафіксованої на диску, візьміть
`macaed-<tag>.html` з релізу й порівняйте його з `SHA256SUMS.txt`.

Встановлений застосунок просить браузер зберегти його сховище (`navigator.storage.persist()`): інакше при
нестачі місця на диску система могла б забрати офлайн-копію й запам'ятовані папки разом з ним.

`npm run test:browser` теж відкриває `build/pages/` (`tools/test-pwa.mjs`): service worker
бере сторінку під свій контроль, Chrome знаходить маніфест придатним для встановлення, а за зниклого сервера
сторінка все одно завантажується; потім перевірка не знаходить нічого, потім — немає з'єднання, потім —
новий деплой, який чекає, поки Оновити його впустить.

```
src/export-template.html, src/export.css   the default page template and its stylesheet

src/update.ts       the installed app's updates: the waiting worker, its version, Update

src/clip-ui.ts      the dialog that asks where it goes
src/pwa/sw.js       the service worker of the Pages build: offline, and a new version waits
src/extension/      "Send to Markdown": manifest.json; background.ts (button, shortcut, menu);
                    grab.ts (run in the page: its text or the selection); to-markdown.ts
                    (HTML → Markdown); extension.ts (in the place of platform.ts); messages.ts
tools/              build helpers (load.mjs, i18n.mjs, chrome.mjs) and the tests: block model,
```

## Обмеження

- Спільне редагування, плагіни, синхронізація та граф зв'язків не підтримуються.
- На телефоні розкладка зроблена для читання: контекстне меню дерева потребує довгого натискання,
  яке iOS не перетворює на таке, а таблиці розширюються смугами, що з'являються при наведенні.
- Записувати файли вміють лише браузери на основі Chromium.
- Розширення — для Chrome (і браузерів на його основі з боковою панеллю, таких як Edge); його
  поки немає в Chrome Web Store. Воно зберігає зображення у вебі, а не завантажує їх
  у папку: для цього знадобився б доступ до будь-якого сайту.
