로컬 폴더에 담긴 노트를 위한 Markdown 편집기 — Obsidian의 정신을 따르지만, 완전히 하나의
독립된 HTML 파일 안에 들어 있습니다. 네트워크는 전혀 사용하지 않습니다: 파일은 디스크에서
직접 읽고 저장됩니다.

**[온라인 데모](https://markdown.marketkernel.com/)** — 같은 편집기를 PWA(프로그레시브
웹 앱)로도 쓸 수 있습니다: 시스템에 설치하면 자체 창과 아이콘을 가진 별도의 앱으로 실행되며,
오프라인에서도 작동합니다. 컴퓨터에서는 Chrome, Edge, Arc의 주소표시줄에 있는 설치 버튼을
사용하고, Android에서는 Chrome의 ⋮ 메뉴 → 앱 설치, iOS에서는 Safari나 Chrome에서 공유 →
홈 화면에 추가를 사용하세요. 그곳에서도 노트는 여러분의 디스크에 그대로 남아 있고, 설치된
앱은 Finder나 탐색기에서 `.md`를 바로 열 수 있으며, 여러분이 원할 때 업데이트됩니다 —
"[GitHub Pages](#github-pages)" 참고.

같은 편집기는 **Markdown Knowledge Base**라는
[Chrome 확장 프로그램](#markdown-knowledge-base-chrome-확장-프로그램)이기도 합니다: 웹
페이지에서 텍스트를 선택하고 버튼을 누르면 **Send to Markdown**이 그것을 지식 베이스의
기본 노트에 추가합니다 — 또는 여러분이 고른 다른 노트에도 추가할 수 있습니다. 편집기
자체는 Chrome의 사이드 패널에 페이지와 나란히 열립니다.

## 사용 방법

1. `build/macaed.html`을 빌드하고("[빌드](#빌드)" 참고) 브라우저에서 여세요.
2. "폴더 열기" → `.md` 파일이 있는 폴더를 선택하세요. 폴더를 창 안으로 그냥 드래그해도
   됩니다.
3. 위쪽의 **읽기 / 편집** 전환 스위치, 또는 `⌘E`.

Chrome, Edge, Arc에서는 File System Access API를 통해 폴더가 열립니다: 노트를 그 자리에서
읽고 쓸 수 있으며, 파일과 폴더를 만들고 이름을 바꾸고 삭제하는 기능도 모두 작동합니다.
Safari와 Firefox에서는 폴더가 읽기 전용으로 열리며, `⌘S`를 누르면 수정된 파일을
다운로드하도록 제안합니다 — 휴대폰에서도 마찬가지입니다: Android의 Chrome에는 File System
Access가 없고, iOS의 모든 브라우저는 Chrome을 포함해 Safari의 엔진으로 동작하기 때문입니다.

편집기는 그곳에서 열었던 최근 폴더 여섯 개를 기억하며(페이지는 폴더의 경로를 알지 못하므로,
브라우저의 IndexedDB에 폴더의 핸들만 보관합니다), 각 폴더에서 마지막으로 열려 있던 노트도
기억합니다. 다음에 시작할 때 브라우저가 여전히 허용한다면 — 설치된 앱에서, 또는 "항상
허용"을 선택한 경우 — 마지막 폴더가 저절로 열립니다. 그렇지 않으면 시작 화면에 최근 폴더
목록이 표시됩니다: 한 번 클릭하면 브라우저가 다시 접근 권한을 요청합니다. 그 목록으로
돌아가려면 — 폴더를 바꾸거나 새 폴더를 열려면 — 파일 패널 위쪽의 폴더 이름을 클릭하거나,
설정에서 "폴더 닫기"를 클릭하세요. ×를 누르면 목록에서 폴더가 제거됩니다.

`macaed.html`을 노트 옆에 두고 HTTP로 서비스하면, 페이지가 폴더를 스스로 인식합니다 — 단,
그 옆에 `index.json`이 있어야 하며, 형식은
`{ "name": "Notes", "files": ["Note.md", "Folder/Other.md"] }`와 같습니다.

### 단일 노트

`.md` 파일은 자신의 폴더 없이 단독으로도 열 수 있습니다:

- **Finder나 탐색기에서**, 설치된 앱(컴퓨터의 Chrome이나 Edge)으로: 연결 프로그램 →
  해당 앱을 선택하거나, `.md`의 기본 앱으로 지정하세요. 앱의 창이 이미 열려 있으면
  노트가 그 창으로 들어옵니다 — 같은 파일을 창 두 개로 열면 저장이 서로를 덮어쓰게
  되기 때문입니다 — 그리고 그곳에 표시되던 폴더의 자리를 대신합니다. 같은 노트를 다시
  열면 그대로 둡니다.
- **창 위로 드래그**해도, 어떤 브라우저에서든 열립니다.

노트는 폴더에서와 마찬가지로 그 자리에서 읽고 씁니다 — Safari와 Firefox에서는 읽기
전용이며, `⌘S`를 누르면 다운로드를 제안합니다. 주변에 폴더가 없으므로 그 옆에 만들거나,
이름을 바꾸거나, 삭제할 것이 없고, 폴더에서 오는 이미지도, 태그도, 내보내기도 없습니다:
이런 기능들은 폴더를 열어야 따라옵니다. 이렇게 연 노트는 최근 폴더 목록에 추가되지
않습니다.

## Markdown Knowledge Base: Chrome 확장 프로그램

`npm run build`는 `build/extension/`도 함께 만듭니다: Chrome 확장 프로그램 형태의
편집기이며, Chrome 웹 스토어용으로 `build/macaed-extension-<version>.zip`도 함께
만듭니다. 릴리스에도 이 zip이 포함됩니다. 설치하려면: `chrome://extensions` → 개발자
모드 → 압축해제된 확장 프로그램을 로드합니다 → `build/extension`(또는 압축을 푼 zip
파일)을 선택하세요.

**지식 베이스**는 확장 프로그램에서 마지막으로 연 노트 폴더입니다. 편집기 자체 —
**전체 모드** — 는 Chrome의 사이드 패널 안에서, 페이지 옆에 — 패널이 좁기 때문에
휴대폰용 레이아웃으로 — 자리 잡으며, 탭을 바꿔도 그대로 남아 있습니다. 폴더는 파일에서와
마찬가지로 그 안에서 열리며, 최근 폴더도 기억됩니다 — 파일이나 PWA의 것과는 별도로,
확장 프로그램 자신의 목록입니다.

**툴바 버튼**(또는 `Alt+Shift+M`)을 누르면 페이지 위에 작은 창이 열립니다:

- 위쪽에는 페이지에서 선택한 부분이 Markdown 형태로 표시됩니다 — 선택한 것이 없으면
  대신 페이지의 본문: 사이트의 메뉴, 사이드바, 푸터, 공유 버튼, 폼, 숨겨진 부분을 뺀
  본문 기사가 표시됩니다.
- **Send to Markdown**은 그것을 **기본 노트** — 처음에는 지식 베이스 루트의
  `Inbox.md`이며, 처음 필요할 때 만들어집니다 — 의 끝에 추가합니다. 빈 줄 다음에
  본문이 오고, 그 뒤에 출처를 링크하는 `— [The page's title](https://…)` 줄이
  이어집니다. 저장되는 즉시 창이 닫힙니다.
- **다른 노트에 추가**: 지식 베이스의 노트들이 이름으로 찾을 수 있는 입력란과 함께
  나열됩니다. 노트를 클릭하면 그 노트에 대신 추가됩니다. 노트 옆의 별 모양은 그
  노트를 기본값으로 만들며, 기본 노트가 맨 위에 나열됩니다.
- 선택한 것이 없을 때는 **새 노트로**를 누르면 페이지가 그 자체로 하나의 노트가
  됩니다(아래 참고).
- **전체 모드**는 사이드 패널을 엽니다.

**지식 베이스가 닫혀 있을 때** — 브라우저를 다시 시작한 뒤, "항상 허용"을 선택하지
않았다면 — 페이지는 클릭 전까지는 폴더에 들어갈 수 없습니다: 창은 이를 알리고,
**전체 모드에서 열기**를 누르면 사이드 패널이 열리며, 그곳에서 폴더를 한 번 클릭하면
접근 권한을 다시 얻습니다. 폴더가 열리면 선택했던 내용은 저절로 기본 노트로 이어집니다.

사이드 패널에 지식 베이스가 열려 있으면, 노트에 추가하는 일은 패널이 맡습니다 — 패널이
그 노트를 저장되지 않은 변경 사항과 함께 열어 두고 있을 수 있으며, 뒤에서 몰래 쓰면 그
변경 사항을 잃게 되기 때문입니다. 패널이 닫혀 있으면 창이 직접 노트를 씁니다.

페이지의 **컨텍스트 메뉴**에는 **페이지를 Markdown으로 보내기**가 있고, 선택한
텍스트에는 **선택한 부분을 Markdown으로 보내기**, 링크에는 **링크를 Markdown으로
보내기**, 이미지에는 **이미지를 Markdown으로 보내기**가 있습니다. 어느 것을 선택하든
사이드 패널이 열리고, 그 안의 대화상자에 전송된 내용 — 그리고 어느 사이트에서
왔는지 — 이 여전히 수정할 수 있는 Markdown 형태로 표시되며, 어디에 저장할지 묻습니다:

- **새 노트** — 페이지의 기본값입니다: 스크랩 폴더(바꾸지 않는 한 루트의 `Clippings`;
  이 폴더는 기억되며, 비워 두면 루트를 뜻합니다)에, 페이지 제목을 따서 이름이 붙고,
  파일 이름에 쓸 수 없는 문자는 빠집니다. 이미 쓰인 이름이면 번호가 붙습니다,
  `Title 2.md`. 노트는 프런트 매터 — 페이지 제목, 주소, 날짜 — 로 시작한 다음 본문이
  이어지며, 저장되는 즉시 열립니다.

  ```markdown
  ---
  title: "The page's title"
  source: "https://example.com/post"
  clipped: 2026-10-07
  ---

  # The page's title

  The text…
  ```

- **열려 있는 노트의 끝** — 선택한 부분, 링크, 이미지의 기본값이며, Send to Markdown과
  같은 방식입니다. 링크는 출처 줄이 필요 없습니다: 링크 자신이 이미 출처이기 때문입니다.

폴더를 열기 전에 전송하면 대기 상태가 됩니다: 패널이 폴더를 요청하고, 폴더가 열리면
그제서야 대화상자가 나타납니다. 확장 프로그램이 읽을 수 없는 페이지 — Chrome 자체
페이지, 웹 스토어, PDF — 는 그 페이지로의 링크 형태로 전달됩니다.

**Markdown이 어떻게 만들어지는가.** 제목, 단락, **굵게**, *기울임*, ~~취소선~~, ==강조==,
`code`, 전체 주소를 가진 링크와 이미지, 목록 — 중첩, 번호, 작업 — 인용, 언어 정보가
있는 코드 블록(`language-…`, GitHub의 `highlight-source-…` 등에서 가져옴), 표(셀 안의
줄바꿈은 편집기가 쓰는 방식 그대로 `<br>`), 구분선을 담습니다. 텍스트는 글자 그대로
읽힙니다: 줄 맨 앞의 `*`나 `#`, 페이지에 입력된 `<b>`는 이스케이프되어 서식으로 바뀌지
않으며, 페이지의 HTML은 노트 안으로 들어오지 않습니다. 이미지는 웹에 그대로 남아
주소로 링크되며, 지연 로딩 이미지는 자리표시자 대신 실제 주소를 가져오고, 추적용
픽셀은 제외됩니다.

**권한.** `activeTab`: 버튼 클릭, 메뉴, 단축키 중 하나를 사용하면 그 하나의 탭에 대한
권한이 확장 프로그램에 주어지고, 그때서야 비로소 읽습니다 — `scripting` 권한으로
페이지 안에서 함수를 실행해 텍스트를 복사해 돌려받는 방식입니다. 콘텐츠 스크립트는
어디에서도 실행되지 않으며, 그 밖의 방법으로는 어떤 사이트에도 접근하지 않습니다:
`host_permissions`은 없으며, 빌드가 이를 거부합니다. `contextMenus`, `sidePanel`,
`storage` — 사이드 패널로 보내는 내용은 브라우저가 닫히면 사라지는
`chrome.storage.session`을 통해 해당 창의 패널에 전달되며, 패널의 언어는 메뉴를 위해
`chrome.storage.local`을 통해 워커로 전달됩니다. 버튼의 창은 `chrome.runtime` 메시지로
자신의 창의 패널에 노트에 추가해 달라고 요청하며, 패널은 확장 프로그램 자신의
페이지에서 온 것만 받아들입니다. 확장 프로그램의 페이지들은 `connect-src 'none'`을
가지고 있습니다: 편집기는 네트워크의 어떤 것에도 접근하지 않으며, 빌드가 이를 확인하고,
어떤 페이지에도 인라인 스크립트나 외부 주소가 없는지도 확인합니다.

**만들어진 방식.** 패널은 그 자체로 페이지입니다: Manifest V3가 요구하는 대로
`panel.html`과 그 스크립트인 `panel.js`로 되어 있습니다 — 같은 `src/main.ts`를 쓰되,
`src/platform.ts` 자리에 `src/extension/extension.ts`를 두며, 그 훅들은 파일 버전과
PWA에서는 아무 일도 하지 않습니다. 버튼의 창은 `popup.html`과 `popup.js`
(`src/extension/popup.ts`)이며, 페이지의 스타일을 그대로 씁니다: 패널과 같은
IndexedDB에서 지식 베이스의 핸들을 읽고, 브라우저가 여전히 허용하는 동안 그것을 통해
직접 씁니다. 워커인 `background.js`가 메뉴를 담당합니다. Chrome은 클릭 핸들러 안에서,
아무것도 기다리기 전에만 사이드 패널을 열 수 있으므로, 패널을 먼저 연 다음 탭을
읽습니다(`src/extension/take.ts`, `grab.ts`). 그 HTML은
`src/extension/to-markdown.ts`에서 Markdown으로 바뀌고, 편집기는 그것을 추가하거나
어디에 저장할지 묻습니다(`src/clip.ts`, `src/clip-ui.ts`).

## 실시간 미리보기

편집 모드에서는 문서가 서식이 적용된 채로 유지되며, 캐럿이 놓인 블록만 원본 Markdown으로
바뀝니다. 블록이란 단락, 제목, 목록 전체, 코드 블록, 인용을 말합니다: 목록이 줄 단위로
흩어지지는 않습니다. 표는 다른 방식으로 편집됩니다 — "[표](#표)" 참고.

원본 줄은 서식이 적용된 줄과 같은 글꼴 크기, 굵기, 줄 높이를 유지하므로 텍스트가 튀지
않습니다: `# Heading`은 제목 크기로 표시됩니다. 이는 자동으로 검증됩니다 — 블록이
전환될 때 위쪽 가장자리의 이동량은 확대 비율 50~200% 어디에서도 1픽셀 미만입니다.

이 모드에서 높이가 바뀌는 곳이 한 군데 있는데, 이는 피할 수 없습니다: 코드 블록은
`` ``` `` 펜스 줄 두 개를 추가로 얻습니다. 이 과정에서 이웃한 블록이 흔들리지는
않으며 — 아래쪽에 있는 내용만 밀려납니다.

목록 밖에서 Enter를 누르면 새 블록이 시작됩니다. 블록 끝이나 빈 줄에서 누르면 그
아래에 빈 줄이 열리고 캐럿이 그 위에 놓이며, 다시 누르면 하나가 더 추가됩니다.
Markdown에서는 빈 줄 하나만으로는 두 블록을 나누지 못하므로, 입력할 수 있는 빈 줄은
양쪽에 빈 줄이 있는 줄입니다 — 편집기가 구분용 줄을 스스로 더해 주므로, 입력한
텍스트가 이웃 블록에 붙는 일은 없습니다. 이런 줄과 링크 참조 정의(`[id]: https://…`)는
편집 모드에서만 표시되며, 읽기 화면은 Markdown을 있는 그대로 렌더링합니다.

## 표

표는 `| 파이프 |` 형태로 바뀌지 않습니다. 클릭하면 포인터 아래의 셀만 열리고, 그
셀은 자신의 원본 텍스트 — 굵게 표시된 글자가 아니라 `**굵게**` — 를 보여 주므로,
인라인 서식과 툴바의 표시, 링크, 색상이 그 안에서도 그대로 작동합니다. 입력하면 파일
안에서 그 셀만 다시 쓰여지며, 표의 나머지 부분은 패딩과 정렬을 그대로 유지합니다.

- **이동**: Tab과 Shift+Tab은 다음 셀과 이전 셀로, Enter는 아래 셀로, 화살표는 텍스트
  끝에서 이웃 셀로 이동합니다 — 표의 끝을 넘어가면 그다음 블록으로도 이동합니다.
  마지막 행에서 Enter를 누르면 표 아래에 새 블록이 시작됩니다.
- **줄바꿈**: Ctrl+Enter(또는 ⌘Enter, Shift+Enter)는 셀 안에서 새 줄을 시작합니다.
  표의 한 행은 Markdown에서 한 줄이므로, 줄바꿈은 `<br>`로 기록됩니다. 편집 중인
  셀에는 실제 줄바꿈으로 보이며, 붙여넣은 텍스트도 줄 구성이 그대로 유지됩니다.
  여러 줄로 된 셀 안에서는 위아래 화살표가 먼저 그 줄들 사이를 이동합니다. 셀
  텍스트는 위쪽 정렬입니다.
- **추가**: 편집 모드에서 표 위에 마우스를 올리면 아래쪽에 **+**가 있는 막대가 나타나
  행을 추가하고, 오른쪽의 **+**는 열을 추가합니다. 마지막 셀에서 Tab을 눌러도 행이
  추가됩니다.
- **삭제**: 비어 있는 행과 열만 삭제되므로, 실수로 텍스트가 사라지는 일은 없습니다.
  빈 행 위에 마우스를 올리면 왼쪽에 **×**가, 빈 열 위에 마우스를 올리면 위쪽에
  **×**가 나타납니다. 빈 셀에서 Backspace를 누르면 키보드로도 같은 일을 할 수
  있습니다: 행 전체가 비어 있으면 행을 삭제하고, 그렇지 않고 열 전체가 비어 있으면
  (헤더 포함) 열을 삭제합니다. 표에 텍스트가 하나도 남지 않으면 표 전체가
  삭제됩니다. 헤더 행은 남습니다 — 표에는 헤더가 있어야 하니까요.

행이나 열을 추가하거나 삭제하면 표는 평범한 `| a | b |` 형태로 다시 쓰여집니다.

## 태그

태그는 폴더를 넘나들며 노트를 묶어 줍니다. 태그는 노트 안에 기록되지 않습니다:
Markdown은 원래 그대로 유지되고, 폴더의 모든 태그는 노트 옆의 파일 하나에 저장됩니다.

- **노트에서**: 태그는 제목 아래에 `#태그` 칩 형태로 놓이고, 그 뒤에 **+**가
  있습니다. **+**를 누르면 입력란으로 바뀌고, Enter를 누르면 태그가 추가되며 그
  뒤에 **+**가 다시 나타납니다. 입력하는 동안 폴더에서 이미 사용 중인 태그가
  제안됩니다. Esc를 누르면 취소되고, 텍스트가 남아 있는 채로 입력란을 벗어나도
  태그가 추가됩니다. 칩의 **×**는 태그를 제거하고, 칩을 클릭하면 그 태그의
  페이지가 열립니다. 태그는 읽기 모드와 편집 모드 모두에서 바꿀 수 있습니다.
- **표기**: 맨 앞의 `#`은 빠지고, 태그 안의 공백은 대시로 바뀌어 `#to do`는
  `to-do`로 저장됩니다. 대소문자만 다른 태그는 기존 표기를 따릅니다 — `Idea`와
  `idea`가 서로 다른 두 태그가 되는 일은 없습니다. 하나의 노트가 같은 태그를 두 번
  가질 수는 없습니다.
- **중첩**: `/`는 태그를 중첩시킵니다. `work/alpha`와 `work/beta`는 태그 트리에서
  `work` 아래에 놓이고, `work/alpha` 태그가 붙은 노트는 `work`에도 함께
  집계됩니다.
- **태그 트리**: 파일 트리와 구분되어 파일 패널 아래쪽에 있는 영역입니다. 각 태그는
  자신이나 그 아래에 중첩된 태그가 붙은 노트의 수를 보여 줍니다. 상위 태그의
  화살표는 하위 태그를 접고, 제목을 누르면 영역 전체가 접힙니다. 파일 트리 위의
  이름 필터는 태그도 함께 필터링합니다. 이 영역은 패널의 최대 42%까지 차지하며
  내부에서 스크롤됩니다. 위쪽 경계선을 드래그하면 더 낮아지기만 하고(더 높아지지는
  않음), 경계선을 더블클릭하면 공간이 되돌아오며, 경계선에 포커스가 있을 때 ↑와
  ↓도 같은 일을 합니다. 높이는 기억됩니다.
- **태그의 페이지**: 트리에서 태그를 클릭하거나 칩을 클릭하면 그 태그가 붙은 노트가
  표시됩니다 — 상위 태그는 그 아래 모든 태그의 노트까지 함께 나열합니다. 각 행에는
  노트의 이름, 폴더, 모든 태그가 표시됩니다. 이름을 클릭하면 노트가 열리고, 태그를
  클릭하면 그 태그가 열립니다. 이 페이지는 읽기 전용입니다: 편집할 것이 없으며
  서식 툴바는 꺼져 있습니다. 중첩된 태그의 경우 제목 안의 상위 태그들도 각자의
  페이지로 연결됩니다.
- **이름 변경과 삭제**: 파일 패널에서 노트나 폴더 안의 모든 노트의 이름을 바꾸거나
  삭제하면 태그도 그대로 따라갑니다. 편집기 밖에서 옮기거나 삭제한 노트는 파일
  안의 항목이 그대로 남아 있지만, 노트가 없는 동안에는 그 항목이 표시되거나
  집계되지 않습니다.
- **읽기 전용 폴더**(Safari, Firefox): 태그는 표시되지만 **+**와 **×**는 표시되지
  않습니다.

### `.meta.json`

이 파일은 열린 폴더의 루트에 있으며, 첫 번째 태그를 추가할 때 만들어집니다. 파일
트리에는 절대 표시되지 않습니다.

```json
{
  "notes": {
    "Ideas.md": { "tags": ["idea", "work/alpha"] },
    "Projects/Roadmap.md": { "tags": ["work/alpha", "planning"] }
  }
}
```

키는 트리에 표시되는 것과 같은, 루트 기준 노트 경로입니다. 태그는 추가된 순서를 그대로
유지합니다. 파일은 노트를 경로순으로 정렬하고 공백 두 칸 들여쓰기로 저장되므로 diff에서
보기 좋으며, 태그가 하나도 남지 않은 노트는 파일에서 빠집니다. 편집기가 알지 못하는
필드 — 최상위든 노트 항목 내부든 — 는 파일을 다시 쓸 때도 그대로 유지되므로, 다른
도구가 자신의 데이터를 그 안에 저장할 수 있습니다. 파일이 올바른 JSON 객체가 아니면
편집기는 이를 알리고 태그를 표시하지 않으며 파일을 절대 덮어쓰지 않습니다. 파일을
고치고 폴더를 다시 열기 전까지는 태그를 바꿀 수 없습니다.

폴더를 `index.json`과 함께 HTTP로 서비스하는 경우("[사용 방법](#사용-방법)" 참고),
태그가 표시되도록 `.meta.json`도 파일 목록에 포함하세요.

## HTML로 내보내기

툴바의 내보내기 버튼(저장 옆에 있음)은 폴더 전체를 정적 사이트로 바꿉니다. 폴더의
컨텍스트 메뉴에 있는 **HTML로 내보내기…**는 그 폴더 하나만을, 트리 아래의 빈 공간에
있는 것은 폴더 전체를 같은 방식으로 내보냅니다. 사이트는 노트 폴더의 루트에 있는
`output/<폴더>/` 안에 기록됩니다. 폴더 이름은 내보내는 순간을 따서
`2025-12-31_23-33-33`처럼 지어지며, 대화상자에서 이름을 바꿀 수 있습니다. `output`은
트리에 전혀 표시되지 않습니다. 쓰기 권한으로 열린 폴더만 내보낼 수 있습니다.

내보내는 동안 대화상자는 진행 중인 단계 — 노트 읽는 중, 페이지 쓰는 중, 이미지 복사
중 — 를 진행률 표시줄과 함께 보여 주며, 닫을 수 없습니다. **중지**를 누르면 이미
진행 중인 파일까지만 마치고 멈추며, 그때까지 쓰인 내용은 그대로 남습니다. 끝날 때까지
내보내기 버튼과 메뉴 항목은 비활성화됩니다. 파일은 한 번에 여러 개씩 읽고 쓰며, 경로상의
각 폴더는 한 번만 생성됩니다. 끝나면 내보내기는 디스크에서 폴더를 다시 읽어 들입니다:
파일이 하나라도 빠졌다면, 빈 폴더를 두고 성공했다고 알리는 대신 몇 개가 빠졌는지와 그중
하나의 이름을 대화상자에 표시합니다.

**정적 사이트 만들기**(기본적으로 켜져 있음)는 아래에서 설명하듯 노트마다 하나의
페이지를 만듭니다. 이 옵션을 끄면 모든 노트가 담긴 단일 페이지 `index.html`로
내보냅니다: 왼쪽 패널이 목차가 되고, 각 노트는 그 이름을 위에 둔 하나의 섹션이 되며,
노트의 제목들은 한 단계 낮아지고 그 id 앞에 노트의 id가 붙어, 노트 사이의 링크와
제목으로의 링크가 페이지 안의 앵커가 됩니다. 페이지는 한 번에 노트 하나만 보여
줍니다 — 주소의 `#앵커`가 가리키거나 그 안을 가리키는 노트이며, 처음에는 루트의
`index`나 `README`를, 없으면 루트의 첫 번째 노트를 보여 줍니다. 목차, 링크, 검색
결과, 그리고 각 노트 끝의 **이전**/**다음** 링크가 노트 사이를 전환합니다. 이는
CSS(`:target`)로 구현되어 스크립트 없이도 작동하며, 스크립트는 단지 목차에서 현재
보이는 노트를 표시하는 역할만 합니다. 인쇄하면 모든 노트가 표시됩니다. 브라우저
자체의 찾기(`⌘F`)는 현재 보이는 노트만 보지만, 검색 필드는 모든 노트를 찾아봅니다.
태그를 쓰는 경우, 패널의 태그 트리와 노트의 칩이 끝부분의 태그 섹션으로 연결되며,
태그마다 그 노트들과 함께 제목이 하나씩 생깁니다. 페이지는 파일 하나입니다:
스타일시트와 스크립트가 그 안에 함께 기록됩니다. 이미지만 따로 옆에 놓이는데,
원래 있던 폴더 구조는 유지하되 각 노트 자신의 `assets` 단계는 유지하지 않는
`assets` 폴더에 모읍니다: `docs/assets/Guide/a.png`는 `assets/docs/Guide/a.png`가
됩니다. 단일 페이지도 사이트와 똑같은 검색, 테마 버튼, **모두 펼치기**/**모두 접기**
버튼, 크기 조절 가능한 패널을 가집니다. 검색은 노트를 페이지에서 직접 읽어
들이며, 결과를 클릭하면 해당 노트로 이동합니다.

텍스트 너비와 노트 이름 표시 여부는 내보내는 시점의 편집기 설정을 따릅니다:
**텍스트 너비**가 전체 너비로 설정되어 있으면 페이지도 전체 너비가 되고, **노트
이름을 제목으로 표시**가 꺼져 있으면 노트 위에 이름이 붙지 않습니다.

페이지는 모든 텍스트와 평범한 상대 링크를 그대로 담고 있어, 나중에 따로 불러오는
것이 없습니다: 사이트는 `file://` 주소에서도, 어떤 웹 서버에서도, 검색 엔진을
위해서도 그대로 열립니다 — 각 페이지에는 `<title>`, 첫 단락에서 가져온
`<meta name="description">`, `lang`, 그리고 `<h1>` 하나가 있습니다. 내비게이션의
폴더는 `<details>`로 접히며, 테마는 시스템을 따릅니다.

작은 스크립트 하나, `site.js`가 HTML만으로는 할 수 없는 것들을 더해 줍니다:

- **검색**: 왼쪽 패널 위쪽의 입력란입니다. 노트의 이름, 폴더, 본문에 입력된 모든
  단어를 찾습니다. 검색 결과는 트리 자리를 대신합니다 — 이름이 일치하는 것이
  먼저 나오고, 각각에는 찾은 단어 주변의 강조된 발췌문이 함께 표시되며, 입력란을
  비우면(Esc) 트리가 다시 나타납니다. Enter는 첫 번째 결과를 열고, ↓와 ↑는
  목록을 이동합니다. 이 텍스트는 `search.js`에서 가져오는데, 이 스크립트는
  입력란이 처음 사용될 때 불러오므로 페이지 자체는 그만큼 가벼운 상태를
  유지합니다.
- 내비게이션 위, "노트" 옆의 **모두 펼치기**와 **모두 접기**.
- 사이트 이름 옆의 **테마** 버튼: 달 모양은 다크 테마로, 해 모양은 다시 라이트
  테마로 전환합니다. 시스템이 어느 쪽을 선호하든 상관없습니다. 누르기 전까지는
  테마가 시스템을 따릅니다.
- 패널 오른쪽 가장자리의 손잡이로 너비를 넓히거나 좁힐 수 있습니다(160–560px;
  더블클릭하면 기본값으로 돌아가고, 손잡이에 포커스가 있을 때 ← →로 움직일 수
  있습니다).

테마, 칼럼 너비, 폴더의 펼침 상태는 사이트별로 페이지를 넘나들며 기억됩니다. 현재
보이는 페이지가 속한 폴더는 항상 펼쳐져 있습니다. 스크립트가 없으면 — 차단되었거나
템플릿에서 빠진 경우 — 검색 필드, 버튼, 손잡이는 그냥 존재하지 않으며, 테마는
시스템을 따르고, 사이트는 읽기와 링크 모두 똑같이 동작합니다.

- **페이지**: `dir/Note.md`는 `dir/Note.html`이 됩니다. 노트 이름과 같은 제목으로
  시작하는 노트는 그 제목이 페이지의 타이틀이 되고, 그 아래에 태그가 표시됩니다.
  `index`나 `README`라는 이름의 루트 노트는 첫 페이지인 `index.html`이 됩니다.
  그런 노트가 없으면 첫 페이지에는 노트와 태그 목록이 나열됩니다. `[text](other.md)`와
  `[[위키 링크]]`는 해당 페이지를 가리키고, `[[Note#Heading]]`은 그 제목을
  가리킵니다 — 모든 제목에는 id가 붙습니다 — 내보내기에 포함되지 않은 노트로의
  링크는 그냥 일반 텍스트로 남습니다. 작업 체크박스는 표시되지만 클릭할 수는
  없습니다. 프런트 매터는 빠집니다.
- **이미지**: 폴더 안의 모든 그림과 PDF는 같은 경로에 복사되므로 `![[image.png]]`와
  `![alt](path.png)` 모두 그대로 작동합니다. 임베드는 편집기가 찾는 곳과 같은
  곳에서 찾습니다.
- **태그**: **태그 내보내기** 옵션을 켜면 각 페이지에 태그가 표시되고, 내비게이션
  아래에 태그 트리가 놓이며, 태그마다 그 노트를 나열하는 페이지가 생깁니다 — 상위
  태그는 그 아래 모든 태그의 노트까지 함께 나열합니다 — 그리고 `tags/index.html`에
  태그 색인도 생깁니다. 내보내기에 포함된 노트만 집계됩니다.
- **템플릿**: 대화상자에 페이지 템플릿이 표시됩니다. 그 자리에서 직접 수정하거나
  **기본값으로 되돌리기**를 누를 수 있으며, 그 내용은 기억됩니다. 템플릿은
  `{{자리표시자}}`가 포함된 HTML입니다:

  | 자리표시자 | 의미 |
  | --- | --- |
  | `{{navigation}}` | 현재 페이지가 표시된 `<nav>` 형태의 폴더 트리 — 필수 |
  | `{{heading}}` | 페이지의 `<h1>`, 노트가 자신의 제목으로 시작하면 비어 있음 — 필수 |
  | `{{content}}` | HTML로 변환된 노트 — 필수 |
  | `{{tags}}` | `<nav>` 형태의 태그 트리; 태그를 내보낼 때는 필수, 그렇지 않으면 비어 있음 |
  | `{{pagetags}}` | 노트의 태그를 그 페이지로 링크하는 `#칩` 형태로 |
  | `{{title}}` | `<title>`에 쓸, 일반 텍스트로 된 페이지 이름 |
  | `{{site}}` | 내보낸 폴더의 이름 |
  | `{{description}}` | `<meta name="description">`에 쓸, 일반 텍스트로 된 첫 단락 |
  | `{{width}}` | 텍스트 너비 설정에 따른 `full` 또는 `column` |
  | `{{root}}` | 페이지가 속한 폴더마다 `../`가 되어, `{{root}}style.css`가 루트에 닿도록 함 |
  | `{{styles}}` | 스타일시트: `style.css`로의 `<link>`, 또는 단일 페이지에서는 `<style>` 전체 |
  | `{{script}}` | 스크립트: `site.js`를 위한 `<script src>`, 또는 단일 페이지에서는 `<script>` 전체 |
  | `{{theme}}` | 라이트/다크 버튼 |
  | `{{path}}` | 노트의 경로, `docs/Note.md` |
  | `{{lang}}` | `<html lang>`에 쓸 인터페이스 언어 |

  사이트는 템플릿이 그것들을 쓰든 안 쓰든 루트에 `style.css`, `site.js`,
  `search.js`를 갖습니다. 단일 페이지는 스타일시트와 스크립트를 내부에 담으며,
  템플릿이 `{{styles}}`가 생기기 이전 방식으로 여전히 하나를 링크하고 있을 때만
  그 옆에 `style.css`도 생깁니다. 기본 스타일시트는 노트를 편집기의 읽기
  화면처럼 꾸미며, 너비는 `<html data-width="{{width}}">`에서 읽어 옵니다.
  내보내기가 알지 못하는 자리표시자는 그대로 남습니다. 새 자리표시자가 생기기
  전에 저장된 템플릿은 그것을 쓰지 않습니다: **기본값으로 되돌리기**를 누르면
  반영됩니다.

## 개인정보 보호와 보안

- **페이지는 아무 데도 접속하지 않습니다.** 파일 안의 Content-Security-Policy는
  같은 서버에 있는, 자신 옆의 파일 말고는(`index.json`으로 서비스되는 폴더의
  경우 `connect-src 'self'`) 아무것도 가져오지 못하게 하며, 어디로도 폼을
  전송하지 않습니다. 정책이 빠지거나 외부 참조가 끼어들면 빌드가 실패합니다.
  PWA 버전은 자신의 출처(origin)에서 오는 매니페스트와 서비스 워커만
  허용합니다.
- **노트 안의 스크립트는 절대 실행되지 않습니다.** 노트는 HTML을 담을 수 있는데 —
  텍스트 색상이 바로 이런 방식으로 동작합니다 — 그래서 정책은 해시로 지정된
  편집기 자신의 스크립트 딱 하나만 허용합니다: 노트 안의 `<img>`에 있는
  `onerror`나 `<script>`는 아무 일도 하지 않습니다.
- **노트가 웹의 무언가를 링크하면 그곳에서 불러옵니다**: `https://` 주소를 가진
  이미지, 동영상, 임베드된 프레임이 그렇습니다. 다른 모든 Markdown 뷰어와
  마찬가지로, 이는 편집기가 아니라 노트가 선택한 것입니다. 이런 요청에는
  `Referer`가 실리지 않습니다.
- **파일은 여러분의 디스크에만 남습니다.** 노트는 File System Access API를 통해
  그 자리에서 읽고 씁니다. 기억된 폴더는 브라우저의 IndexedDB 안의 핸들일
  뿐, 경로나 내용이 저장되는 일은 없습니다.
- 확장 프로그램의 권한: "[Markdown Knowledge Base](#markdown-knowledge-base-chrome-확장-프로그램)" 참고.

## 기능

- **파일 트리**: 접을 수 있는 폴더, 이름으로 필터링, 컨텍스트 메뉴를 통한
  생성/이름 변경/삭제, 크기 조절 가능한 패널, 숨길 수 있는 패널(`⌘\`).
- **선택한 부분 서식 지정**: 제목 H1–H3, 굵게, 기울임, 취소선, 고정폭, `==…==`
  강조, 텍스트와 배경 색상, 링크, `[[위키 링크]]`, 목록, 작업, 인용, 코드
  블록, 표, 구분선.
- **마크업**: CommonMark에 더해 표, 클릭 가능한 체크박스가 있는 작업,
  `==강조==`, `[[위키 링크]]`, 프런트 매터, 19개 언어의 구문 강조, 폴더 안의
  이미지.
- **이미지**: `![alt](assets/Note/image-1.png)`는 노트 폴더 기준 경로로
  이미지를 보여 줍니다. Obsidian 방식인 `![[assets/Note/image-1.png]]`도
  작동하며, 경로는 노트의 폴더 기준이거나 루트 기준입니다(`![[…|300]]`으로
  너비를 지정). 이름만 있는 예전 방식의 임베드 `![[image-1.png]]`는 설정의
  이미지 폴더에서, 노트의 하위 폴더를 포함하거나 제외하고,
  `assets/<노트 이름>/`에서, 노트 옆에서, 그리고 Obsidian과 마찬가지로 그
  이름으로 폴더 전체를 뒤져서 찾습니다. 이미지 폴더는 트리에서 처음에는
  접힌 상태로 시작합니다. 노트 이름을 바꾸면 이미지 폴더의 이름도 함께
  바뀌고, 두 형식 모두에서 노트가 이미지를 가리키는 링크도 새 경로로
  바뀝니다. 트리에서 클릭한 그림은 텍스트가 아니라 그림으로 열립니다.
- **이미지 추가**: 툴바의 그림 버튼은 이미지 파일을 선택합니다. `⌘V`로
  붙여넣은 이미지 — 스크린샷, 브라우저에서 복사한 그림, 파일 관리자에서
  복사한 파일 — 도 같은 방식으로 들어갑니다. 둘 다 노트 옆의 이미지
  폴더(기본값은 `assets/<노트 이름>/`)에 저장되고, 경로를 담은 평범한
  Markdown `![image-1](assets/<노트 이름>/image-1.png)`(경로의 공백은
  `%20`으로 기록되며, 어떤 편집기에서도 표시됩니다)로 삽입됩니다: 캐럿
  위치에, 또는 열린 블록이 없으면 노트 끝에 삽입됩니다. 노트 위로 드래그한
  이미지는 놓인 자리에 들어갑니다: 블록이나 표 셀 안의 그 지점에, 그리고
  텍스트 옆이나 두 블록 사이라면 위 블록의 끝에 들어갑니다. 읽기 모드에
  드롭하면 편집 모드로 전환되고, 노트 밖에 드롭하면 이미지가 끝에
  추가됩니다. 폴더가 포함된 드롭은 여전히 그 폴더를 엽니다. 붙여넣은
  스크린샷은 `image-1.png`, `image-2.png`처럼 이름이 붙고, 선택한 파일은
  자신의 이름을 유지하되 이미 쓰인 이름이면 번호가 붙습니다. 스프레드시트에서
  복사한 셀은 함께 딸려 오는 그림이 아니라 텍스트로 붙여넣어집니다. 쓰기
  권한으로 열린 폴더만 새 이미지를 받아들입니다.
- **태그**: 노트에 중첩 태그를 달고, 태그 트리와 태그별 페이지를 가지며,
  노트와는 별도로 `.meta.json`에 보관됩니다 — "[태그](#태그)" 참고.
- **HTML로 내보내기**: 폴더 전체 또는 그 하위 폴더 하나를 검색 기능이 있는
  정적 사이트로, 또는 단일 페이지로 내보냅니다 — "[HTML로 내보내기](#html로-내보내기)" 참고.
- **단일 노트**를 설치된 앱에서 Finder나 탐색기로 열거나, 창에 드롭해서 엽니다 —
  "[단일 노트](#단일-노트)" 참고.
- **Markdown Knowledge Base**: Chrome에서 선택한 부분을 Send to Markdown으로 기본
  노트나 직접 고른 노트에 보냅니다; 페이지, 링크, 이미지는 노트로 보냅니다 —
  "[Markdown Knowledge Base](#markdown-knowledge-base-chrome-확장-프로그램)" 참고.
- **설정**(검색 옆, 오른쪽 위의 톱니바퀴): 인터페이스 언어, 테마(시스템,
  라이트, 다크), 확대/축소 50–200%, 텍스트 너비(가운데 칼럼 또는 전체
  너비), 노트 이름을 제목으로 표시할지 여부, 추가한 이미지가 어디로 갈지:
  노트 옆의 이미지 폴더(기본값 `assets`)와 노트마다 그 안에 자신의 하위
  폴더를 가질지 여부 — 하위 폴더가 없으면 모든 이미지는 그 폴더에 바로
  들어갑니다. 아래쪽에는 버전이 있고, 설치된 앱에서는 업데이트 확인 여부와
  자동 설치 여부도 있습니다.
- **언어**: 영어를 포함해 16개 언어를 더 지원합니다 — 中文, हिन्दी, Español,
  Français, العربية, বাংলা, Português, Русский, اردو, Bahasa Indonesia,
  Deutsch, 日本語, Türkçe, 한국어, Italiano, Українська. 기본적으로
  인터페이스는 브라우저의 언어를 따릅니다. 아랍어와 우르두어에서는 화면
  구성 요소가 오른쪽에서 왼쪽으로 미러링되며, 노트 자체는 자신의 고유한
  방향을 유지합니다.
- **휴대폰**: 화면 너비가 720px보다 좁으면 파일 패널이 노트 위로 미끄러져
  나타납니다 — ☰로 열고, 노트를 선택하거나 그 옆을 탭하면 닫힙니다 — 그리고
  툴바는 한 줄에 들어가며, 서식 관련 항목은 편집 모드에서만 둘째 줄을
  씁니다. 내보내기는 거기서는 빠집니다. 터치스크린에서는 입력 필드가 최소
  16px이어서 iOS가 확대하지 않으며, 트리의 행 높이도 더 커집니다. 데스크톱
  레이아웃과 그곳에서 기억된 패널 너비는 그대로입니다.
- 편집 1초 뒤 자동 저장, 실행 취소와 다시 실행, 노트 안 검색.
- 언어, 테마, 확대/축소, 텍스트 너비, 패널 너비, 태그 패널 높이, 마지막으로
  연 노트가 기억됩니다.

| 블록에서 나가기 | `Esc` |

## 번역

영어 텍스트는 코드 안에 그대로 남아 있습니다: `t('tree', 'Delete')`,
`tn('status', '{count} word', '{count} words', n)`, 그리고 템플릿 안의
`data-i18n="context"` / `data-i18n-attr="context"`. 첫 번째 인자는 컨텍스트 —
그 문자열이 인터페이스의 어느 부분에 속하는지를 나타내며, 덕분에 같은 영어
단어도 두 곳에서 다르게 번역될 수 있습니다. 사전 파일 `src/locales/<code>.json`은
컨텍스트 → 영어 텍스트 → 번역을 매핑합니다:

```json
{
  "tree": { "Delete": "Удалить" },
  "status": { "{count} words": { "one": "{count} слово", "few": "{count} слова", "many": "{count} слов", "other": "{count} слова" } }
}
```

사전에 없는 문자열은 영어로 표시됩니다. 숫자가 들어간 텍스트는 해당 언어의
복수 범주(`Intl.PluralRules`)마다 하나의 형태를 가지며, 영어 복수형을 키로
사용합니다. `npm run i18n`은 언어별로 아직 번역되지 않은 문자열과 더 이상
쓰이지 않는 문자열을 나열합니다. `npm test`는 모든 번역이 영어
자리표시자를 그대로 유지하고 있는지, 모든 복수형을 갖추고 있는지를
확인합니다.

Chrome이 확장 프로그램 자체에 대해 보여 주는 것 — 이름과 설명, 툴바 버튼의
제목 — 은 `chrome.i18n`을 통해 패널이 아니라 브라우저의 언어를 따릅니다. 이
텍스트들은 `src/extension/manifest.json` 안의 영어 원문이며, 같은 사전들의
`manifest` 컨텍스트에서 번역됩니다. 빌드는 이를 `_locales/<code>/messages.json`에
기록하고, `__MSG_appName__`과 같은 것들을 매니페스트에 넣습니다. Chrome은
자체 코드 체계를 가지고 있고 나머지는 무시합니다: `pt`는 `pt_BR`과
`pt_PT`가 되고, `zh`는 `zh_CN`이 되며, 우르두어에는 해당 코드가 없어
Chrome은 그곳에서 확장 프로그램을 영어로 설명합니다. 빌드는 이름이 75자를
넘거나 설명이 132자를 넘으면 멈춥니다. 컨텍스트 메뉴는 패널이 한 번이라도
열린 뒤에는 패널의 언어로, 그 전에는 브라우저의 언어로 표시됩니다.

이 README도 함께 번역됩니다: 언어마다 하나씩 `docs/readme/README.<code>.md`로,
각 파일 맨 위에는 언어 목록이 있습니다. 이 문서를 바꾸면 번역본도 함께
바꿔야 합니다.

## 빌드

```sh
./build.sh         # installs the dependencies if needed, then builds
npm install
npm run build      # -> build/macaed.html, build/pages/, build/extension/ and its zip
npm run watch      # rebuild on changes in src/ and assets/
npm run typecheck  # tsc --noEmit
npm test           # the block model, formatting, Markdown syntax, tags, the export, clippings and the dictionaries
npm run test:browser  # in headless Chrome: the editor, HTML → Markdown, the PWA, the extension
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row: green means done
```

`build.mjs`는 esbuild로 `src/main.ts`를 IIFE로 번들링한 다음, 스타일과
아이콘(data URI)과 함께 `src/template.html`에 대입합니다. 내보내기용
템플릿과 스타일시트는 문자열로 번들링됩니다. 템플릿의
Content-Security-Policy는 그 스크립트 하나의 해시값을 갖습니다. 결과물은
약 640KB인 `build/macaed.html`입니다. 외부 참조가 하나라도 남아 있으면
빌드는 실패합니다.

같은 실행이 `build/pages/`도 만듭니다: 설치 가능한 PWA 형태의 그 페이지 —
매니페스트 링크와, 워커를 등록하라고 페이지에 알려 주는
`<meta name="service-worker">`가 있는 `index.html`, `manifest.webmanifest`,
아이콘들, 그리고 페이지를 캐시하여 오프라인에서도 열리게 하는 `sw.js`입니다.
`build/macaed.html` 자체는 외부 참조가 전혀 없는 단일 파일로 남습니다.

그리고 `build/extension/`: `panel.html`(템플릿과 그 스크립트인 `panel.js`),
`popup.html`(페이지의 스타일과 `popup.css`)과 `popup.js`, `background.js`,
아이콘들, `_locales/`, 그리고 `package.json`의 버전을
따르는 `manifest.json`입니다. `build/macaed-extension-<version>.zip`은
같은 파일들을 고정된 날짜로 담고 있습니다: 같은 소스는 같은 바이트를
만들어 냅니다.

브라우저 테스트는 로컬 Chrome을 실행하고(특정 Chrome을 고르려면
`CHROME=/path/to/chrome`) 아무 의존성 없이 DevTools 프로토콜로 그것과
대화합니다. Chrome이 없으면 건너뜁니다. `tools/test-extension.mjs`는 이
프로토콜을 통해 확장 프로그램을 로드하고(파이프를 통한
`Extensions.loadUnpacked`; `--load-extension`은 Chrome 137 버전부터
사라졌습니다), 사이드 패널에서 폴더를 열고 로컬 서버의 테스트 사이트에서
페이지, 선택한 부분, 링크, 이미지를 보냅니다. 그다음 버튼의 창이 선택한
부분을 패널을 통해, 그리고 그 자체로 기본 노트와 고른 노트에 추가하며,
지식 베이스가 닫혀 있을 때는 전체 모드로 넘깁니다. 컨텍스트 메뉴는
DevTools에서는 클릭할 수 없으므로, 테스트는 워커의 `onClicked`를 직접
실행시키고, 버튼의 창을 옆에 둘 탭을 알려 준 채로 독립된 페이지로
엽니다. 실제 클릭이 없으면 Chrome은 `activeTab`을 부여하지
않으므로, 테스트 대상 복사본은 호스트 권한으로 테스트 사이트인 `*.test`에
접근할 수 있습니다.

## 버전과 릴리스

버전은 `package.json` 한 곳에만 적혀 있습니다. 빌드는 이를 페이지(시작
화면 아래의 줄, 설정 하단), 확장 프로그램의 `manifest.json`, PWA의 캐시
이름에 넣습니다. `v<version>` 태그가 붙은 커밋을 빌드하면 버전이 그대로
표시되고, 그 외에는 커밋 정보가 더해져 `0.11.0+1a2b3c4`처럼 되므로,
GitHub Pages의 `main` 브랜치 페이지가 릴리스로 오인되지 않습니다.
Chrome의 `version`은 숫자만 담을 수 있어, 거기서는 커밋 정보가
`version_name`에 들어갑니다.

```sh
npm version minor           # 0.11.0 -> 0.12.0: package.json, package-lock.json, a commit and the tag v0.12.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

릴리스 워크플로는 태그와 `package.json`이 일치하지 않으면 중단하고,
테스트를 실행한 다음 `macaed-<tag>.html`, `macaed-extension-<tag>.zip`,
`SHA256SUMS.txt`를 첨부합니다.

## GitHub Pages

`.github/workflows/pages.yml`은 `main`에 푸시할 때마다 빌드와 테스트를
실행하고, `build/pages/`를 GitHub Pages(설정 → Pages → 소스: GitHub
Actions)로 배포합니다. 주소는 <https://marketkernel.github.io/markdown-catalog-editor/>입니다.
Chrome, Edge, Arc에서는 주소표시줄의 설치 버튼이 이를 별도의 앱 창으로
바꿔 주고, iOS에서는 공유 → 홈 화면에 추가입니다. 폴더를 여는 방식은
단일 파일에서와 같습니다.

**오프라인.** 한 번 열면 편집기는 연결 없이도 작동합니다: 서비스
워커가 페이지와 매니페스트, 아이콘을 버전 이름을 딴 캐시에 보관해 두고
그곳에서 페이지를 제공합니다. 노트는 그것을 절대 거치지 않습니다 — 노트는
여러분의 디스크에 있습니다.

**업데이트.** 배포할 때마다 `sw.js`가 바뀌므로 브라우저가 스스로 새
워커를 찾아냅니다 — 연결된 상태로 앱을 시작할 때, 앱이 열려 있는 동안
몇 시간마다, 연결이 돌아왔을 때, 또는 설정 → 업데이트 확인을 눌렀을
때입니다. 새 워커는 자신의 버전을 자기만의 캐시에 내려받고 기다립니다.
실행 중인 워커는 오프라인에서도 계속 예전 페이지를 제공하므로, 여러분이
모르는 사이에 바뀌는 것은 아무것도 없습니다. 그러면 버튼에 점이 표시된
설정과 시작 화면에 "버전 …이(가) 준비되었습니다. 업데이트"라는 문구가
나타납니다: 업데이트를 누르면 열려 있는 노트를 저장하고(저장할 수
없으면 먼저 묻습니다), 새 워커를 들여보낸 뒤 페이지를 다시 불러오며,
업데이트되었다는 안내를 한 번 보여 줍니다. 예전 캐시는 삭제됩니다.
버튼을 누르지 않아도 새 버전은 앱의 모든 창이 닫히고 나면 시작됩니다 —
또는 설정에서 "모든 항목이 저장되고 앱이 백그라운드에 있을 때 업데이트를
자동으로 설치"를 켜 두었다면, 저장하지 않은 것이 없고 창이 보이지 않게
되는 즉시 시작됩니다.

이것이 바로 트레이드오프이기도 합니다: 설치된 PWA는 마지막 배포가 올려
놓은 것을 그대로 실행하지만, 다운로드한 파일은 그 버전 그대로 남아
있습니다. 디스크에 고정된 버전을 원한다면, 릴리스에서
`macaed-<tag>.html`을 받아 `SHA256SUMS.txt`와 비교하세요.

**`.md` 열기.** 매니페스트는 Markdown 파일을 앱이 여는 파일로
지정하고(`file_handlers`), 한 창으로만 열리게 합니다(`launch_handler`,
`focus-existing`): "[단일 노트](#단일-노트)" 참고. 페이지는 시작
과정 — 마지막 폴더를 다시 여는 과정 — 이 끝난 뒤에야 `launchQueue`를
통해 이를 받으므로, 폴더가 노트를 대체하는 일은 없습니다. 내보내는
중이거나 대화상자가 열려 있는 동안 들어온 것은 다시 열 때까지
기다립니다.

설치된 앱은 브라우저에 자신의 저장소를 보존해 달라고 요청합니다
(`navigator.storage.persist()`): 그렇지 않으면 디스크 공간이 부족할 때
오프라인 사본과 기억된 폴더들이 함께 사라질 수 있습니다.

`npm run test:browser`는 `build/pages/`도 엽니다(`tools/test-pwa.mjs`):
서비스 워커가 페이지를 넘겨받고, Chrome은 매니페스트를 설치 가능하다고
인식하며, 서버가 사라져도 페이지는 여전히 열립니다. 그다음 확인에서는
아무것도 찾지 못하고, 연결이 없다가, 새 배포가 이루어지며, 이는
업데이트가 받아들일 때까지 기다립니다. 헤드리스 Chrome은 앱에 파일을
건네주지 않으므로, 대신하는 `launchQueue`가 페이지에 실제 파일 핸들을
주어, 노트가 단독으로 열리고 편집한 내용이 그 안에 저장됩니다.

## 제한 사항

- 공동 편집, 플러그인, 동기화, 링크 그래프는 지원하지 않습니다.
- 휴대폰에서는 레이아웃이 읽기 위주로 되어 있습니다: 트리의 컨텍스트 메뉴에는
  길게 누르기가 필요한데 iOS는 이를 길게 누르기로 인식하지 않으며, 표는 호버
  시 나타나는 막대로 확장됩니다.
- Chromium 기반 브라우저만 파일을 쓸 수 있습니다.
- 확장 프로그램은 Chrome용입니다(그리고 Edge처럼 사이드 패널을 가진, Chrome
  기반 브라우저에서도 사용 가능합니다). 아직 Chrome 웹 스토어에는 등록되어
  있지 않습니다. 이미지를 폴더로 내려받지 않고 웹에 그대로 두는데, 그렇게
  하려면 모든 사이트에 대한 접근 권한이 필요하기 때문입니다.
