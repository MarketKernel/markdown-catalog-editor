نوٹس کے ایک مقامی فولڈر کے لیے ایک Markdown ایڈیٹر — Obsidian کے انداز میں، مگر مکمل طور پر
ایک ہی خودمختار HTML فائل میں سمایا ہوا۔ کوئی نیٹ ورک استعمال نہیں ہوتا: فائلیں براہ راست
ڈسک سے پڑھی اور اسی پر محفوظ کی جاتی ہیں۔

**[آن لائن ڈیمو](https://markdown.marketkernel.com/)** — وہی ایڈیٹر PWA (Progressive Web
App) کی صورت میں: اسے سسٹم میں انسٹال کیا جا سکتا ہے، اور پھر یہ ایک الگ ایپ کے طور پر چلتا
ہے، اپنی ونڈو اور آئیکن کے ساتھ، اور آف لائن کام کرتا ہے۔ کمپیوٹر پر، Chrome، Edge اور Arc
میں، ایڈریس بار کا انسٹال بٹن استعمال کریں؛ Android پر، Chrome کے ⋮ مینو ← ایپ انسٹال
کریں؛ iOS پر، شیئر ← ہوم اسکرین پر شامل کریں، Safari یا Chrome میں۔ آپ کے نوٹس وہاں بھی
آپ کی ڈسک پر رہتے ہیں، انسٹال شدہ ایپ Finder یا Explorer سے براہ راست ایک `.md` کھولتی ہے،
اور یہ تب اپڈیٹ ہوتی ہے جب آپ کہیں — دیکھیں «[GitHub Pages](#github-pages)»۔ جہاں کوئی
براؤزر ڈسک پر لکھ نہیں سکتا — Safari، Firefox، کوئی iPad یا فون — وہاں نوٹس براؤزر کے اندر
رکھے جاتے ہیں اور ZIP آرکائیو کی صورت میں اندر باہر آتے جاتے ہیں: دیکھیں
«[براؤزر میں رکھے گئے نوٹس](#براؤزر-میں-رکھے-گئے-نوٹس)»۔

وہی ایڈیٹر **Markdown Knowledge Base** بھی ہے، ایک
[Chrome ایکسٹینشن](#markdown-knowledge-base-chrome-ایکسٹینشن): کسی ویب صفحے پر متن منتخب
کریں، اس کا بٹن دبائیں، اور **Send to Markdown** اسے آپ کی نالج بیس کے ڈیفالٹ نوٹ میں شامل
کر دیتا ہے — یا کسی بھی نوٹ میں جو آپ چنیں۔ ایڈیٹر خود صفحے کے ساتھ Chrome کے سائیڈ پینل
میں کھلتا ہے۔

## استعمال کا طریقہ

1. `build/macaed.html` بنائیں (دیکھیں «[بلڈ](#بلڈ)») اور اسے کسی براؤزر میں کھولیں۔
2. «فولڈر کھولیں» ← `.md` فائلوں والا فولڈر منتخب کریں۔ آپ فولڈر کو ونڈو میں گھسیٹ بھی سکتے
   ہیں۔
3. اوپر **پڑھیں / ترمیم کریں** کا سوئچ، یا `⌘E`۔

Chrome، Edge اور Arc میں فولڈر File System Access API کے ذریعے کھلتا ہے: نوٹس اپنی جگہ پر
پڑھے اور لکھے جاتے ہیں، اور فائلیں و فولڈر بنانا، نام تبدیل کرنا اور حذف کرنا سب کام کرتا
ہے۔ Safari اور Firefox ڈسک پر کسی فولڈر میں لکھ نہیں سکتے، نہ ہی فون اور iPad: Android پر
Chrome کے پاس File System Access نہیں ہے، اور iOS اور iPadOS پر ہر براؤزر، بشمول Chrome،
Safari کے انجن پر چلتا ہے۔ وہاں نوٹس براؤزر کے اندر رکھے جاتے ہیں — دیکھیں
«[براؤزر میں رکھے گئے نوٹس](#براؤزر-میں-رکھے-گئے-نوٹس)»۔

ایڈیٹر وہاں کھولے گئے آخری چھ فولڈر یاد رکھتا ہے (صفحے کو کبھی فولڈر کا راستہ معلوم نہیں
ہوتا، اس لیے یہ فولڈر کا ہینڈل براؤزر کے IndexedDB میں رکھتا ہے)، اور ہر ایک میں آخری کھلا
نوٹ بھی۔ اگلی بار شروع ہونے پر آخری فولڈر خود بخود کھل جاتا ہے اگر براؤزر اب بھی اس کی اجازت
دیتا ہو — کسی انسٹال شدہ ایپ میں، یا جب آپ نے «ہر وزٹ پر اجازت دیں» منتخب کیا ہو۔ ورنہ شروعاتی
اسکرین حالیہ فولڈروں کی فہرست دکھاتی ہے: ایک کلک، اور براؤزر دوبارہ رسائی مانگتا ہے۔ اس
فہرست پر واپس جانے کے لیے — فولڈر تبدیل کرنے یا نیا کھولنے کے لیے — فائل پینل کے اوپر فولڈر
کے نام پر کلک کریں، یا ترتیبات میں «فولڈر بند کریں»؛ × فہرست سے فولڈر ہٹا دیتا ہے۔

اگر آپ `macaed.html` کو اپنے نوٹس کے ساتھ رکھیں اور اسے HTTP پر سرو کریں، تو صفحہ خود بخود
فولڈر اٹھا لیتا ہے — بشرطیکہ اس کے ساتھ ایک `index.json` موجود ہو، اس صورت میں
`{ "name": "Notes", "files": ["Note.md", "Folder/Other.md"] }`۔

### براؤزر میں رکھے گئے نوٹس

جہاں براؤزر ڈسک پر کسی فولڈر میں لکھ نہیں سکتا — Safari، Firefox، کوئی فون یا iPad —
شروعاتی اسکرین یہ بتاتی ہے اور اندر آنے کے دو طریقے دیتی ہے: **فولڈر کھولیں** اور **ZIP
آرکائیو کھولیں** (یا دونوں میں سے کوئی ایک ونڈو پر گھسیٹ کر چھوڑیں)۔ جو آپ کھولتے ہیں وہ
براؤزر کے IndexedDB میں کاپی ہو جاتا ہے، اور اس کے بعد ایڈیٹر اسی کاپی کو پڑھتا اور لکھتا
ہے: خودکار محفوظ، نئے نوٹس اور فولڈر، نام تبدیل کرنا، حذف کرنا، تصاویر، ٹیگز — سب کچھ ویسے
ہی کام کرتا ہے جیسے ڈسک پر۔ کچھ بھی ڈیوائس سے باہر نہیں جاتا۔

- **باہر آنے کا راستہ** ایک ZIP آرکائیو ہے: ترتیبات ← **ZIP ڈاؤن لوڈ کریں** پورے فولڈر کو —
  نوٹس، تصاویر، `.meta.json` — اس کے نام کے ایک فولڈر کے اندر پیک کر دیتا ہے، بالکل ویسے
  ہی جیسے Finder یا Explorer میں کمپریس کیا گیا کوئی فولڈر ہوتا۔ اسے دوبارہ آرکائیو کے طور
  پر کھولنا اسے ویسا ہی واپس لاتا ہے جیسا وہ تھا۔ یہ بٹن ڈسک پر موجود فولڈر کے ساتھ بھی
  ہوتا ہے، اس کی ایک فوری کاپی کے طور پر۔
- **کوئی آرکائیو** جو Finder، Explorer یا `zip` سے بنایا گیا ہو، اس کے اندر موجود اکلوتے
  فولڈر کے طور پر کھلتا ہے (یا، اوپر سیدھی فائلیں ہونے پر، آرکائیو کے نام کے تحت)۔ صرف وہی
  جو ایڈیٹر دکھاتا ہے کاپی ہوتا ہے — نوٹس، تصاویر اور اٹیچمنٹس، `.meta.json`؛ ڈاٹ-فولڈرز،
  `node_modules`، `output/` اور Mac کا `__MACOSX` باہر رہ جاتے ہیں۔ اسے فولڈر چننے والے
  کسی بھی آپشن کی ضرورت نہیں ہوتی، جو ایک پرانے iPad کے لیے ضروری ہے، جس کا Safari کوئی
  فولڈر نہیں چن سکتا۔
- **شروعاتی اسکرین اس براؤزر میں رکھے گئے فولڈروں کی فہرست دکھاتی ہے**، سب سے نیا سب سے
  پہلے، اور اگلی بار شروع ہونے پر آخری والا خود بخود کھل جاتا ہے۔ اسی فولڈر یا آرکائیو کو
  دوبارہ کھولنا پہلی کاپی پر تبدیلی لکھنے کی بجائے اس کے ساتھ ایک دوسری کاپی شامل کر دیتا ہے
  ("Notes 2")۔ × پوچھنے کے بعد براؤزر سے ایک کاپی ہٹا دیتا ہے — یہ اس کی اکلوتی کاپی ہو
  سکتی ہے۔
- **HTML میں برآمد کریں** سائٹ کو `output/` میں لکھنے کی بجائے ایک ZIP آرکائیو کے طور پر
  ڈاؤن لوڈ کرتا ہے۔
- **یہ کب تک رہتے ہیں**: براؤزر سے سائٹ کا ڈیٹا ہمیشہ کے لیے رکھنے کو کہا جاتا ہے
  (`navigator.storage.persist()`) — Firefox آپ سے پوچھتا ہے، Chrome اور Safari خود فیصلہ
  کرتے ہیں، انسٹال شدہ ایپ کے لیے زیادہ آسانی سے۔ جو براؤزر منع کر دے وہ ڈسک کم پڑنے پر
  نوٹس مٹا سکتا ہے، اور Safari ایسی سائٹ کا ڈیٹا مٹا دیتا ہے جسے Safari کے سات دن کے
  استعمال میں نہ کھولا گیا ہو، جب تک وہ ہوم اسکرین پر شامل نہ ہو۔ سائٹ کا ڈیٹا یا براؤزر کی
  ہسٹری مٹانا کسی بھی براؤزر میں انہیں حذف کر دیتا ہے۔ اس لیے وقتاً فوقتاً ایک ZIP آرکائیو
  ڈاؤن لوڈ کرتے رہیں — یہ براؤزر کے باہر اکلوتی کاپی ہوتی ہے۔

جہاں IndexedDB بند ہو (کچھ پرائیویٹ ونڈوز)، فولڈر پہلے کی طرح صرف پڑھنے کے لیے کھلتا ہے،
اور `⌘S` تبدیل شدہ نوٹ ڈاؤن لوڈ کرنے کی پیشکش کرتا ہے۔

### اکیلا نوٹ

`.md` فائل اکیلے، اپنے فولڈر کے بغیر، کھولی جا سکتی ہے:

- **Finder یا Explorer سے**، انسٹال شدہ ایپ میں (کمپیوٹر پر Chrome یا Edge): Open With ←
  ایپ، یا اسے `.md` کے لیے ڈیفالٹ ایپ بنا دیں۔ نوٹ ایپ کی ونڈو میں آ جاتا ہے جب ایک کھلی ہو
  — ایک ہی فائل پر دو ونڈوز ایک دوسرے کا محفوظ کیا ہوا مٹا دیتیں — اور وہاں دکھائے گئے
  فولڈر کی جگہ لے لیتا ہے؛ اسی نوٹ کو دوبارہ کھولنا اسے جیسا ہے ویسا چھوڑ دیتا ہے۔
- **ونڈو پر گھسیٹا گیا**، کسی بھی براؤزر میں۔

نوٹ اپنی جگہ پر پڑھا اور لکھا جاتا ہے، جیسے فولڈر میں — Safari اور Firefox میں صرف پڑھنے
کے لیے، جہاں `⌘S` ڈاؤن لوڈ کی پیشکش کرتا ہے (نوٹ براؤزر میں کاپی نہیں ہوتا؛ اس کا فولڈر ہو
سکتا ہے)۔ اس کے گرد کوئی فولڈر نہ ہونے کی وجہ سے اس کے
ساتھ بنانے، نام تبدیل کرنے یا حذف کرنے کو کچھ نہیں، اور نہ اس کے فولڈر کی تصاویر، ٹیگز یا
برآمد: وہ فولڈر کھولنے کے ساتھ آتے ہیں۔ اس طرح کھلا نوٹ حالیہ فولڈروں میں شامل نہیں ہوتا۔

## Markdown Knowledge Base: Chrome ایکسٹینشن

`npm run build` `build/extension/` بھی لکھتا ہے: ایڈیٹر بطور Chrome ایکسٹینشن، اور اس کا
`build/macaed-extension-<version>.zip` Chrome ویب اسٹور کے لیے؛ ریلیز میں یہ زپ بھی شامل
ہوتی ہے۔ اسے انسٹال کرنے کے لیے: `chrome://extensions` ← ڈویلپر موڈ ← Load unpacked ←
`build/extension` (یا کھولی گئی زپ)۔

**نالج بیس** وہ نوٹس کا فولڈر ہے جو ایکسٹینشن میں آخری بار کھولا گیا۔ ایڈیٹر خود — **مکمل
موڈ** — Chrome کے سائیڈ پینل میں رہتا ہے، صفحے کے ساتھ، فون لے آؤٹ میں، کیونکہ پینل تنگ
ہوتا ہے؛ یہ ٹیبز کے درمیان بھی وہیں رہتا ہے۔ اس میں فولڈر اسی طرح کھلتا ہے جیسے فائل میں، اور
حالیہ فولڈر یاد رکھے جاتے ہیں — ایکسٹینشن کے اپنے، فائل یا PWA کے فولڈروں سے الگ۔

**ٹول بار بٹن** (یا `Alt+Shift+M`) صفحے کے اوپر ایک چھوٹی ونڈو کھولتا ہے:

- اوپر، جو صفحے پر منتخب ہے، Markdown کے طور پر — یا، کچھ منتخب نہ ہونے پر، صفحے کا مرکزی
  متن: مضمون، سائٹ کے مینیوز، سائیڈبارز، فوٹر، شیئر بٹنز، فارمز اور چھپے ہوئے حصوں کے
  بغیر۔
- **Send to Markdown** اسے **ڈیفالٹ نوٹ** کے آخر میں شامل کرتا ہے — شروع میں نالج بیس کی
  جڑ پر `Inbox.md`، جو پہلی بار ضرورت پڑنے پر بنتا ہے۔ ایک خالی سطر کے بعد متن آتا ہے، پھر
  ایک سطر `— [The page's title](https://…)` جو اس کے ماخذ سے جوڑتی ہے۔ لکھے جانے کے بعد
  ونڈو بند ہو جاتی ہے۔
- **کسی اور نوٹ میں شامل کریں**: نالج بیس کے نوٹس، نام سے ڈھونڈنے کے لیے ایک فیلڈ کے ساتھ؛
  کسی نوٹ پر کلک اسے وہاں شامل کرتا ہے۔ نوٹ کے ساتھ ستارہ اسے ڈیفالٹ بنا دیتا ہے؛ ڈیفالٹ
  سب سے پہلے فہرست میں آتا ہے۔
- کچھ منتخب نہ ہونے پر، **نئے نوٹ کے طور پر** صفحے کو اپنا ایک نوٹ بنا دیتا ہے (نیچے)۔
- **مکمل موڈ** سائیڈ پینل کھولتا ہے۔

**جب نالج بیس بند ہو** — Chrome آخری سائیڈ پینل بند ہوتے ہی، اور دوبارہ شروع ہونے کے بعد،
فولڈر کی رسائی واپس لے لیتا ہے، جب تک آپ نے «ہر وزٹ پر اجازت دیں» منتخب نہ کیا ہو — صفحہ اس
وقت تک فولڈر میں نہیں جا سکتا جب تک آپ کلک نہ کریں۔ ونڈو تب یہ بتاتی ہے اور پھر بھی نوٹس کو
ویسے ہی دکھاتی ہے جیسے پینل نے آخری بار دیکھے تھے: **Send to Markdown**، یا کسی نوٹ پر
کلک، آپ کے منتخب کردہ کو ایکسٹینشن کے اپنے اسٹوریج میں الگ رکھ دیتا ہے، اور جیسے ہی کوئی
سائیڈ پینل فولڈر دوبارہ کھولتا ہے یہ اسی نوٹ کے آخر میں چلا جاتا ہے۔ **کھولیں** ونڈو میں
براہِ راست Chrome سے فولڈر مانگتا ہے؛ سائیڈ پینل میں فولڈر پر ایک کلک بھی یہی کرتا ہے۔ جب
Chrome پوچھے تو **ہر وزٹ پر اجازت دیں** چنیں: تب فولڈر، پینل بند ہونے پر اور دوبارہ شروع
ہونے کے بعد بھی کھلا رہتا ہے۔

جب سائیڈ پینل میں نالج بیس کھلی ہو، تو پینل ہی نوٹ میں شامل کرتا ہے — ہو سکتا ہے وہ نوٹ وہاں
ایسی تبدیلیوں کے ساتھ کھلا ہو جو ابھی محفوظ نہیں ہوئیں، جنہیں پیٹھ پیچھے لکھنا کھو دیتا۔
جب کوئی پینل کھلا نہ ہو اور فولڈر کو اب بھی اجازت حاصل ہو — ہر وزٹ پر، یا **کھولیں** کے
ذریعے — تو ونڈو خود نوٹ لکھتی ہے۔

کسی صفحے کی **کانٹیکسٹ مینو** میں **صفحہ Markdown کو بھیجیں** ہوتا ہے؛ منتخب متن پر،
**انتخاب Markdown کو بھیجیں**؛ لنک پر، **لنک Markdown کو بھیجیں**؛ تصویر پر، **تصویر
Markdown کو بھیجیں**۔ ان میں سے کوئی بھی سائیڈ پینل نہیں کھولتا: پینل کا کھلنا صفحے کو ایک
طرف دباتا ہے۔ ونڈو میں کوئی پینل کھلا نہ ہو تو، آپ نے جو منتخب کیا وہ **Send to Markdown**
کی طرح ڈیفالٹ نوٹ کے آخر میں چلا جاتا ہے — یا، نالج بیس بند ہونے پر، اوپر کی طرح اس کا
انتظار کرتا ہے۔ ٹول بار بٹن بتاتا ہے کہ کیا ہوا: تھوڑی دیر کے لیے ایک ٹک، اپنے ٹائٹل میں
وجہ کے ساتھ `!`، اور جب تک کوئی پینل فولڈر نہ کھولے کتنی بھیجی گئی چیزیں منتظر ہیں۔ ونڈو کا
پینل کھلا ہو تو، یہ اس کے بجائے وہاں جاتا ہے، جہاں ایک ڈائیلاگ دکھاتا ہے کہ کیا آیا ہے — اور
کس سائٹ سے — Markdown کی صورت میں جسے آپ اب بھی تبدیل کر سکتے ہیں، اور پوچھتا ہے کہ یہ کہاں
جائے:

- **نیا نوٹ**، صفحے کے لیے پہلے سے طے شدہ: کلپنگز فولڈر میں (جڑ پر `Clippings`، جب تک آپ
  اسے تبدیل نہ کریں؛ فولڈر یاد رکھا جاتا ہے، خالی کا مطلب جڑ ہے)، صفحے کے عنوان کے نام پر،
  جو فائل کا نام نہیں بن سکتا وہ چھوڑ کر۔ پہلے سے لیا گیا نام ایک نمبر پاتا ہے، `Title
  2.md`۔ نوٹ front matter سے شروع ہوتا ہے — صفحے کا عنوان، اس کا پتہ اور دن — اور پھر متن؛
  محفوظ ہونے پر یہ کھل جاتا ہے۔

  ```markdown
  ---
  title: "The page's title"
  source: "https://example.com/post"
  clipped: 2026-10-07
  ---

  # The page's title

  The text…
  ```

- **کھلے نوٹ کا اختتام**، انتخاب، لنک یا تصویر کے لیے پہلے سے طے شدہ، بالکل اسی طرح جیسے
  Send to Markdown۔ لنک کو ماخذ کی سطر کی ضرورت نہیں: وہ خود اپنا ماخذ ہے۔

جب تک کوئی فولڈر کبھی کھولا ہی نہ گیا ہو، بھیجی گئی چیز انتظار کرتی ہے: پینل فولڈر مانگتا
ہے، اور جیسے ہی کوئی
کھلتا ہے ڈائیلاگ آ جاتا ہے۔ وہ صفحہ جسے ایکسٹینشن شاید پڑھ نہ سکے — Chrome کے اپنے صفحات،
ویب اسٹور، کوئی PDF — اس کے لنک کی صورت میں پہنچتا ہے۔

**Markdown کیا ہے۔** سرخیاں، پیراگراف، **بولڈ**، *ترچھا*، ~~کٹا ہوا متن~~، ==نمایاں==،
`کوڈ`، اپنے مکمل پتوں کے ساتھ لنکس اور تصاویر، فہرستیں — نیسٹڈ، نمبر والی، کام — اقتباسات،
اپنی زبان کے ساتھ کوڈ بلاکس (`language-…` سے، GitHub کے `highlight-source-…` اور ایسے ہی
دیگر سے)، جدولیں (خلیے میں سطر کی شکست `<br>` کے طور پر، جیسے ایڈیٹر لکھتا ہے)، ڈیوائیڈرز۔
متن خود کی طرح پڑھا جاتا ہے: سطر کے شروع میں `*`، `#` یا صفحے پر ٹائپ کردہ `<b>` ایسکیپ ہو
جاتا ہے، اس لیے وہ کبھی فارمیٹنگ میں تبدیل نہیں ہوتا، اور صفحے کا کوئی HTML نوٹ میں نہیں
جاتا۔ تصاویر ویب پر ہی رہتی ہیں، اپنے پتے سے منسلک؛ کاہل (lazy) تصویر کا اصل پتہ لیا جاتا ہے
نہ کہ اس کا پلیس ہولڈر، ٹریکنگ پکسل چھوڑ دیے جاتے ہیں۔

**اجازتیں۔** `activeTab`: بٹن پر، مینو میں یا شارٹ کٹ سے ایک کلک ایکسٹینشن کو وہی ایک ٹیب
دیتا ہے، اور تبھی وہ اسے پڑھتا ہے — `scripting` کے ذریعے، ایک فنکشن جو صفحے میں چلتا ہے
اور اس کا متن کاپی کر کے واپس کرتا ہے۔ کہیں بھی کوئی content script نہیں چلتا، اور بصورت
دیگر کسی سائٹ تک رسائی نہیں: کوئی `host_permissions` نہیں، جسے بلڈ مسترد کر دیتا ہے۔
`offscreen`: ورکر کے پاس کوئی DOM نہیں ہوتا، اس لیے جب کوئی پینل کھلا نہ ہو تو صفحے یا
انتخاب کا HTML ایکسٹینشن کی ایک offscreen دستاویز میں Markdown بنتا ہے، جو کام ختم ہوتے ہی
بند ہو جاتی ہے۔
`contextMenus`، `sidePanel`، اور `storage` — جو کچھ سائیڈ پینل کو بھیجا جاتا ہے وہ اس کی
ونڈو کے پینل کو `chrome.storage.session` کے ذریعے پہنچتا ہے، جو براؤزر بند ہونے پر ختم ہو
جاتا ہے؛ `chrome.storage.local` میں وہ چیز جو بٹن کی ونڈو نے نالج بیس بند ہونے کے دوران
الگ رکھی تھی، اس کے نوٹس کی فہرست، اور پینل کی زبان اور ڈیفالٹ نوٹ، ورکر کے لیے، موجود
ہوتی ہے۔ بٹن کی ونڈو اور ورکر اس پینل سے جس میں نالج بیس کھلی ہو `chrome.runtime` پیغام کے
ذریعے کسی نوٹ میں شامل کرنے کو کہتے ہیں، جسے پینل صرف ایکسٹینشن کے اپنے صفحات سے قبول کرتا
ہے۔ ایکسٹینشن کے صفحات
میں `connect-src 'none'` ہے: ایڈیٹر نیٹ ورک پر کچھ بھی نہیں پہنچتا؛ بلڈ اس کی اور اس بات کی
تصدیق کرتا ہے کہ کسی صفحے میں کوئی inline script یا بیرونی پتہ نہیں ہے۔

**یہ کیسے بنا ہے۔** پینل خود وہ صفحہ ہے: `panel.html` اور اس کا اسکرپٹ `panel.js` میں، جیسا
Manifest V3 چاہتا ہے — وہی `src/main.ts`، `src/platform.ts` کی جگہ
`src/extension/extension.ts` کے ساتھ، جس کے ہُکس فائل اور PWA میں کچھ نہیں کرتے۔ بٹن کی
ونڈو `popup.html` اور `popup.js` ہے (`src/extension/popup.ts`)، صفحے کے اسٹائلز کے ساتھ:
یہ نالج بیس کا ہینڈل اسی IndexedDB سے پڑھتی ہے جو پینل استعمال کرتا ہے، اور جب تک براؤزر
اجازت دیتا رہے اس کے ذریعے لکھتی ہے؛ ورنہ یہ بھیجی گئی چیز کو `chrome.storage.local` میں
الگ رکھ دیتی ہے، جہاں فولڈر کھولنے والا پینل اسے پا لیتا ہے (`src/extension/messages.ts`)۔
ورکر، `background.js`، کے پاس مینو ہے: یہ ٹیب پڑھتا ہے (`src/extension/take.ts`،
`grab.ts`)، اور جو لیا گیا اسے ونڈو کے پینل کو بھیجتا ہے، یا اسے ڈیفالٹ نوٹ میں شامل کرتا
ہے جیسا کہ بٹن کی ونڈو کرتی ہے (`src/extension/knowledge.ts`)، Markdown کے لیے
`offscreen.html` کے ذریعے (`src/extension/offscreen.ts`)۔ HTML
`src/extension/to-markdown.ts` میں Markdown بن جاتا ہے، اور ایڈیٹر اسے شامل کرتا ہے یا
پوچھتا ہے کہ یہ کہاں جائے (`src/clip.ts`، `src/clip-ui.ts`)۔

## براہِ راست پیش منظر

ترمیمی موڈ میں دستاویز فارمیٹ شدہ رہتی ہے، اور صرف وہ بلاک جس میں کرسر ہوتا ہے خام Markdown
میں بدل جاتا ہے۔ بلاک ایک پیراگراف، ایک سرخی، ایک مکمل فہرست، ایک کوڈ بلاک یا اقتباس ہوتا
ہے: فہرست سطر در سطر نہیں بکھرتی۔ جدولیں مختلف انداز میں ترمیم کی جاتی ہیں — دیکھیں
«[جدولیں](#جدولیں)»۔

ماخذ سطر فارمیٹ شدہ سطر کا فونٹ سائز، وزن اور لائن اونچائی برقرار رکھتی ہے، تاکہ متن نہ
اچھلے: `# Heading` سرخی کے سائز میں دکھایا جاتا ہے۔ اس کی خودکار جانچ ہوتی ہے — جب کوئی
بلاک بدلا جاتا ہے، 50 سے 200% تک کسی بھی زوم سطح پر اس کا اوپری کنارہ ایک پکسل سے کم حرکت
کرتا ہے۔

ایک جگہ ایسی ہے جہاں اونچائی واقعی بدلتی ہے، اور یہ اس موڈ کے لیے ناگزیر ہے: کوڈ بلاک کو
`` ``` `` کی دو باڑ (fence) سطریں مل جاتی ہیں۔ اس دوران ملحقہ بلاکس نہیں ہلتے — صرف وہی
حرکت کرتا ہے جو نیچے ہے۔

فہرست سے باہر Enter ایک نیا بلاک شروع کرتا ہے۔ بلاک کے آخر میں، یا خالی سطر پر دبانے سے،
یہ نیچے ایک خالی سطر کھولتا ہے اور کرسر اس پر رکھتا ہے؛ دوبارہ دبانے سے، یہ ایک اور سطر
شامل کرتا ہے۔ Markdown میں ایک ہی خالی سطر صرف دو بلاکس کو الگ کرتی ہے، اس لیے وہ خالی سطر
جس میں آپ ٹائپ کر سکتے ہیں وہ ہے جس کے دونوں اطراف خالی سطریں ہوں — ایڈیٹر خود الگ کرنے
والی سطر شامل کرتا ہے، اور ٹائپ کیا گیا متن کبھی ملحقہ بلاک سے چپکتا نہیں۔ ایسی سطریں اور
لنک حوالہ تعریفات (`[id]: https://…`) صرف ترمیمی موڈ میں دکھائی جاتی ہیں؛ قراءت کا منظر
Markdown کو جیسا وہ ہے ویسا ہی دکھاتا ہے۔

## جدولیں

جدول کبھی `| pipes |` میں تبدیل نہیں ہوتا۔ کلک پوائنٹر کے نیچے والا صرف ایک خلیہ کھولتا ہے،
اور خلیہ اپنا خام متن دکھاتا ہے — بولڈ کی بجائے `**bold**` — تاکہ اندرونی فارمیٹنگ اور ٹول
بار کے نشانات، لنکس اور رنگ اس کے اندر بھی کام کرتے رہیں۔ ٹائپ کرنا فائل میں صرف اسی خلیے
کو دوبارہ لکھتا ہے؛ جدول کا باقی حصہ اپنی پیڈنگ اور ترتیب برقرار رکھتا ہے۔

- **حرکت**: Tab اور Shift+Tab اگلے اور پچھلے خلیے میں جاتے ہیں، Enter نیچے والے خلیے میں،
  تیر متن کے کنارے پر ملحقہ خلیے میں — اور جدول کے کنارے سے آگے اس کے ساتھ والے بلاک میں۔
  آخری قطار میں Enter جدول کے نیچے ایک نیا بلاک شروع کرتا ہے۔
- **لائن بریکس**: Ctrl+Enter (نیز ⌘Enter یا Shift+Enter) خلیے کے اندر ایک نئی سطر شروع
  کرتا ہے۔ جدول کی قطار Markdown کی ایک سطر ہوتی ہے، اس لیے بریک `<br>` کے طور پر لکھا جاتا
  ہے؛ زیرِ ترمیم خلیہ اسے ایک حقیقی لائن بریک کے طور پر دکھاتا ہے، اور پیسٹ کیا گیا متن اپنی
  سطریں اسی طرح برقرار رکھتا ہے۔ کئی سطروں والے خلیے کے اندر، اوپر اور نیچے کے تیر پہلے اس
  کی سطروں کے درمیان حرکت کرتے ہیں۔ خلیے کا متن اوپر کی طرف سیدھ میں رکھا جاتا ہے۔
- **اضافہ**: ترمیمی موڈ میں، جدول پر ہوور کرنے سے نیچے **+** والی ایک پٹی دکھائی دیتی ہے،
  جو ایک قطار شامل کرتی ہے، اور اس کے دائیں ایک اور، جو ایک کالم شامل کرتی ہے۔ آخری خلیے
  میں Tab بھی ایک قطار شامل کرتا ہے۔
- **حذف**: صرف خالی قطاریں اور کالم حذف ہوتے ہیں، اس لیے کسی غلطی سے کوئی متن ضائع نہیں
  ہوتا۔ خالی قطار پر ہوور کرنے سے اس کے بائیں **×** دکھائی دیتا ہے، خالی کالم پر اس کے اوپر
  **×**۔ خالی خلیے میں Backspace کی بورڈ سے وہی کام کرتا ہے: اگر پوری قطار خالی ہو تو یہ
  قطار حذف کرتا ہے، ورنہ کالم اگر پورا کالم خالی ہو (ہیڈر سمیت)؛ جس جدول میں کوئی متن نہ
  بچے وہ پورا حذف ہو جاتا ہے۔ ہیڈر قطار باقی رہتی ہے — جدول کو اس کی ضرورت ہوتی ہے۔

اضافہ یا حذف جدول کو سادہ `| a | b |` صورت میں دوبارہ لکھ دیتا ہے۔

- **نوٹ پر**: ٹیگ عنوان کے نیچے `#tag` چپس کے طور پر بیٹھتے ہیں، جن کے بعد ایک **+** آتا
  ہے۔ **+** ایک فیلڈ میں بدل جاتا ہے؛ Enter ٹیگ شامل کرتا ہے، اور **+** اس کے بعد دوبارہ
  نمودار ہوتا ہے۔ ٹائپ کرتے وقت فولڈر میں پہلے سے استعمال شدہ ٹیگز تجویز کیے جاتے ہیں۔ Esc
  منسوخ کرتا ہے؛ فیلڈ کو متن کے ساتھ چھوڑنا بھی ٹیگ شامل کر دیتا ہے۔ چپ پر **×** ٹیگ ہٹاتا
  ہے، اور چپ پر کلک ٹیگ کا صفحہ کھولتا ہے۔ ٹیگ قراءت اور ترمیم دونوں موڈز میں تبدیل کیے جا
  سکتے ہیں۔
- **ہجے**: شروع کا `#` ہٹا دیا جاتا ہے اور ٹیگ کے اندر خالی جگہیں ڈیشز بن جاتی ہیں، اس لیے
  `#to do` کو `to-do` کے طور پر محفوظ کیا جاتا ہے۔ وہ ٹیگ جو کسی موجودہ ٹیگ سے صرف حروف کی
  بڑائی/چھوٹائی (case) میں مختلف ہو، موجودہ ہجے اپنا لیتا ہے — `Idea` اور `idea` کبھی دو
  الگ ٹیگ نہیں بنتے۔ کوئی نوٹ ایک ہی ٹیگ دو بار نہیں رکھ سکتا۔
- **نیسٹنگ**: `/` ٹیگز کو نیسٹ کرتا ہے۔ `work/alpha` اور `work/beta` ٹیگ ٹری میں `work` کے
  نیچے بیٹھتے ہیں، اور `work/alpha` ٹیگ والا نوٹ `work` کے نیچے بھی شمار ہوتا ہے۔
- **ٹیگ ٹری**: فائل پینل کے نیچے والا سیکشن، فائل ٹری سے الگ۔ ہر ٹیگ دکھاتا ہے کہ کتنے
  نوٹس اسے یا اس کے نیچے نیسٹ کیا گیا ٹیگ رکھتے ہیں؛ والد ٹیگ کا تیر اس کے بچوں کو سمیٹتا
  ہے، اور عنوان پورے سیکشن کو سمیٹتا ہے۔ فائل ٹری کے اوپر والا نام فلٹر ٹیگز کو بھی فلٹر
  کرتا ہے۔ یہ سیکشن پینل کا 42% تک لیتا ہے اور اندر ہی اسکرول ہوتا ہے؛ اس کے اوپر والی لکیر
  کو گھسیٹنا اسے چھوٹا کرتا ہے (کبھی بڑا نہیں)، لکیر پر ڈبل کلک جگہ واپس دے دیتا ہے، اور
  لکیر پر فوکس ہونے پر ↑ اور ↓ وہی کام کرتے ہیں۔ اونچائی یاد رکھی جاتی ہے۔
- **ٹیگ کا صفحہ**: ٹری میں کسی ٹیگ پر، یا چپ پر کلک کرنا، اسے رکھنے والے نوٹس دکھاتا ہے —
  والد ٹیگ اپنے نیچے ہر ٹیگ کے نوٹس بھی فہرست کرتا ہے۔ ہر قطار نوٹ کا نام، اس کا فولڈر اور
  اس کے سب ٹیگز دیتی ہے؛ نام پر کلک نوٹ کھولتا ہے، کسی ٹیگ پر کلک وہ ٹیگ کھولتا ہے۔ صفحہ
  صرف پڑھنے کے لیے ہے: اس پر ترمیم کے لیے کچھ نہیں، اور فارمیٹنگ ٹول بار بند ہے۔ نیسٹڈ ٹیگ
  کے لیے اس کے عنوان میں والد ٹیگز اپنے اپنے صفحات سے جڑے ہوتے ہیں۔
- **نام تبدیل کرنا اور حذف کرنا**: فائل پینل سے کسی نوٹ، یا فولڈر کے ہر نوٹ کا نام تبدیل
  یا حذف کرنے پر ٹیگ اس کی پیروی کرتے ہیں۔ ایڈیٹر کے باہر منتقل یا حذف کیا گیا نوٹ فائل میں
  اپنا اندراج رکھتا ہے، لیکن جب تک نوٹ غائب ہے یہ اندراج نہ دکھایا جاتا ہے نہ شمار کیا جاتا
  ہے۔
- **صرف پڑھنے کے لیے فولڈرز** (Safari، Firefox): ٹیگز دکھائے جاتے ہیں، لیکن **+** اور
  **×** نہیں۔

### `.meta.json`

یہ فائل کھلے فولڈر کی جڑ پر ہوتی ہے اور پہلے ٹیگ کے ساتھ بنائی جاتی ہے۔ یہ فائل ٹری میں
کبھی نہیں دکھائی جاتی۔

```json
{
  "notes": {
    "Ideas.md": { "tags": ["idea", "work/alpha"] },
    "Projects/Roadmap.md": { "tags": ["work/alpha", "planning"] }
  }
}
```

کلیدیں جڑ کی نسبت نوٹ کے راستے ہیں، جیسے ٹری انہیں دکھاتی ہے؛ ٹیگز وہی ترتیب رکھتے ہیں جس
میں وہ شامل کیے گئے تھے۔ فائل راستے کے حساب سے ترتیب دیے گئے نوٹس اور دو اسپیس کے انڈینٹیشن
کے ساتھ لکھی جاتی ہے، تاکہ یہ diff میں اچھی طرح پڑھی جا سکے، اور جن نوٹس کے پاس کوئی ٹیگ
نہیں بچتا وہ اس سے ہٹا دیے جاتے ہیں۔ وہ فیلڈز جنہیں ایڈیٹر نہیں جانتا — اوپر یا کسی نوٹ کے
اندراج کے اندر — جب یہ فائل واپس لکھتا ہے تو محفوظ رکھے جاتے ہیں، تاکہ دوسرے اوزار اپنا
ڈیٹا اس میں محفوظ کر سکیں۔ اگر فائل درست JSON آبجیکٹ نہ ہو، تو ایڈیٹر یہ بتاتا ہے، کوئی
ٹیگ نہیں دکھاتا، اور کبھی اس کے اوپر نہیں لکھتا؛ جب تک فائل درست نہ کی جائے اور فولڈر دوبارہ
نہ کھولا جائے ٹیگز تبدیل نہیں کیے جا سکتے۔

جب فولڈر کو `index.json` کے ساتھ HTTP پر سرو کیا جاتا ہے (دیکھیں «[استعمال کا
طریقہ](#استعمال-کا-طریقہ)»)، تو ٹیگز دکھانے کے لیے `.meta.json` کو اس کی فائلوں میں شامل
کریں۔

## HTML میں برآمد کریں

ٹول بار پر برآمد کا بٹن (محفوظ کریں کے ساتھ) پورے فولڈر کو ایک اسٹیٹک سائٹ میں بدل دیتا ہے؛
فولڈر کی کانٹیکسٹ مینو میں **HTML میں برآمد کریں…** صرف اسی فولڈر کے لیے وہی کام کرتا ہے،
اور ٹری کے نیچے خالی جگہ پر پورے فولڈر کے لیے۔ سائٹ نوٹس کے فولڈر کی جڑ پر `output/<folder>/`
میں لکھی جاتی ہے؛ فولڈر کا نام برآمد کے لمحے پر رکھا جاتا ہے، `2025-12-31_23-33-33`، اور
ڈائیلاگ میں اس کا نام تبدیل کیا جا سکتا ہے۔ `output` ٹری میں کبھی نہیں دکھایا جاتا۔ صرف
وہی فولڈر برآمد کیا جا سکتا ہے جو لکھنے کے لیے کھلا ہو۔

برآمد کے چلتے ہوئے، ڈائیلاگ دکھاتا ہے کہ یہ کس مرحلے پر ہے — نوٹس پڑھنا، صفحات لکھنا،
تصاویر نقل کرنا — ایک پروگریس بار کے ساتھ، اور اسے بند نہیں کیا جا سکتا؛ **روکیں** پہلے سے
جاری فائلوں کے بعد اسے ختم کر دیتا ہے، جو اب تک لکھا گیا وہ چھوڑ کر۔ جب تک یہ مکمل نہ ہو
برآمد کا بٹن اور مینو آئٹم بند رہتے ہیں۔ فائلیں ایک وقت میں کئی پڑھی اور لکھی جاتی ہیں، راستے
کا ہر فولڈر ایک بار بنایا جاتا ہے۔ آخر میں برآمد فولڈر کو ڈسک سے واپس پڑھتا ہے: اگر کوئی
فائل غائب ہو تو ڈائیلاگ بتاتا ہے کتنی ہیں اور ایک کا نام لیتا ہے، خالی فولڈر پر کامیابی کی
اطلاع دینے کی بجائے۔

**اسٹیٹک سائٹ بنائیں** — طے شدہ طور پر فعال — ہر نوٹ کے لیے ایک صفحہ بناتا ہے، جیسا نیچے
بیان کیا گیا ہے۔ غیر فعال ہونے پر، برآمد ایک ہی صفحہ ہوتا ہے، `index.html`، جس میں ہر نوٹ
موجود ہوتا ہے: بائیں پینل ایک فہرستِ مضامین ہے، ہر نوٹ اپنے نام کے ساتھ ایک سیکشن ہے، اس کی
سرخیاں ایک درجہ نیچے اور ان کے ids نوٹ کے نام سے سابقہ لگے ہوئے، تاکہ نوٹس کے درمیان اور
ان کی سرخیوں تک روابط صفحے پر اینکرز بن جائیں۔ صفحہ ایک وقت میں ایک نوٹ دکھاتا ہے — وہ جس
کی طرف پتے کا `#anchor` اشارہ کرتا ہے یا جس کے اندر جاتا ہے، اور شروع میں جڑ کا `index` یا
`README`، ورنہ جڑ کا پہلا نوٹ۔ فہرستِ مضامین، لنکس، تلاش کے نتائج، اور ہر نوٹ کے آخر میں
**پچھلا** / **اگلا** لنکس ان کے درمیان تبدیل کرتے ہیں۔ یہ CSS (`:target`) میں کیا جاتا ہے،
اس لیے یہ اسکرپٹ کے بغیر بھی کام کرتا ہے؛ اسکرپٹ صرف فہرستِ مضامین میں دکھائے جا رہے نوٹ کو
نشان زد کرتا ہے۔ پرنٹنگ ہر نوٹ دکھاتی ہے۔ براؤزر کی اپنی تلاش (`⌘F`) صرف دکھائے جا رہے نوٹ
کو دیکھتی ہے — تلاش کا فیلڈ ان سب میں دیکھتا ہے۔ ٹیگز کے ساتھ، پینل میں ٹیگ ٹری اور نوٹس پر
چپس آخر میں ایک ٹیگز سیکشن کی طرف لے جاتے ہیں، ہر ٹیگ کے لیے ایک سرخی اور اس کے نوٹس کے
ساتھ۔ صفحہ ایک فائل ہے: اسٹائل شیٹ اور اسکرپٹ اسی میں لکھے جاتے ہیں۔ صرف تصاویر اس کے ساتھ
بیٹھتی ہیں، ایک `assets` فولڈر میں جمع، جو وہ فولڈر برقرار رکھتا ہے جن سے وہ آئی تھیں مگر
ہر نوٹ کے اپنے `assets` مرحلے کو نہیں: `docs/assets/Guide/a.png`، `assets/docs/Guide/a.png`
بن جاتا ہے۔ ایک صفحے کے پاس سائٹ جیسی ہی تلاش، تھیم بٹن، **سب پھیلائیں** / **سب سمیٹیں**
بٹنز اور سائز بدلنے کے قابل پینل ہوتا ہے؛ تلاش نوٹس کو براہ راست صفحے سے پڑھتی ہے، اور
نتیجہ اپنے نوٹ کی طرف جاتا ہے۔

برآمد کے وقت متن کی چوڑائی اور اس کے اوپر نوٹ کا نام ایڈیٹر کی ترتیبات کی پیروی کرتے ہیں:
**متن کی چوڑائی** کو پورے پینل پر سیٹ کرنا پورے عرض کے صفحات دیتا ہے، اور **نوٹ کا نام
عنوان کے طور پر دکھائیں** غیر فعال ہونے پر نوٹس کے اوپر کوئی نام شامل نہیں ہوتا۔

صفحات اپنا سارا متن اور سادہ نسبتی لنکس لے کر چلتے ہیں، بعد میں کچھ بھی لوڈ کیے بغیر: سائٹ
`file://` پتے سے، کسی بھی ویب سرور سے، اور سرچ انجن کے لیے کھلتی ہے — ہر صفحے کا ایک
`<title>`، اس کے پہلے پیراگراف سے لیا گیا `<meta name="description">`، ایک `lang`، اور
ایک `<h1>` ہوتا ہے۔ نیویگیشن میں فولڈر `<details>` کے ساتھ سمٹتے ہیں؛ تھیم سسٹم کی پیروی
کرتی ہے۔

ایک چھوٹا سا اسکرپٹ، `site.js`، وہ کچھ شامل کرتا ہے جو اکیلا HTML نہیں کر سکتا:

- **تلاش**: بائیں پینل کے اوپر ایک فیلڈ۔ یہ نوٹس کے ناموں، فولڈروں اور متن میں ٹائپ کیا
  گیا ہر لفظ ڈھونڈتا ہے؛ نتائج ٹری کی جگہ لے لیتے ہیں — پہلے مماثل نام، ہر ایک ملنے والے
  الفاظ کے گرد ایک جھلک کے ساتھ، نمایاں — اور جب فیلڈ خالی کیا جاتا ہے (Esc) تو ٹری واپس آ
  جاتی ہے۔ Enter پہلا نتیجہ کھولتا ہے، ↓ اور ↑ فہرست میں چلتے ہیں۔ متن `search.js` سے آتا
  ہے، جسے اسکرپٹ فیلڈ کے پہلی بار استعمال ہونے پر لوڈ کرتا ہے، تاکہ صفحات خود اتنے ہی ہلکے
  رہیں جتنے تھے۔
- نیویگیشن کے اوپر «نوٹس» کے ساتھ **سب پھیلائیں** اور **سب سمیٹیں**۔
- سائٹ کے نام کے ساتھ ایک **تھیم** بٹن: چاند تاریک تھیم میں بدلتا ہے، سورج واپس روشن میں،
  جو بھی سسٹم کو پسند ہو۔ جب تک اسے دبایا نہ جائے، تھیم سسٹم کی پیروی کرتی ہے۔
- پینل کے دائیں کنارے پر ایک ہینڈل جو اسے چوڑا یا تنگ کرتا ہے (160–560 پکسل؛ ڈبل کلک طے
  شدہ قدر واپس دیتا ہے، ہینڈل پر فوکس ہونے پر ← → اسے حرکت دیتے ہیں)۔

تھیم، کالم کی چوڑائی اور فولڈروں کی حالت صفحے سے صفحے تک یاد رکھی جاتی ہے، ہر سائٹ کے
لیے؛ دکھائے جا رہے صفحے کے فولڈر ہمیشہ کھلے ہوتے ہیں۔ اسکرپٹ کے بغیر — بلاک شدہ، یا
ٹیمپلیٹ سے نکالا گیا — تلاش کا فیلڈ، بٹنز اور ہینڈل بس موجود نہیں ہوتے، تھیم سسٹم کی پیروی
کرتی ہے، اور سائٹ اسی طرح پڑھی اور لنک کی جاتی ہے۔

- **صفحات**: `dir/Note.md`، `dir/Note.html` بن جاتا ہے۔ جو نوٹ اپنے نام کے برابر سرخی سے
  شروع ہوتا ہے اس سرخی کو صفحے کا عنوان مل جاتا ہے، اس کے نیچے اس کے ٹیگز کے ساتھ۔ `index`
  یا `README` نام کا جڑ نوٹ پہلا صفحہ بن جاتا ہے، `index.html`؛ اس کے بغیر پہلا صفحہ نوٹس
  اور ٹیگز کی فہرست دیتا ہے۔ `[text](other.md)` اور `[[wiki links]]` صفحات کی طرف اشارہ
  کرتے ہیں، `[[Note#Heading]]` سرخی کی طرف — ہر سرخی ایک id رکھتی ہے — اور ایسے نوٹ کا لنک
  جو برآمد میں نہیں ہے سادہ متن رہتا ہے۔ کام کے چیک باکسز دکھائے جاتے ہیں، مگر کلک کے قابل
  نہیں۔ Front matter چھوڑ دیا جاتا ہے۔
- **تصاویر**: فولڈر کی ہر تصویر اور PDF اسی راستے پر نقل کی جاتی ہے، تاکہ `![[image.png]]`
  اور `![alt](path.png)` دونوں کام کرتے رہیں؛ embed وہیں ملتا ہے جہاں ایڈیٹر اسے پاتا ہے۔
- **ٹیگز**: **ٹیگ برآمد کریں** باکس فعال ہونے پر، ہر صفحہ اپنے ٹیگز دکھاتا ہے، ٹیگ ٹری
  نیویگیشن کے نیچے بیٹھتی ہے، اور ہر ٹیگ کا ایک صفحہ اس کے نوٹس فہرست کرتا ہے — والد ٹیگ
  اپنے نیچے ہر ٹیگ کے نوٹس بھی — نیز `tags/index.html` پر ٹیگز کا ایک اشاریہ۔ صرف وہی
  نوٹس شمار ہوتے ہیں جو برآمد میں ہیں۔
- **ٹیمپلیٹ**: ڈائیلاگ صفحے کا ٹیمپلیٹ دکھاتا ہے؛ اسے وہیں ترمیم کریں یا **طے شدہ پر واپس
  لائیں**، اور یہ یاد رکھا جاتا ہے۔ ٹیمپلیٹ `{{placeholders}}` کے ساتھ HTML ہے:

  | پلیس ہولڈر | کس کی نمائندگی کرتا ہے |
  | --- | --- |
  | `{{navigation}}` | `<nav>` کی صورت میں فولڈر ٹری، موجودہ صفحہ نشان زد — لازمی |
  | `{{heading}}` | صفحے کا `<h1>`، خالی جب نوٹ اپنی ہی سرخی سے شروع ہو — لازمی |
  | `{{content}}` | HTML کی صورت میں نوٹ — لازمی |
  | `{{tags}}` | `<nav>` کی صورت میں ٹیگ ٹری؛ ٹیگز برآمد ہونے پر لازمی، ورنہ خالی |
  | `{{pagetags}}` | نوٹ کے ٹیگز اپنے صفحات سے لنک کرتے `#chips` کے طور پر |
  | `{{title}}` | `<title>` کے لیے، سادہ متن کے طور پر صفحے کا نام |
  | `{{site}}` | برآمد شدہ فولڈر کا نام |
  | `{{description}}` | `<meta name="description">` کے لیے، سادہ متن میں پہلا پیراگراف |
  | `{{width}}` | متن کی چوڑائی کی ترتیب سے، `full` یا `column` |
  | `{{root}}` | اس فولڈر کے لیے `../` جس میں صفحہ ہے، تاکہ `{{root}}style.css` جڑ تک پہنچے |
  | `{{styles}}` | اسٹائل شیٹ: `style.css` کا `<link>`، یا ایک صفحے پر مکمل `<style>` |
  | `{{script}}` | اسکرپٹ: `site.js` کے لیے `<script src>`، یا ایک صفحے پر مکمل `<script>` |
  | `{{theme}}` | روشن/تاریک بٹن |
  | `{{path}}` | نوٹ کا راستہ، `docs/Note.md` |
  | `{{lang}}` | انٹرفیس کی زبان، `<html lang>` کے لیے |

  سائٹ کو اپنی جڑ پر `style.css`، `site.js` اور `search.js` ملتے ہیں چاہے ٹیمپلیٹ انہیں
  استعمال کرے یا نہ کرے؛ ایک صفحہ اپنی اسٹائل شیٹ اور اسکرپٹ اندر ہی لے کر چلتا ہے، اور
  اپنے ساتھ `style.css` تب ہی پاتا ہے جب اس کا ٹیمپلیٹ، `{{styles}}` سے پہلے کا، اب بھی
  ایک سے لنک کرتا ہو۔ طے شدہ اسٹائل شیٹ نوٹ کو ایڈیٹر کے قراءت منظر کی طرح سجاتی ہے اور
  چوڑائی `<html data-width="{{width}}">` سے پڑھتی ہے۔ جس پلیس ہولڈر کو برآمد نہیں جانتا اسے
  جیسا ہے ویسا چھوڑ دیا جاتا ہے۔ نیا پلیس ہولڈر آنے سے پہلے محفوظ کیا گیا ٹیمپلیٹ اسے استعمال
  نہیں کرتا: **طے شدہ پر واپس لائیں** اسے لے آتا ہے۔

## رازداری اور حفاظت

- **صفحہ کہیں نہیں پہنچتا۔** فائل میں ایک Content-Security-Policy اس کے کوڈ کو اسی سرور
  پر اپنے ساتھ کی فائلوں کے سوا کچھ نہیں لانے دیتی (`connect-src 'self'`، `index.json` کے
  ساتھ سرو کیے گئے فولڈر کے لیے)، اور کسی بھی جگہ کوئی فارم نہیں بھیجنے دیتی۔ اگر پالیسی
  غائب ہو جائے یا کوئی بیرونی حوالہ اس میں آ جائے تو بلڈ ناکام ہو جاتا ہے۔ PWA کی کاپی اپنے
  مانیفسٹ اور اپنے سروس ورکر کو آنے دیتی ہے، دونوں اپنے ہی اوریجن سے۔
- **نوٹس میں موجود اسکرپٹس کبھی نہیں چلتیں۔** نوٹس میں HTML ہو سکتا ہے — اسی طرح متن کے
  رنگ کام کرتے ہیں — اس لیے پالیسی بالکل ایک ہی اسکرپٹ کی اجازت دیتی ہے، ایڈیٹر کا اپنا،
  اس کے ہیش کے ذریعے: کسی نوٹ میں `<img>` یا `<script>` پر `onerror` کچھ نہیں کرتا۔
- **ویب پر نوٹ جس سے لنک کرتا ہے وہ وہیں سے لوڈ ہوتا ہے**: `https://` پتے والی تصویر،
  ویڈیو یا embedded فریم، جیسے کسی بھی Markdown ویور میں — یہ نوٹ کا انتخاب ہے، ایڈیٹر کا
  نہیں۔ ایسی درخواستیں کوئی `Referer` نہیں لے جاتیں۔
- **فائلیں آپ کی ڈسک پر رہتی ہیں۔** نوٹس File System Access API کے ذریعے اپنی جگہ پر پڑھے
  اور لکھے جاتے ہیں؛ یاد رکھے گئے فولڈر براؤزر کے IndexedDB میں ہینڈلز ہیں، کبھی راستے یا
  مواد نہیں۔ جہاں براؤزر ڈسک پر لکھ نہیں سکتا، وہاں آپ کے کھولے گئے فولڈرز اس کے IndexedDB
  میں کاپی ہو جاتے ہیں، صرف اسی ڈیوائس پر، اور اس سے باہر صرف آپ کے ڈاؤن لوڈ کیے گئے ZIP
  آرکائیو کے طور پر جاتے ہیں — دیکھیں «[براؤزر میں رکھے گئے نوٹس](#براؤزر-میں-رکھے-گئے-نوٹس)»۔
- ایکسٹینشن کی اجازتیں: دیکھیں «[Markdown Knowledge Base](#markdown-knowledge-base-chrome-ایکسٹینشن)»۔

## خصوصیات

- **فائل ٹری**: سمٹنے والے فولڈر، نام سے فلٹرنگ، کانٹیکسٹ مینو کے ذریعے بنانا، نام تبدیل
  کرنا اور حذف کرنا، سائز بدلنے کے قابل پینل، چھپانے کے قابل پینل (`⌘\`)۔
- **انتخاب کی فارمیٹنگ**: سرخیاں H1–H3، بولڈ، ترچھا، کٹا ہوا متن، مونو اسپیس، `==…==`
  نمایاں، متن اور پس منظر کا رنگ، لنک، `[[wiki link]]`، فہرستیں، کام، اقتباس، کوڈ بلاک،
  جدول، ڈیوائیڈر۔
- **مارک اپ**: CommonMark نیز جدولیں، کلک کے قابل چیک باکسز والے کام، `==highlight==`،
  `[[wiki links]]`، front matter، 19 زبانوں کے لیے سنٹیکس ہائی لائٹنگ، فولڈر سے تصاویر۔
- **تصاویر**: `![alt](assets/Note/image-1.png)` نوٹ کے فولڈر سے اپنے راستے پر ایک تصویر
  دکھاتا ہے۔ Obsidian کا `![[assets/Note/image-1.png]]` بھی کام کرتا ہے، راستہ نوٹ کے
  فولڈر سے یا پھر جڑ سے (`![[…|300]]` چوڑائی طے کرتا ہے)۔ ننگے نام والے پرانے embed،
  `![[image-1.png]]`، کو ترتیبات کے تصاویر کے فولڈر میں، نوٹ کے ذیلی فولڈر کے ساتھ اور اس
  کے بغیر، `assets/<نوٹ کا نام>/` میں، نوٹ کے ساتھ، اور پھر Obsidian کی طرح نام کے ذریعے
  فولڈر میں کہیں بھی ڈھونڈا جاتا ہے۔ تصاویر کے فولڈر ٹری میں سمٹے ہوئے شروع ہوتے ہیں۔ نوٹ
  کا نام تبدیل کرنا اس کے تصاویر کے فولڈر کا نام بھی تبدیل کرتا ہے اور نوٹ کے اپنی تصاویر
  کے لنکس کو، کسی بھی صورت میں، نئے راستے پر بدل دیتا ہے۔ ٹری میں کلک کی گئی تصویر تصویر کے
  طور پر کھلتی ہے، متن کے طور پر نہیں۔
- **تصاویر شامل کرنا**: ٹول بار پر تصویر کا بٹن تصویری فائلیں منتخب کرتا ہے؛ `⌘V` سے
  پیسٹ کی گئی تصویر — اسکرین شاٹ، براؤزر میں کاپی کی گئی تصویر، فائل مینیجر میں کاپی کی
  گئی فائل — اسی طرح شامل ہوتی ہے۔ کوئی بھی نوٹ کے ساتھ تصاویر کے فولڈر میں محفوظ ہوتی ہے،
  طے شدہ طور پر `assets/<نوٹ کا نام>/`، اور اپنے راستے کے ساتھ سادہ Markdown کے طور پر
  شامل کی جاتی ہے، `![image-1](assets/<نوٹ کا نام>/image-1.png)`، جسے ہر ایڈیٹر دکھاتا ہے
  (راستے میں خالی جگہ `%20` کے طور پر لکھی جاتی ہے): کرسر پر، یا جب کوئی بلاک کھلا نہ ہو تو
  نوٹ کے آخر میں۔ نوٹ پر گھسیٹی گئی تصاویر وہیں شامل ہوتی ہیں جہاں چھوڑی جاتی ہیں: کسی
  بلاک یا جدول کے خلیے میں اس نقطے پر، اور متن کے ساتھ یا دو بلاکس کے درمیان، اوپر والے
  بلاک کے آخر میں؛ قراءت موڈ میں ڈراپ ترمیم کی طرف بدل جاتا ہے، اور نوٹ سے باہر ڈراپ آخر
  میں تصاویر شامل کرتا ہے۔ فولڈر پر مشتمل ڈراپ پھر بھی فولڈر کھولتا ہے۔ پیسٹ کیا گیا
  اسکرین شاٹ `image-1.png`، `image-2.png` وغیرہ کا نام پاتا ہے؛ منتخب کی گئی فائل اپنا نام
  رکھتی ہے، دہرائے جانے پر ایک نمبر کے اضافے کے ساتھ۔ اسپریڈشیٹ سے کاپی کیے گئے خلیے متن کے
  طور پر پیسٹ ہوتے ہیں، نہ کہ ان کے ساتھ آنے والی تصویر کے طور پر۔ صرف وہی فولڈر نئی تصاویر

انگریزی متن کوڈ میں رہتا ہے: `t('tree', 'Delete')`، `tn('status', '{count} word',
'{count} words', n)`، اور ٹیمپلیٹ میں `data-i18n="context"` / `data-i18n-attr="context"`۔
پہلا دلیل سیاق و سباق (context) ہے — انٹرفیس کا وہ حصہ جس سے کوئی سٹرنگ تعلق رکھتی ہے،
تاکہ ایک ہی انگریزی لفظ دو جگہوں پر مختلف طریقے سے ترجمہ کیا جا سکے۔ ایک ڈکشنری،
`src/locales/<code>.json`، سیاق ← انگریزی متن ← ترجمہ کا نقشہ بناتی ہے:

```json
{
  "tree": { "Delete": "Удалить" },
  "status": { "{count} words": { "one": "{count} слово", "few": "{count} слова", "many": "{count} слов", "other": "{count} слова" } }
}
```

وہ سٹرنگ جو ڈکشنری میں نہیں ہے انگریزی میں دکھائی جاتی ہے۔ نمبر والے متن کی زبان کی جمع کی
ہر قسم (`Intl.PluralRules`) کے لیے ایک صورت ہوتی ہے، جس کی کلید انگریزی جمع کی صورت ہے۔
`npm run i18n` ہر زبان کے لیے وہ سٹرنگز فہرست کرتا ہے جو ابھی ترجمہ نہیں ہوئیں اور وہ جو
اب استعمال میں نہیں ہیں؛ `npm test` تصدیق کرتا ہے کہ ہر ترجمہ انگریزی پلیس ہولڈرز برقرار
رکھتا ہے اور اس کے پاس جمع کی تمام صورتیں ہیں۔

Chrome خود ایکسٹینشن کے بارے میں جو دکھاتا ہے — اس کا نام اور تفصیل، ٹول بار بٹن کا عنوان
— پینل کی بجائے `chrome.i18n` کے ذریعے براؤزر کی زبان کی پیروی کرتا ہے۔ وہ متن
`src/extension/manifest.json` میں انگریزی ہیں، انہی ڈکشنریوں میں `manifest` سیاق کے تحت
ترجمہ شدہ؛ بلڈ انہیں `_locales/<code>/messages.json` میں لکھتا ہے اور `__MSG_appName__`
جیسی چیزیں مانیفسٹ میں ڈالتا ہے۔ Chrome کے اپنے کوڈز ہیں اور باقی کو نظر انداز کرتا ہے:
`pt`، `pt_BR` اور `pt_PT` بن جاتا ہے، `zh`، `zh_CN` بن جاتا ہے، اور اردو کا کوئی کوڈ نہیں،
اس لیے وہاں Chrome ایکسٹینشن کو انگریزی میں بیان کرتا ہے۔ بلڈ 75 حروف سے زیادہ لمبے نام یا
132 سے زیادہ لمبی تفصیل پر رک جاتا ہے۔ کانٹیکسٹ مینو پینل کھلنے کے بعد پینل کی زبان بولتا
ہے، اس سے پہلے براؤزر کی۔

یہ README بھی ترجمہ شدہ ہے: `docs/readme/README.<code>.md`، ہر زبان کے لیے ایک، ہر ایک کے
اوپر زبانوں کی فہرست کے ساتھ۔ یہاں کوئی تبدیلی تراجم میں بھی ہونی چاہیے۔

## بلڈ

```sh
./build.sh         # installs the dependencies if needed, then builds
npm install
npm run build      # -> build/macaed.html, build/pages/, build/extension/ and its zip
npm run watch      # rebuild on changes in src/ and assets/
npm run typecheck  # tsc --noEmit
npm test           # the block model, formatting, Markdown syntax, tags, the export, clippings and the dictionaries
npm run test:browser  # in headless Chrome: the editor, HTML → Markdown, the PWA, the extension
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row: green means done
```

`build.mjs` esbuild کے ساتھ `src/main.ts` کو ایک IIFE میں باندھتا ہے اور اسے، اسٹائلز اور
آئیکن (data URI کے طور پر) کے ساتھ، `src/template.html` میں رکھ دیتا ہے؛ برآمد کا ٹیمپلیٹ
اور اسٹائل شیٹ سٹرنگز کے طور پر باندھے جاتے ہیں۔ ٹیمپلیٹ کی Content-Security-Policy کو اسی
ایک اسکرپٹ کا ہیش ملتا ہے۔ نتیجہ `build/macaed.html` ہے، تقریباً 640 KB کا۔ اگر اس میں ایک
بھی بیرونی حوالہ باقی رہ جائے تو بلڈ ناکام ہو جاتا ہے۔

وہی رن `build/pages/` بھی لکھتا ہے: وہی صفحہ ایک انسٹال کے قابل PWA کے طور پر —
`index.html` ایک مانیفسٹ لنک اور ایک `<meta name="service-worker">` کے ساتھ جو صفحے کو اپنا
ورکر رجسٹر کرنے کو کہتا ہے، `manifest.webmanifest`، آئیکنز، اور `sw.js`، جو صفحے کو کیش
کرتا ہے تاکہ یہ آف لائن کھلے۔ `build/macaed.html` خود ایک ہی فائل رہتا ہے، بغیر کسی بیرونی
حوالے کے۔

اور `build/extension/`: `panel.html` — ٹیمپلیٹ، اس کا اسکرپٹ `panel.js` میں — `popup.html`
(صفحے کے اسٹائلز اور `popup.css` کے ساتھ) اور `popup.js`، `background.js`، `offscreen.html`
اور `offscreen.js`، آئیکنز، `_locales/` اور `manifest.json`، جس کا ورژن `package.json` کا ہے۔
`build/macaed-extension-<version>.zip` میں وہی فائلیں طے شدہ تاریخوں کے ساتھ ہوتی ہیں:
وہی ماخذ وہی بائٹس دیتے ہیں۔

براؤزر ٹیسٹ مقامی Chrome شروع کرتے ہیں (`CHROME=/path/to/chrome` ایک منتخب کرنے کے لیے)
اور اس سے DevTools پروٹوکول میں بات کرتے ہیں، بغیر کسی انحصار کے؛ Chrome کے بغیر یہ چھوڑ
دیے جاتے ہیں۔ `tools/test-extension.mjs` اس پروٹوکول کے ذریعے ایکسٹینشن لوڈ کرتا ہے
(`Extensions.loadUnpacked` ایک پائپ پر؛ `--load-extension` Chrome سے ورژن 137 سے ختم ہو
چکا ہے)، سائیڈ پینل میں ایک فولڈر کھولتا ہے اور اسے مقامی سرور پر ٹیسٹ سائٹس سے صفحات،
انتخاب، لنکس اور تصاویر بھیجتا ہے؛ پھر بٹن کی ونڈو تحدیدات کو ڈیفالٹ نوٹ میں اور کسی منتخب
نوٹ میں شامل کرتی ہے، پینل کے ذریعے اور خود بھی، اور، نالج بیس بند ہونے پر، انہیں پینل کے
لیے الگ رکھ دیتی ہے، یا خود کھول دیتی ہے؛ جب کوئی پینل کھلا نہ ہو تو، مینو ڈیفالٹ نوٹ میں
شامل کرتا ہے، یا اسے الگ رکھ دیتا ہے۔ کانٹیکسٹ مینو کے کسی آئٹم پر DevTools سے کلک نہیں کیا جا سکتا، اس لیے
ٹیسٹ ورکر کے `onClicked` کو خود چلاتا ہے، اور بٹن کی ونڈو کو اپنے صفحے کے طور پر کھولتا ہے،
جسے بتایا جاتا ہے کہ کون سا ٹیب ساتھ ہے؛ کسی حقیقی کلک کے بغیر Chrome کوئی `activeTab` نہیں
دیتا، اس لیے زیرِ جانچ کاپی ٹیسٹ سائٹس، `*.test`، تک host permissions کے طور پر پہنچ
سکتی ہے۔

## ورژنز اور ریلیزز

ورژن ایک جگہ لکھا جاتا ہے، `package.json`۔ بلڈ اسے صفحے میں ڈالتا ہے (شروعاتی اسکرین کے
نیچے کی سطر، ترتیبات کا نچلا حصہ)، ایکسٹینشن کے `manifest.json` میں، اور PWA کے کیش نام
میں۔ `v<version>` ٹیگ والے کمٹ کا بلڈ اسے جیسا ہے ویسا دکھاتا ہے؛ کوئی اور بلڈ اپنا کمٹ شامل
کرتا ہے، `0.11.0+1a2b3c4`، تاکہ GitHub Pages پر `main` سے آیا صفحہ ریلیز نہ سمجھا جائے۔
Chrome کا `version` صرف نمبر رکھتا ہے، اس لیے وہاں کمٹ `version_name` میں جاتا ہے۔

```sh
npm version minor           # 0.11.0 -> 0.12.0: package.json, package-lock.json, a commit and the tag v0.12.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

اگر ٹیگ اور `package.json` میں اختلاف ہو تو ریلیز ورک فلو رک جاتا ہے، ٹیسٹ چلاتا ہے، پھر
`macaed-<tag>.html`، `macaed-extension-<tag>.zip` اور `SHA256SUMS.txt` منسلک کرتا ہے۔

## GitHub Pages

`.github/workflows/pages.yml` `main` میں ہر پش کو بلڈ اور ٹیسٹ کرتا ہے اور `build/pages/`
کو GitHub Pages پر تعینات کرتا ہے (Settings → Pages → Source: GitHub Actions)، اس پتے پر
<https://marketkernel.github.io/markdown-catalog-editor/>۔ Chrome، Edge اور Arc میں،
ایڈریس بار کا انسٹال بٹن اسے ایک الگ ایپ ونڈو میں بدل دیتا ہے؛ iOS پر یہ شیئر ← ہوم اسکرین
پر شامل کریں ہے۔ فولڈرز اسی طرح کھلتے ہیں جیسے واحد فائل میں۔

**آف لائن۔** ایک بار کھلنے کے بعد، ایڈیٹر بغیر کنکشن کے کام کرتا ہے: سروس ورکر صفحے،
اس کے مانیفسٹ اور آئیکنز کو ورژن کے نام والے کیش میں رکھتا ہے، اور صفحہ وہیں سے پیش کرتا
ہے۔ نوٹس کبھی اس سے نہیں گزرتے — وہ آپ کی ڈسک پر ہیں۔

**اپڈیٹس۔** ہر ڈیپلائے `sw.js` کو تبدیل کرتا ہے، اس لیے براؤزر خود نیا ورکر ڈھونڈ لیتا ہے
— کنکشن کے ساتھ شروع ہونے پر، ایپ کھلی رہنے کے دوران ہر چند گھنٹوں میں، کنکشن واپس آنے پر،
یا جب Settings → اپڈیٹس چیک کریں یہ مانگے۔ نیا ورکر اپنا ورژن اپنے کیش میں ڈاؤن لوڈ کرتا
ہے اور انتظار کرتا ہے؛ چلتا ہوا ورکر پرانا صفحہ پیش کرتا رہتا ہے، آف لائن بھی، تاکہ آپ کے
ہاتھ تلے کچھ نہ بدلے۔ ترتیبات، اپنے بٹن پر ایک نقطے کے ساتھ، اور شروعاتی اسکرین پھر کہتے
ہیں «ورژن … تیار ہے۔ اپڈیٹ کریں»: اپڈیٹ کریں کھلے نوٹ کو محفوظ کرتا ہے (یا پوچھتا ہے، جب
یہ محفوظ نہ ہو سکے)، نئے ورکر کو اندر آنے دیتا ہے اور صفحہ دوبارہ لوڈ کرتا ہے، جو ایک بار
کہتا ہے کہ یہ اپڈیٹ ہو گیا ہے؛ پرانا کیش حذف کر دیا جاتا ہے۔ بٹن کے بغیر نیا ورژن ایپ کی ہر
ونڈو بند ہونے کے بعد خود شروع ہو جاتا ہے — یا، ترتیبات میں «جب سب کچھ محفوظ ہو اور ایپ پس
منظر میں ہو تو اپڈیٹس خود بخود انسٹال کریں» کو نشان زد کرنے پر، جیسے ہی کچھ بھی غیر محفوظ
نہ رہے اور ونڈو نظروں سے اوجھل ہو۔

یہی وہ سمجھوتہ بھی ہے: ایک انسٹال شدہ PWA وہی چلاتا ہے جو آخری ڈیپلائے نے وہاں رکھا، جبکہ
ایک ڈاؤن لوڈ کی گئی فائل اسی ورژن پر رہتی ہے جو وہ ہے۔ ڈسک پر طے شدہ ورژن کے لیے، کسی ریلیز
سے `macaed-<tag>.html` لیں اور اسے `SHA256SUMS.txt` سے موازنہ کریں۔

**`.md` کھولنا۔** مانیفیسٹ Markdown فائلوں کو ایسی فائلیں قرار دیتا ہے جنہیں ایپ کھولتی
ہے (`file_handlers`) اور انہیں ایک ہی ونڈو تک محدود رکھتا ہے (`launch_handler`،
`focus-existing`): دیکھیں «[اکیلا نوٹ](#اکیلا-نوٹ)»۔ صفحہ انہیں `launchQueue` کے ذریعے
لیتا ہے، ایک بار اس کا آغاز — آخری فولڈر دوبارہ کھولنا — ختم ہو جانے پر، تاکہ فولڈر کبھی
نوٹ کی جگہ نہ لے؛ جو کسی برآمد کے دوران یا کھلے ڈائیلاگ کے ساتھ آئے وہ آپ کے دوبارہ کھولنے
تک انتظار کرتا ہے۔

انسٹال شدہ ایپ براؤزر سے اپنا اسٹوریج محفوظ رکھنے کو کہتی ہے (`navigator.storage.persist()`):
ورنہ کم ہوتی جگہ والی ڈسک آف لائن کاپی اور یاد رکھے گئے فولڈرز کو اپنے ساتھ لے جا سکتی ہے۔

`npm run test:browser` `build/pages/` بھی کھولتا ہے (`tools/test-pwa.mjs`): سروس ورکر
صفحے کا کنٹرول لے لیتا ہے، Chrome مانیفسٹ کو انسٹال کے قابل پاتا ہے، اور سرور کے غائب ہونے
پر بھی صفحہ لوڈ ہوتا رہتا ہے؛ پھر ایک چیک کچھ نہیں پاتا، پھر کوئی کنکشن نہیں، پھر ایک نیا
ڈیپلائے، جو اس وقت تک انتظار کرتا ہے جب تک اپڈیٹ کریں اسے اندر نہ آنے دے۔ Headless Chrome
کسی ایپ کو کوئی فائل نہیں دیتا، اس لیے `launchQueue` کا ایک متبادل صفحے کو ایک حقیقی فائل
ہینڈل دیتا ہے: نوٹ اکیلے کھلتا ہے اور اس میں ایک ترمیم محفوظ ہو جاتی ہے۔

  باقی جگہ نوٹس براؤزر میں رکھے جاتے ہیں اور ZIP آرکائیو کی صورت میں باہر لائے جاتے ہیں۔
- ایکسٹینشن Chrome کے لیے ہے (اور اس پر مبنی براؤزرز جن کا سائیڈ پینل ہو، جیسے Edge)؛ یہ
  ابھی تک Chrome ویب اسٹور میں نہیں ہے۔ یہ تصاویر کو فولڈر میں ڈاؤن لوڈ کرنے کی بجائے ویب
  پر ہی رکھتا ہے: اس کے لیے ہر سائٹ تک رسائی درکار ہوتی۔
