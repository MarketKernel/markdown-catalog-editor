Редактор Markdown для локальной папки заметок — в духе Obsidian, но целиком умещающийся в одном
автономном HTML-файле. Сеть не используется: файлы читаются с диска и сохраняются прямо на
него.

**[Онлайн-демо](https://markdown.marketkernel.com/)** — тот же редактор
в виде PWA (Progressive Web App, прогрессивного веб-приложения): его можно установить в систему, и тогда
он работает как отдельное приложение, со своим окном и значком, и работает офлайн. На компьютере, в Chrome,
Edge и Arc, используйте кнопку установки в адресной строке; на Android — меню ⋮ в Chrome →
Установить приложение; на iOS — Поделиться → На экран «Домой», в Safari или в Chrome. Ваши заметки
остаются на вашем диске и там тоже, установленное приложение открывает `.md` прямо из Finder или
Проводника, а обновляется, когда вы скажете — см. «[GitHub Pages](#github-pages)».

Тот же редактор — это ещё и **Markdown Knowledge Base**,
[расширение для Chrome](#markdown-knowledge-base-расширение-для-chrome): выделите текст на веб-странице,
нажмите его кнопку, и **Send to Markdown** добавит это в заметку по умолчанию вашей базы знаний —
или в любую заметку, которую вы выберете. Сам редактор открывается рядом со страницей в боковой
панели Chrome.

![Редактор с открытой папкой заметок: дерево файлов и теги слева, заметка в режиме редактирования справа](../macaed.jpg)

## Как пользоваться

1. Соберите `build/macaed.html` (см. «[Сборка](#сборка)») и откройте его в браузере.
2. «Открыть папку» → выберите папку с файлами `.md`. Можно также просто перетащить папку в
   окно.
3. Переключатель **Чтение / Правка** вверху или `⌘E`.

В Chrome, Edge и Arc папка открывается через File System Access API: заметки
читаются и записываются на месте, и создание, переименование и удаление файлов и папок работают.
В Safari и Firefox папка открывается только для чтения, и `⌘S` предлагает скачать изменённый
файл — так же и на телефонах: у Chrome на Android нет File System Access, а любой
браузер на iOS, включая Chrome, работает на движке Safari.

Редактор запоминает последние шесть открытых в нём папок (страница никогда не узнаёт путь папки,
поэтому он хранит хэндл папки в IndexedDB браузера) и последнюю открытую в каждой из них заметку.
При следующем запуске последняя папка открывается сама, если браузер всё ещё это разрешает — в
установленном приложении или если вы выбрали «Разрешать при каждом посещении». Иначе начальный экран
показывает список недавних папок: один клик — и браузер снова спросит доступ. Чтобы вернуться к этому
списку — сменить папку или открыть новую, — щёлкните по имени папки вверху панели файлов,
или «Закрыть папку» в настройках; × убирает папку из списка.

Если положить `macaed.html` рядом со своими заметками и раздавать его по HTTP, страница сама подхватит
папку — если рядом с ним лежит `index.json` вида
`{ "name": "Notes", "files": ["Note.md", "Folder/Other.md"] }`.

### Отдельная заметка

Файл `.md` можно открыть отдельно, без его папки:

- **Из Finder или Проводника**, в установленном приложении (Chrome или Edge на компьютере): Открыть
  с помощью → приложения, либо сделайте его приложением по умолчанию для `.md`. Заметка приходит
  в окно приложения, если оно уже открыто, — два окна с одним файлом перезаписывали бы сохранения
  друг друга, — и занимает место папки, показанной там; повторное открытие той же заметки оставляет
  всё как есть.
- **Перетащив на окно** — в любом браузере.

Заметка читается и записывается на месте, как в папке, — в Safari и Firefox только для чтения,
`⌘S` предлагает скачать. Без папки вокруг неё нечего создавать, переименовывать или удалять
рядом с ней, и нет изображений из её папки, тегов или экспорта: это всё приходит вместе с
открытием папки. Заметка, открытая так, не добавляется в недавние папки.

## Markdown Knowledge Base: расширение для Chrome

`npm run build` также создаёт `build/extension/`: редактор в виде расширения для Chrome, и
`build/macaed-extension-<version>.zip` для Chrome Web Store; в релизе этот zip тоже есть. Чтобы установить:
`chrome://extensions` → режим разработчика → Загрузить распакованное расширение →
`build/extension` (или распакованный zip).

**База знаний** — это папка с заметками, открытая в расширении последней. Сам редактор
— **полный режим** — живёт в боковой панели Chrome, рядом со страницей, в телефонной раскладке, поскольку
панель узкая; он остаётся там при переключении вкладок. Папка открывается в ней так же, как в файле, и
недавние папки запоминаются — свои у расширения, отдельно от папок файла или PWA.

**Кнопка на панели инструментов** (или `Alt+Shift+M`) открывает небольшое окно поверх страницы:

- Вверху — то, что выделено на странице, в виде Markdown, — или, если ничего не выделено, основной
  текст страницы: статья, без меню сайта, боковых панелей, подвала, кнопок «поделиться»,
  форм и скрытых частей.
- **Send to Markdown** добавляет это в конец **заметки по умолчанию** — изначально `Inbox.md` в
  корне базы знаний, создаваемой при первой необходимости. После пустой строки идёт
  текст, затем строка `— [The page's title](https://…)`, ссылающаяся на источник. Окно
  закрывается, как только это записано.
- **Добавить в другую заметку**: заметки базы знаний, с полем для поиска по имени;
  клик по заметке добавляет туда вместо этого. Звёздочка рядом с заметкой делает её заметкой по
  умолчанию; заметка по умолчанию показывается первой.
- Если ничего не выделено, **Как новая заметка** превращает страницу в отдельную заметку (ниже).
- **Полный режим** открывает боковую панель.

**Когда база знаний закрыта** — Chrome забирает доступ к папке обратно, как только закрывается
последняя боковая панель, а также после перезапуска, если вы не выбрали «Разрешать при каждом
посещении», — страница не может попасть в папку, пока вы не кликнете. Тогда окно сообщает об
этом и по-прежнему показывает список заметок таким, каким его в последний раз видела панель:
**Send to Markdown** или клик по заметке откладывает то, что вы выделили, в собственное
хранилище расширения, и это попадает в конец этой заметки, как только боковая панель снова
откроет папку. **Открыть** просит у Chrome доступ к папке прямо в окне; один клик по папке в
боковой панели делает то же самое. Когда Chrome спросит, выберите «Разрешать при каждом
посещении»: тогда папка останется открытой и при закрытии панели, и после перезапуска.

Когда в боковой панели открыта база знаний, именно панель добавляет в заметку — у неё может
быть открыта та же заметка с несохранёнными изменениями, которые запись в обход панели потеряла бы.
Если ни одна панель не открыта, а доступ к папке по-прежнему разрешён — либо «при каждом
посещении», либо через **Открыть**, — заметку записывает само окно.

**В контекстном меню** страницы есть **Отправить страницу в Markdown**; на выделенном тексте —
**Отправить выделение в Markdown**; на ссылке — **Отправить ссылку в Markdown**; на изображении —
**Отправить изображение в Markdown**. Ни один из них не открывает боковую панель: открытие
панели сжимает страницу, отодвигая её в сторону. Если в окне не открыта ни одна панель, то,
что вы выбрали, попадает в конец заметки по умолчанию, так же как при **Send to Markdown**, —
или, если база знаний закрыта, ждёт её открытия, как описано выше. Кнопка на панели
инструментов показывает, что произошло: галочка на миг, `!` с причиной в подсказке, и сколько
отправленного ждёт, пока панель не откроет папку. Если панель окна открыта, оно уходит туда
вместо этого, где в диалоге показано, что пришло — и с какого сайта — в виде Markdown, который
ещё можно изменить, и спрашивается, куда это отправить:

- **Новая заметка**, вариант по умолчанию для страницы: в папку для вырезок (`Clippings` в корне,
  если не изменить; папка запоминается, пусто значит корень), названная по заголовку
  страницы, с тем, что не может быть в имени файла, — опущенным. Если имя уже занято, добавляется
  номер: `Title 2.md`. Заметка начинается с front matter — заголовка страницы, её адреса
  и даты — а затем идёт текст; она открывается после сохранения.

  ```markdown
  ---
  title: "The page's title"
  source: "https://example.com/post"
  clipped: 2026-10-07
  ---

  # The page's title

  The text…
  ```

- **Конец открытой заметки**, вариант по умолчанию для выделения, ссылки или изображения, так же,
  как и у Send to Markdown. Ссылке не нужна строка с источником: она сама себе источник.

Если отправить до того, как папка была хоть раз открыта, запрос ждёт: панель просит открыть папку, и диалог появляется,
как только папка открыта. Страница, которую расширение не может прочитать, — собственные страницы Chrome,
Chrome Web Store, PDF — приходит как ссылка на неё.

**Что представляет собой Markdown.** Заголовки, абзацы, **жирный**, *курсив*, ~~зачёркнутый~~,
==маркер==, `код`, ссылки и изображения с полными адресами, списки — вложенные, нумерованные,
задачи — цитаты, блоки кода с указанием языка (из `language-…`, гитхабовского
`highlight-source-…` и тому подобного), таблицы (перенос строки в ячейке как `<br>`, как это
записывает редактор), разделители. Текст читается как есть: `*`, `#` в начале строки или `<b>`,
набранные на странице, экранируются, так что они никогда не превращаются в форматирование, и никакой HTML
страницы не попадает в заметку. Изображения остаются в вебе, на них ссылаются по адресу; у «ленивого»
изображения берётся настоящий адрес, а не заглушка, пиксели отслеживания опускаются.

**Разрешения.** `activeTab`: клик по кнопке, в меню или по сочетанию клавиш даёт
расширению именно эту вкладку, и только тогда оно её читает — с помощью `scripting`, функция, выполняемая в
странице, копирует её текст и возвращает его. Ни один content script никогда не выполняется, и доступа к
какому-либо сайту иначе нет: никаких `host_permissions`, сборка их отвергает. `offscreen`: у
воркера нет DOM, поэтому, если ни одна панель не открыта, HTML страницы или выделения
превращается в Markdown в offscreen-документе расширения, который закрывается, как только
это сделано. `contextMenus`, `sidePanel` и `storage` — то, что отправлено в боковую панель,
уходит панели её окна через `chrome.storage.session`, что исчезает при закрытии браузера; в
`chrome.storage.local` хранится то, что окно кнопки отложило, пока база знаний была закрыта,
список её заметок, язык панели и заметка по умолчанию — для воркера. Окно кнопки и воркер
просят панель, в которой открыта база знаний, добавить это в заметку сообщением
`chrome.runtime`, которое панель принимает только от собственных страниц расширения. У
страниц расширения `connect-src 'none'`:
редактор ничего не достигает по сети; сборка это проверяет, а также
что ни на одной странице нет встроенного скрипта или внешнего адреса.

**Как это устроено.** Панель — это сама страница: `panel.html` со своим скриптом в `panel.js`,
как того требует Manifest V3, — тот же `src/main.ts`, с `src/extension/extension.ts` вместо
`src/platform.ts`, чьи хуки ничего не делают в файле и в PWA. Окно кнопки — это
`popup.html` и `popup.js` (`src/extension/popup.ts`), со стилями страницы: оно читает
хендл базы знаний из того же IndexedDB, что и панель, и пишет через него, пока
браузер это ещё разрешает; в противном случае откладывает отправленное в
`chrome.storage.local`, откуда его находит панель, открывающая папку
(`src/extension/messages.ts`). У воркера, `background.js`, — меню: он читает вкладку
(`src/extension/take.ts`, `grab.ts`) и отправляет взятое панели окна либо добавляет это в
заметку по умолчанию, как и окно кнопки (`src/extension/knowledge.ts`), через
`offscreen.html` для получения Markdown (`src/extension/offscreen.ts`). HTML превращается в
Markdown в `src/extension/to-markdown.ts`, а редактор добавляет это или спрашивает, куда это отправить
(`src/clip.ts`, `src/clip-ui.ts`).

## Живой предпросмотр

В режиме правки документ остаётся отформатированным, и только блок, в котором стоит курсор, превращается в
сырой Markdown. Блок — это абзац, заголовок, целый список, блок кода или цитата: список не
рассыпается построчно. Таблицы редактируются иначе — см.
«[Таблицы](#таблицы)».

Исходная строка сохраняет размер шрифта, начертание и высоту строки отформатированной, так что текст не
прыгает: `# Heading` показывается с размером заголовка. Это проверяется автоматически — при
переключении блока его верхний край смещается меньше чем на пиксель при любом масштабе от 50 до 200 %.

Есть одно место, где высота всё же меняется, и это неизбежно для такого режима: блок кода
получает две строки-ограждения из `` ``` ``. Соседние блоки при этом не дёргаются — сдвигается
только то, что ниже.

Enter вне списка начинает новый блок. Нажатый в конце блока или на пустой строке, он
открывает пустую строку под ним и ставит на неё курсор; нажатый снова, добавляет ещё одну. В
Markdown одна пустая строка лишь разделяет два блока, поэтому пустая строка, в которую можно печатать, —
это та, у которой пустые строки с обеих сторон, — редактор сам добавляет разделяющую строку, и
набранный текст никогда не прилипает к соседнему блоку. Такие строки и определения
ссылок-сносок (`[id]: https://…`) показываются только в режиме правки; режим чтения отображает
Markdown как он есть.

## Таблицы

Таблица никогда не превращается в `| пайпы |`. Клик открывает только ячейку под курсором, и
ячейка показывает свой собственный текст — `**bold**`, а не жирным, — так что встроенное форматирование и
отметки панели инструментов — ссылки и цвета — по-прежнему работают внутри неё. Печать переписывает в файле
только эту ячейку; остальная часть таблицы сохраняет свои отступы и выравнивание.

- **Перемещение**: Tab и Shift+Tab переходят к следующей и предыдущей ячейке, Enter — к ячейке ниже,
  стрелки — к соседней ячейке у края текста, а за краем таблицы — к блоку рядом с ней. Enter на последней
  строке начинает новый блок под таблицей.
- **Переносы строк**: Ctrl+Enter (а также ⌘Enter или Shift+Enter) начинает новую строку внутри
  ячейки. Строка таблицы — это одна строка Markdown, поэтому перенос записывается как `<br>`; редактируемая
  ячейка показывает его как настоящий перенос строки, и вставленный текст сохраняет свои строки так же.
  Внутри ячейки с несколькими строками стрелки вверх и вниз сначала перемещаются между её строками. Текст
  ячейки выравнивается по верхнему краю.
- **Добавление**: в режиме правки наведение на таблицу показывает полосу с **+** под ней, которая добавляет
  строку, и ещё одну справа от неё, которая добавляет столбец. Tab в последней ячейке тоже добавляет строку.
- **Удаление**: удаляются только пустые строки и столбцы, так что ни один текст не теряется по ошибке.
  Наведение на пустую строку показывает **×** слева от неё, на пустой столбец — **×** над
  ним. Backspace в пустой ячейке делает то же самое с клавиатуры: он удаляет строку, если вся
  строка пуста, иначе столбец, если пуст весь столбец (включая заголовок); таблица, в которой не осталось
  текста, удаляется целиком. Строка заголовка остаётся — таблице она нужна.

Добавление или удаление переписывает таблицу в обычном виде `| a | b |`.

## Теги

Теги группируют заметки из разных папок. Они не записываются в заметки: Markdown остаётся
в точности таким, каким был, а все теги папки хранятся в одном файле рядом с заметками.

- **На заметке**: теги располагаются под заголовком в виде чипов `#тег`, за которыми следует **+**.
  **+** превращается в поле; Enter добавляет тег, и **+** снова появляется после него. Уже
  использованные в папке теги подсказываются по мере набора. Esc отменяет; уход из поля
  с текстом в нём тоже добавляет тег. **×** на чипе убирает тег, а клик по чипу
  открывает страницу тега. Теги можно менять и в режиме чтения, и в режиме правки.
- **Написание**: ведущий `#` отбрасывается, а пробелы внутри тега становятся дефисами, так что
  `#to do` сохраняется как `to-do`. Тег, отличающийся от уже существующего только регистром, принимает
  написание существующего — `Idea` и `idea` никогда не становятся двумя разными тегами. Заметка не может
  нести один и тот же тег дважды.
- **Вложенность**: `/` вкладывает теги друг в друга. `work/alpha` и `work/beta` располагаются под
  `work` в дереве тегов, и заметка с тегом `work/alpha` считается и под `work` тоже.
- **Дерево тегов**: раздел внизу панели файлов, отдельно от дерева файлов. Каждый тег
  показывает, сколько заметок несёт его или вложенный в него тег; стрелка родительского тега
  сворачивает его потомков, а заголовок сворачивает весь раздел. Фильтр по имени
  над деревом файлов фильтрует и теги. Раздел занимает до 42 % панели и
  прокручивается внутри себя; перетаскивание линии над ним делает его ниже (но никогда выше), двойной клик
  по линии возвращает место обратно, а при фокусе на линии ↑ и ↓ делают то же самое. Высота
  запоминается.
- **Страница тега**: клик по тегу в дереве или по чипу показывает заметки, несущие его — родительский
  тег показывает и заметки всех вложенных в него тегов тоже. Каждая строка даёт имя заметки, её
  папку и все её теги; клик по имени открывает заметку, клик по тегу открывает этот
  тег. Страница доступна только для чтения: на ней нечего редактировать, и панель форматирования
  отключена. Для вложенного тега родители в его заголовке ссылаются на свои собственные страницы.
- **Переименование и удаление**: теги следуют за заметкой — или за всеми заметками папки, —
  когда её переименовывают или удаляют из панели файлов. Заметка, перемещённая или удалённая вне редактора,
  сохраняет свою запись в файле, но эта запись не показывается и не учитывается, пока заметка отсутствует.
- **Папки только для чтения** (Safari, Firefox): теги показываются, но **+** и **×** —
  нет.

### `.meta.json`

Файл находится в корне открытой папки и создаётся при первом теге. Он
никогда не показывается в дереве файлов.

```json
{
  "notes": {
    "Ideas.md": { "tags": ["idea", "work/alpha"] },
    "Projects/Roadmap.md": { "tags": ["work/alpha", "planning"] }
  }
}
```

Ключи — это пути заметок относительно корня, как их показывает дерево; теги сохраняют
порядок, в котором их добавили. Файл записывается с заметками, отсортированными по пути, и с отступом в
два пробела, так что он хорошо читается в diff, а заметки, у которых не осталось тегов, из него убираются.
Поля, которых редактор не знает — вверху или внутри записи заметки, — сохраняются, когда он
записывает файл обратно, так что другие инструменты могут хранить в нём свои данные. Если файл не является
валидным JSON-объектом, редактор сообщает об этом, не показывает теги и никогда не перезаписывает его; теги
нельзя менять, пока файл не исправят и папку не откроют заново.

Когда папка раздаётся по HTTP с `index.json` (см. «[Как пользоваться](#как-пользоваться)»),
перечислите `.meta.json` среди его файлов, чтобы теги показывались.

## Экспорт в HTML

Кнопка экспорта на панели инструментов (рядом с «Сохранить») превращает всю папку в статический сайт;
«Экспорт в HTML…» в контекстном меню папки делает то же самое для одной этой папки, а на
пустом месте под деревом — для всей папки. Сайт записывается в
`output/<folder>/` в корне папки заметок; папка называется по моменту
экспорта, `2025-12-31_23-33-33`, и может быть переименована в диалоге. `output` никогда
не показывается в дереве. Экспортировать можно только папку, открытую для записи.

Пока экспорт выполняется, диалог показывает, на каком он шаге — чтение заметок, запись
страниц, копирование изображений — с индикатором прогресса, и его нельзя закрыть; «Остановить» завершает его
после уже начатых файлов, оставляя то, что успело записаться. Кнопка экспорта и
пункт меню недоступны, пока он не завершится. Файлы читаются и записываются по несколько за раз, каждая
папка на пути создаётся один раз. В конце экспорт считывает папку обратно с диска: если
какого-то файла не хватает, диалог говорит, сколько их, и называет один, а не сообщает об
успехе над пустой папкой.

«Создать статический сайт» — включено по умолчанию — делает страницу на каждую заметку, как описано ниже.
Выключено — экспорт представляет собой одну страницу, `index.html`, со всеми заметками в ней: левая
панель — это оглавление, каждая заметка — раздел с её именем над ним, её заголовки на уровень ниже, а их
id с префиксом из имени заметки, так что ссылки между заметками и на их заголовки становятся якорями на
странице. Страница показывает по одной заметке за раз — ту, на которую указывает или в которую попадает
`#якорь` адреса, а изначально — корневую `index` или `README`, иначе первую заметку в корне. Оглавление,
ссылки, результаты поиска и ссылки **предыдущая** / **следующая** в конце каждой заметки переключают между
ними. Это сделано на CSS (`:target`), так что работает и без скрипта тоже; скрипт лишь отмечает
показываемую заметку в оглавлении. Печать показывает все заметки. Встроенный поиск браузера (`⌘F`)
видит только показываемую заметку — поле поиска просматривает их все. С тегами
дерево тегов на панели и чипы на заметках ведут в раздел тегов в конце, с заголовком на
каждый тег и его заметками. Страница — это один файл: таблица стилей и скрипт
записаны прямо в неё. Рядом с ней лежат только изображения, собранные в папку `assets`, которая сохраняет
папки, из которых они пришли, но не собственный шаг `assets` каждой заметки: `docs/assets/Guide/a.png`
становится `assets/docs/Guide/a.png`. У одностраничного варианта те же поиск, кнопка темы,
кнопки **развернуть всё** / **свернуть всё** и изменяемая по ширине панель, что и у сайта; поиск читает
заметки прямо со страницы, а результат переходит к своей заметке.

Ширина текста и имя заметки над ней следуют настройкам редактора на момент
экспорта: «Ширина текста», выставленная на всю панель, даёт страницы на всю ширину, а при выключенном
«Показывать имя заметки как заголовок» над заметками имя не добавляется.

Страницы несут весь свой текст и обычные относительные ссылки, ничего не подгружая позже: сайт
открывается и с адреса `file://`, и с любого веб-сервера, и для поисковой системы — у каждой страницы
есть `<title>`, `<meta name="description">`, взятый из её первого абзаца, `lang`
и один `<h1>`. Папки в навигации сворачиваются через `<details>`; тема следует за
системной.

Один небольшой скрипт, `site.js`, добавляет то, чего не может один HTML:

- **Поиск**: поле вверху левой панели. Он ищет каждое набранное слово в именах заметок, папках
  и тексте; результаты занимают место дерева — сначала совпавшие имена, каждое со сниппетом
  вокруг найденных слов, выделенным, — а дерево возвращается, когда поле очищено (Esc). Enter открывает
  первый результат, ↓ и ↑ ходят по списку. Текст приходит из `search.js`, который скрипт
  загружает при первом использовании поля, так что сами страницы остаются такими же лёгкими, как были.
- **Развернуть всё** и **свернуть всё** рядом с «Заметки» над навигацией.
- Кнопка **темы** рядом с именем сайта: луна переключает на тёмную тему, солнце — обратно на
  светлую, какой бы ни предпочитала система. Пока её не нажали, тема следует за
  системой.
- Ручка на правом краю панели, которая делает её шире или уже (160–560 px; двойной
  клик возвращает значение по умолчанию, ← → двигают её при фокусе на ручке).

Тема, ширина колонки и состояние папок запоминаются от страницы к странице, в рамках
сайта; папки показываемой страницы всегда открыты. Без скрипта — заблокированного или убранного
из шаблона — поля поиска, кнопок и ручки просто нет, тема следует за
системой, а сайт читается и ссылается так же.

- **Страницы**: `dir/Note.md` становится `dir/Note.html`. Заметка, которая начинается с заголовка,
  равного её имени, получает этот заголовок как заголовок страницы, с её тегами под ним. Корневая заметка
  `index` или `README` становится титульной страницей, `index.html`; без неё титульная страница
  перечисляет заметки и теги. `[текст](other.md)` и `[[вики-ссылки]]` указывают на страницы,
  `[[Заметка#Заголовок]]` — на заголовок — у каждого заголовка есть id, — а ссылка на заметку, которой нет
  в экспорте, остаётся обычным текстом. Чекбоксы задач показываются, но не кликабельны. Front matter
  опускается.
- **Изображения**: каждая картинка и PDF в папке копируются по тому же пути, так что и
  `![[image.png]]`, и `![alt](path.png)` продолжают работать; вложение находится там же, где его
  находит редактор.
- **Теги**: при включённом флажке «Экспортировать теги» каждая страница показывает свои теги, дерево
  тегов располагается под навигацией, а страница на каждый тег перечисляет его заметки — для
  родительского тега — заметки всех вложенных в него тегов тоже, — плюс указатель тегов на
  `tags/index.html`. Учитываются только заметки, попавшие в экспорт.
- **Шаблон**: диалог показывает шаблон страницы; редактируйте его там же или нажмите «Вернуть
  стандартный», и он запоминается. Шаблон — это HTML с `{{подстановками}}`:

  | Подстановка | Означает |
  | --- | --- |
  | `{{navigation}}` | дерево папок в виде `<nav>`, с отмеченной текущей страницей — обязательна |
  | `{{heading}}` | `<h1>` страницы, пустой, если заметка начинается со своего собственного, — обязательна |
  | `{{content}}` | заметка в виде HTML — обязательна |
  | `{{tags}}` | дерево тегов в виде `<nav>`; обязательна, когда теги экспортируются, иначе пуста |
  | `{{pagetags}}` | теги заметки в виде чипов `#тег`, ссылающихся на свои страницы |
  | `{{title}}` | имя страницы как обычный текст, для `<title>` |
  | `{{site}}` | имя экспортированной папки |
  | `{{description}}` | первый абзац, обычным текстом, для `<meta name="description">` |
  | `{{width}}` | `full` или `column`, из настройки ширины текста |
  | `{{root}}` | `../` на каждую папку, в которой лежит страница, так что `{{root}}style.css` ведёт в корень |
  | `{{styles}}` | таблица стилей: `<link>` на `style.css`, либо весь `<style>` целиком на одностраничном варианте |
  | `{{script}}` | скрипт: `<script src>` на `site.js`, либо весь `<script>` целиком на одностраничном варианте |
  | `{{theme}}` | кнопка светлой/тёмной темы |
  | `{{path}}` | путь заметки, `docs/Note.md` |
  | `{{lang}}` | язык интерфейса, для `<html lang>` |

  Сайт получает `style.css`, `site.js` и `search.js` в своём корне независимо от того, использует ли их
  шаблон; одностраничный вариант несёт свои таблицу стилей и скрипт внутри себя и получает
  `style.css` рядом с собой, только если его шаблон, оставшийся с времён до `{{styles}}`, всё ещё ссылается
  на него. Стандартная таблица стилей оформляет заметку так же, как режим чтения редактора, и читает
  ширину из `<html data-width="{{width}}">`. Подстановка, которую экспорт не знает,
  оставляется как есть. Шаблон, сохранённый до появления новой подстановки, её не использует:
  «Вернуть стандартный» добавляет её.

## Приватность и безопасность

- **Страница никуда не обращается.** Content-Security-Policy в файле разрешает его коду запрашивать
  только файлы рядом с ним на том же сервере (`connect-src 'self'`, для папки, раздаваемой
  с `index.json`), и не отправлять ни одну форму никуда. Сборка завершается ошибкой, если политика
  пропадает или в неё проникает внешняя ссылка. Копия PWA впускает свой манифест и свой service worker,
  оба со своего собственного источника.
- **Скрипты в заметках никогда не выполняются.** Заметки могут содержать HTML — именно так работает цвет
  текста, — поэтому политика разрешает ровно один скрипт, собственный скрипт редактора, по его хэшу:
  `onerror` у `<img>` или `<script>` в заметке ничего не делает.
- **То, на что заметка ссылается в вебе, загружается оттуда**: изображение, видео или встроенный
  фрейм с адресом `https://`, как в любом просмотрщике Markdown, — это выбор заметки, а не
  редактора. Такие запросы не несут `Referer`.
- **Файлы остаются на вашем диске.** Заметки читаются и записываются на месте через File System
  Access API; запомненные папки — это хэндлы в IndexedDB браузера, никогда не пути и не
  содержимое.
- Разрешения расширения: см. «[Markdown Knowledge Base](#markdown-knowledge-base-расширение-для-chrome)».

## Возможности

- **Дерево файлов**: сворачиваемые папки, фильтрация по имени, создание, переименование и удаление
  через контекстное меню, изменяемая по ширине панель, скрываемая панель (`⌘\`).
- **Форматирование выделения**: заголовки H1–H3, жирный, курсив, зачёркнутый, моноширинный,
  маркер `==…==`, цвет текста и фона, ссылка, `[[вики-ссылка]]`, списки, задачи, цитата,
  блок кода, таблица, разделитель.
- **Разметка**: CommonMark плюс таблицы, задачи с кликабельными чекбоксами, `==маркер==`,
  `[[вики-ссылки]]`, front matter, подсветка синтаксиса для 19 языков, изображения из
  папки.
- **Изображения**: `![alt](assets/Note/image-1.png)` показывает изображение по его пути из папки заметки.
  Обсидиановский `![[assets/Note/image-1.png]]` тоже работает, путь — из папки заметки
  или иначе из корня (`![[…|300]]` задаёт ширину). Старое
  вложение с голым именем, `![[image-1.png]]`, ищется в папке изображений из настроек,
  с подпапкой заметки и без неё, в `assets/<имя заметки>/`, рядом с
  заметкой, а затем где угодно в папке по имени, как это делает Obsidian. Папки с изображениями
  сворачиваются в дереве по умолчанию. Переименование заметки переименовывает и её папку с изображениями и
  меняет ссылки заметки на свои изображения, в любой форме, на новый путь. Картинка, по которой кликнули в
  дереве, открывается как картинка, а не как текст.
- **Добавление изображений**: кнопка картинки на панели инструментов выбирает файлы изображений;
  изображение, вставленное через `⌘V`, — скриншот, картинка, скопированная в браузере, файл,
  скопированный в файловом менеджере, — попадает тем же способом. Любое из них сохраняется в папку
  изображений рядом с заметкой, по умолчанию `assets/<имя заметки>/`, и вставляется как обычный Markdown с
  его путём, `![image-1](assets/<имя заметки>/image-1.png)`, который покажет любой редактор (пробел в
  пути записывается как `%20`): на месте курсора, или в конце заметки, если не открыт ни один блок.
  Изображения, перетащенные на заметку, попадают туда, куда их бросили: в это место в блоке или ячейке
  таблицы, и рядом с текстом или между двумя блоками, в конец блока над ними; бросок в режиме чтения
  переключает на редактирование, а бросок вне заметки добавляет изображения в конец. Бросок с папкой
  внутри всё равно открывает папку. Вставленный скриншот называется `image-1.png`, `image-2.png` и далее;
  выбранный файл сохраняет своё имя, с добавленным номером, если оно уже занято. Ячейки, скопированные из
  электронной таблицы, вставляются как текст, а не как идущая вместе с ними картинка. Новые изображения
  принимает только папка, открытая для записи.
- **Теги**: вложенные теги на заметках, дерево тегов и страница на каждый тег, хранящиеся отдельно
  от заметок в `.meta.json` — см. «[Теги](#теги)».
- **Экспорт в HTML**: папка или одна из её подпапок — в виде статического сайта с поиском,
  либо в виде одной страницы — см. «[Экспорт в HTML](#экспорт-в-html)».
- **Отдельная заметка**, открытая из Finder или Проводника в установленном приложении, или
  перетащенная на окно — см. «[Отдельная заметка](#отдельная-заметка)».
- **Markdown Knowledge Base**: то, что выделено в Chrome, — в заметку по умолчанию или в ту, что
  вы выберете, через Send to Markdown; страница, ссылка или изображение — в заметку — см.
  «[Markdown Knowledge Base](#markdown-knowledge-base-расширение-для-chrome)».
- **Настройки** (шестерёнка вверху справа, рядом с поиском): язык интерфейса, тема
  (системная, светлая, тёмная), масштаб 50–200 %, ширина текста (колонка по центру или вся панель),
  показывать ли имя заметки как заголовок, и куда отправляются добавленные изображения: папка изображений
  рядом с заметкой (`assets` по умолчанию) и получает ли каждая заметка собственную подпапку
  в ней; без неё все изображения идут прямо в папку. Внизу — версия,
  а в установленном приложении — ещё и проверка обновлений, и устанавливать ли их самостоятельно.
- **Языки**: английский и ещё 16 — 中文, हिन्दी, Español, Français, العربية, বাংলা,
  Português, Русский, اردو, Bahasa Indonesia, Deutsch, 日本語, Türkçe, 한국어, Italiano,
  Українська. По умолчанию интерфейс следует за языком браузера. В арабском и урду
  интерфейс зеркалится справа налево; сама заметка сохраняет своё собственное направление.
- **Телефоны**: на экране уже 720 px панель файлов наезжает поверх заметки — ☰
  открывает её, выбор заметки или тап рядом закрывает её, — а панель инструментов помещается в одну
  строку; форматирование получает вторую строку только в режиме правки. Экспорт там отсутствует. На
  сенсорном экране поля не меньше 16 px, так что iOS не увеличивает их, а строки дерева
  выше. Десктопная раскладка и запомненная ширина панели не затронуты.
- Автосохранение через секунду после правки, отмена и повтор, поиск внутри заметки.
- Язык, тема, масштаб, ширина текста, ширина панели, высота панели тегов и последняя открытая заметка
  запоминаются.

## Переводы

Английский текст остаётся в коде: `t('tree', 'Delete')`, `tn('status', '{count} word',
'{count} words', n)`, и `data-i18n="context"` / `data-i18n-attr="context"` в
шаблоне. Первый аргумент — это контекст, часть интерфейса, к которой принадлежит строка, так что
одно и то же английское слово можно переводить по-разному в двух местах. Словарь,
`src/locales/<code>.json`, сопоставляет контекст → английский текст → перевод:

```json
{
  "tree": { "Delete": "Удалить" },
  "status": { "{count} words": { "one": "{count} слово", "few": "{count} слова", "many": "{count} слов", "other": "{count} слова" } }
}
```

Строка, которой нет в словаре, показывается на английском. Текст с числом имеет одну форму на каждую
категорию множественного числа языка (`Intl.PluralRules`), с ключом по английской форме множественного
числа. `npm run i18n` выводит, по каждому языку, ещё не переведённые строки и те, что больше не
используются; `npm test` проверяет, что каждый перевод сохраняет английские плейсхолдеры и имеет все
формы множественного числа.

То, что Chrome показывает о самом расширении — его имя и описание, подсказку кнопки панели
инструментов, — следует за языком браузера, а не панели, через `chrome.i18n`. Эти
тексты — английские, в `src/extension/manifest.json`, переведённые в тех же
словарях, в контексте `manifest`; сборка записывает их в
`_locales/<code>/messages.json` и вставляет `__MSG_appName__` и тому подобное в манифест.
У Chrome свои собственные коды, а остальные он игнорирует: `pt` становится `pt_BR` и `pt_PT`, `zh`
становится `zh_CN`, а у урду кода нет вовсе, так что там Chrome описывает расширение на английском. Сборка
останавливается, если имя длиннее 75 символов или описание длиннее 132. Контекстное меню говорит
на языке панели, если панель уже открывали, иначе — на языке браузера.

Этот README тоже переведён: `docs/readme/README.<code>.md`, по одному на язык, со
списком языков вверху каждого. Изменение здесь должно попасть и в переводы.

## Сборка

```sh
./build.sh         # installs the dependencies if needed, then builds
npm install
npm run build      # -> build/macaed.html, build/pages/, build/extension/ and its zip
npm run watch      # rebuild on changes in src/ and assets/
npm run typecheck  # tsc --noEmit
npm test           # the block model, formatting, Markdown syntax, tags, the export, clippings and the dictionaries
npm run test:browser  # in headless Chrome: the editor, HTML → Markdown, the PWA, the extension
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row: green means done
```

`build.mjs` объединяет `src/main.ts` с помощью esbuild в IIFE и подставляет его, вместе
со стилями и иконкой (data URI), в `src/template.html`; шаблон и таблица стилей экспорта
собираются как строки. Content-Security-Policy шаблона получает хэш именно этого скрипта. Результат —
`build/macaed.html`, около 640 КБ. Сборка завершается ошибкой, если в нём остаётся хотя бы одна
внешняя ссылка.

Тот же запуск записывает `build/pages/`: эта же страница в виде устанавливаемого PWA — `index.html` со
ссылкой на манифест и `<meta name="service-worker">`, который говорит странице зарегистрировать свой
воркер, `manifest.webmanifest`, иконки и `sw.js`, который кеширует страницу, чтобы она открывалась офлайн.
Сам `build/macaed.html` остаётся единым файлом без внешних ссылок.

И `build/extension/`: `panel.html` — шаблон, его скрипт в `panel.js` — `popup.html`
(со стилями страницы и `popup.css`) и `popup.js`, `background.js`, `offscreen.html` и
`offscreen.js`, иконки, `_locales/` и `manifest.json`, чья версия берётся из `package.json`.
`build/macaed-extension-<version>.zip` содержит те же файлы с фиксированными датами: одни и те же
исходники дают одни и те же байты.

Браузерные тесты запускают локальный Chrome (`CHROME=/path/to/chrome`, чтобы выбрать конкретный) и говорят с
ним по протоколу DevTools, без каких-либо зависимостей; без Chrome они пропускаются.
`tools/test-extension.mjs` загружает расширение через этот протокол (`Extensions.loadUnpacked`
через pipe; `--load-extension` убрали из Chrome начиная с версии 137), открывает папку в
боковой панели и отправляет ей страницы, выделения, ссылки и изображения с тестовых сайтов на локальном
сервере; затем окно кнопки добавляет выделения в заметку по умолчанию и в выбранную, через
панель и само по себе, а при закрытой базе знаний либо откладывает их для панели, либо
открывает папку само; если ни одна панель не открыта, меню добавляет в заметку по умолчанию
либо откладывает его. По пункту контекстного меню нельзя кликнуть из DevTools, поэтому тест
сам вызывает `onClicked` воркера и
открывает окно кнопки как отдельную страницу, сообщая ей, рядом с какой вкладкой она; без настоящего клика
Chrome не даёт `activeTab`, так что тестируемая копия может обращаться к тестовым сайтам, `*.test`, как к
host permissions.

## Версии и релизы

Версия записана в одном месте, `package.json`. Сборка вставляет её на страницу (строка
под начальным экраном, низ настроек), в `manifest.json` расширения и в имя кеша PWA. Сборка коммита,
помеченного тегом `v<version>`, показывает её как есть; любая другая добавляет свой коммит, `0.11.0+1a2b3c4`,
так что страницу из `main` на GitHub Pages не принимают за релиз. `version` у Chrome содержит только
цифры, поэтому там коммит идёт в `version_name`.

```sh
npm version minor           # 0.11.0 -> 0.12.0: package.json, package-lock.json, a commit and the tag v0.12.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

Релизный workflow останавливается, если тег и `package.json` расходятся, запускает тесты, затем
прикрепляет `macaed-<tag>.html`, `macaed-extension-<tag>.zip` и `SHA256SUMS.txt`.

## GitHub Pages

`.github/workflows/pages.yml` собирает и тестирует каждый пуш в `main` и разворачивает
`build/pages/` на GitHub Pages (Settings → Pages → Source: GitHub Actions), по адресу
<https://marketkernel.github.io/markdown-catalog-editor/>. В Chrome, Edge и Arc кнопка
установки в адресной строке превращает его в отдельное окно приложения; на iOS это Поделиться →
На экран «Домой». Папки открываются так же, как в одиночном файле.

**Офлайн.** После открытия редактор работает без подключения: service worker хранит
страницу, её манифест и иконки в кеше, названном по версии, и отдаёт страницу
оттуда. Заметки никогда через него не проходят — они у вас на диске.

**Обновления.** Каждый деплой меняет `sw.js`, так что браузер сам находит нового воркера — при
запуске с подключением, каждые несколько часов, пока приложение открыто, когда подключение
возвращается, или когда об этом попросит Настройки → Проверить обновления. Новый воркер скачивает свою
версию в отдельный кеш и ждёт; работающий продолжает отдавать старую страницу, тоже офлайн, так что
ничего не меняется у вас из-под рук. Настройки, с точкой на своей кнопке, и начальный
экран тогда говорят: «Версия … готова. Обновить»: Обновить сохраняет открытую заметку (или спрашивает,
если её нельзя сохранить), впускает новый воркер и перезагружает страницу, которая один раз сообщает, что
обновилась; старый кеш удаляется. Без нажатия кнопки новая версия запускается сама, как только
закроется каждое окно приложения — или, если в настройках отмечено «Устанавливать обновления
самостоятельно, когда всё сохранено, а приложение работает в фоновом режиме», как только ничего не
остаётся несохранённым и окно скрыто из виду.

В этом и состоит компромисс: установленное PWA запускает то, что положил последний деплой, тогда как
скачанный файл остаётся той версией, какой он есть. Для версии, зафиксированной на диске, возьмите
`macaed-<tag>.html` из релиза и сравните его с `SHA256SUMS.txt`.

**Открытие `.md`.** Манифест называет файлы Markdown файлами, которые открывает приложение
(`file_handlers`), и оставляет их в одном окне (`launch_handler`, `focus-existing`): см. «[Отдельная
заметка](#отдельная-заметка)». Страница принимает их через `launchQueue`, как только её запуск —
повторное открытие последней папки — завершён, так что папка никогда не заменяет заметку; та, что
приходит во время экспорта или при открытом диалоге, ждёт, пока вы не откроете её снова.

Установленное приложение просит браузер сохранить его хранилище (`navigator.storage.persist()`): иначе при
нехватке места на диске система могла бы забрать офлайн-копию и запомненные папки вместе с ним.

`npm run test:browser` тоже открывает `build/pages/` (`tools/test-pwa.mjs`): service worker
берёт страницу под свой контроль, Chrome находит манифест пригодным для установки, а при пропавшем сервере
страница всё равно загружается; затем проверка не находит ничего, затем — нет подключения, затем — новый
деплой, который ждёт, пока Обновить его впустит. Headless Chrome не передаёт файл приложению, поэтому
подставной `launchQueue` даёт странице настоящий хендл файла: заметка открывается сама по себе, и
правка сохраняется в неё.

## Ограничения

- Совместное редактирование, плагины, синхронизация и граф связей не поддерживаются.
- На телефоне раскладка сделана для чтения: контекстное меню дерева требует долгого нажатия,
  которое iOS не превращает в таковое, а таблицы расширяются полосами, появляющимися при наведении.
- Записывать файлы умеют только браузеры на основе Chromium.
- Расширение — для Chrome (и браузеров на его основе с боковой панелью, таких как Edge); его
  пока нет в Chrome Web Store. Оно хранит изображения в вебе, а не скачивает их
  в папку: для этого понадобился бы доступ к любому сайту.
